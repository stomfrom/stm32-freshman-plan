# 大一 STM32 入门培养方案

> 面向**大一新生、零基础**的 STM32 单片机培训方案：一年 32 周 · 10 个项目 · 从装工具到独立做出一个完整作品。
> 全仓库 **11 篇手把手教程、117 个任务点、117 个可跳转锚点**，每条任务都能一键跳到对应做法。

**关键信息速览**

| | |
|---|---|
| 主线硬件 | STM32F103C8T6 最小系统板（蓝板）+ ST-Link + USB-TTL |
| 开发环境 | STM32CubeMX 6.x + Keil MDK（**必须勾 C99 Mode**） |
| 项目数量 | 11 个（P00 预备课 + P01~P10 正式项目） |
| 总周期 | 32 周（秋 16 周 + 春 16 周），P00 不计入 |
| 交付方式 | 提交到**你自己的仓库**，把链接发给带教人 |
| 考核方式 | 四件套 + 当面讲 10 分钟，讲不清不算完成 |

## 二、新生路线图：从零到结课

### 你要搞清楚的第一件事

这个仓库（`stm32-freshman-plan`）是**课程方案本身，只读**——**不要往这里提交任何东西**。

你要按 P00 建**自己的仓库**，**你所有的作业都提交到那里**。

| | 是什么 | 你该做什么 |
|---|---|---|
| **这个仓库** | 老师放在这里的课程方案 | 看，照着做；不要提交 |
| **你自己的仓库** | 你按 P00 建的 | **所有作业提交到这里**，把链接发给老师 |

> 作业不是"发文件给老师"，而是**把代码提交到你自己的仓库，把链接发给老师**——老师打开就能看到你的代码，以及你每一步的修改过程。这就是为什么必须先学 Git。

### 完整路线（按顺序走，别跳）

```
                        开课前（不计入 32 周）
  ┌──────────────────────────────────────────────────────────┐
  │ ① 读 GITHUB_新手上路.md        搞懂 GitHub 是什么（10 分钟） │
  │ ② 做 tasks/P00-Git与GitHub入门  装 Git、注册、建自己的仓库   │
  │ ③ 把仓库链接 + 协作者邀请 发给带教人                        │
  └──────────────────────────────────────────────────────────┘
                              ↓
                     秋季学期 16 周（P01 ~ P06）
  ┌──────────────────────────────────────────────────────────┐
  │ P01 点灯 → P02 C语言+串口+万用表 → P03 GPIO与按键          │
  │   → P04 外部中断与状态机 → P05 定时器与PWM → P06 串口协议   │
  └──────────────────────────────────────────────────────────┘
                              ↓
                          寒假 8 周（休息 + 建议 2 个回炉小任务）
                              ↓
                     春季学期 16 周（P07 ~ P10）
  ┌──────────────────────────────────────────────────────────┐
  │ P07 I2C与OLED+传感器 → P08 ADC采集 → P09 FreeRTOS          │
  │   → P10 独立选题：做出并讲清一个完整作品                    │
```

### 现在马上要做的三件事

1. **读完 [`GITHUB_新手上路.md`](GITHUB_新手上路.md)**（10 分钟）。
2. **打开 [`tasks/P00-Git与GitHub入门.md`](tasks/P00-Git与GitHub入门.md)，做完 A 档 9 条**（第 1 周，约 4~5 小时）。这是整套方案的地基。

> P00 有 15 个任务点，对零基础两周偏重。任务卡里已经拆成"**必修 9 条（第 1 周）+ 选做 6 条（第 2 周）**"两轮，优先保第 1 轮。

## 三、使用教程：一个项目怎么做完

这是本仓库最核心的用法。**每个项目都走同一套流程（8 步）**，学会一次，后面 11 个项目都照这个走。

下面用 **P05 定时器与 PWM** 当例子，你换成自己要做的项目编号即可。

### 第 1 步 · 找到任务卡

打开 [`tasks/`](tasks) 目录，按编号找。文件名格式统一是 `PXX-项目名.md`：

```
tasks/P05-定时器与PWM.md      ← 你要做的项目
```

任务卡里只有四样东西，**看完这四项就知道要干什么**：

| 任务卡里的部分 | 告诉你什么 |
|---|---|
| 表格（编号/周期/日期/难度） | 什么时候做、做多久 |
| **前置要求** | 上一个项目要会什么才能开始 |
| **任务**（A 档 / B 档，逐条 ○） | **要做什么**，每条后面挂 📖 教程链接 |
| **交付物 / 验收标准** | **怎么算过关**（这是打分依据） |

> ⚠️ **先看任务卡的"验收标准"，再看教程**。很多人反过来做，照着教程抄完才发现漏了验收项。

### 第 2 步 · 点教程链接，别自己瞎搜

任务卡里每条任务后面都有一个 **📖 教程** 链接：

```
- [ ] 3. 配置一个 PWM 输出通道，实现 LED 呼吸灯… [📖 教程](../tutorials/P05-定时器与PWM.md#p05-a3)
                                                                              ↑ 点这里
```

点进去直接跳到教程的对应小节（靠锚点实现，117 个链接全部有效）。教程每节都长这样：

| 教程小节里的部分 | 作用 |
|---|---|
| 知识点 | 讲原理，**先看懂再动手** |
| 操作步骤 | CubeMX 点哪里、代码写什么，可复制 |
| 验证方法 | **做完必须验证**，不通过就别往下走 |
| 常见问题表 | 报错时先查这里 |

### 第 3 步 · 动手做（遵循"小步验证"）

**每完成一小步就验证一次**，不要一口气写完再调试。零基础最常见的失败模式是"写了 200 行，烧进去不动，不知道哪错了"。

三个必用的验证手段：

- **串口打印**：`printf("到这里 1")`，看输出停在哪 —— 最有效的打点法
- **万用表**：测电压、通断，确认硬件接线对了
- **串口 + 示波器**：看时序、频率、脉宽

### 第 4 步 · 对照验收标准自检

回到任务卡，**逐条勾选 A 档**，每条都要能拿出证据文件。以 P05 为例：

```
- [x] 1. 配置定时器 1ms 中断          → 证据：01-timer-1ms.png
- [x] 2. 计时 10 分钟核对             → 证据：02-计时记录.md
- [x] 3. PWM 呼吸灯                    → 证据：03-呼吸灯.mp4
- [x] 4. 示波器实测频率与占空比        → 证据：04-pwm-wave.png
- [ ] 5. 参数写成注释/结构体           ← 还没做，补上
```

> **A 档没做完 = 项目不通过，必须重做**。B 档可以当次欠账，但要在评审表里登记补交计划，学期末必须补齐。

### 第 5 步 · 卡住了？按三级顺序查

**不要一卡住就喊老师**。按这个顺序，80% 的问题自己就能解决：

```
① 本项目 tutorials/PXX-*.md 的"常见问题表"   ← 先看这个
        ↓ 没解决
② 本项目 hints/PXX-*.md（速查 + 常见坑）
        ↓ 没解决
③ PITFALLS.md（全仓库踩坑库）
        ↓ 没解决
④ FAQ_入门必看.md（16 个高频问题）
        ↓ 还是没有
⑤ 问同学（限 15 分钟）
        ↓
⑥ 找配对的学长
        ↓
⑦ 到每周集体答疑时间问指导人
```

**问人的正确姿势**（信息量为零的提问会被打回）：

```
不要这样问：老师，我的程序不工作。

要这样问：
1. 我做了什么：在 P03 里把 PA0 配成下拉输入读按键
2. 我看到什么：串口打印的电平一直是 0，按下也不变
3. 我预期是什么：按下应该变成 1
```

> 把这三行写出来，往往自己就发现问题了。

### 第 6 步 · 整理成"四件套"

每个项目的交付物固定是**四件套**，缺一件视为未交付：

| # | 交付物 | 具体要求 |
|---|---|---|
| 1 | **源码 / 设计文件** | 能编译、能打开、能复现 |
| 2 | **实测证据** | 截图 / 视频 / 波形 / 万用表读数，文件名要有意义 |
| 3 | **README** | 原理 + 关键参数 + 踩过的坑 |
| 4 | **验收自测清单** | 逐条勾选，每条附证据文件名 |

### 第 7 步 · 提交到自己的仓库，把链接发给带教人

按下面这个目录结构放（**`projects/PXX-项目名/`**，与任务卡编号一致）：

```
你的仓库/
├── README.md                      ← 你从 P00 就在维护的那个
├── hello.txt                      ← P00 的练习文件
├── .gitignore                     ← 排除 .o / .hex / Debug/ / Objects/
└── projects/                      ← 所有作业都在这里
    ├── P01-环境搭建与第一个工程/
    │   ├── README.md              ← 四件套之三
    │   ├── 自测清单.md             ← 四件套之四
    │   ├── evidence/              ← 四件套之二：截图、视频、波形
    │   │   ├── 01-编译通过.png
    │   │   └── 02-LED闪烁.mp4
    │   └── src/                   ← 四件套之一：源码
    │       └── （CubeMX 工程文件）
    ├── P02-C语言补课与器件基础/
    └── P05-定时器与PWM/
        ├── README.md
        ├── 自测清单.md
        ├── evidence/
        └── src/
```

提交命令（在你自己仓库的根目录执行）：

```bash
git add .
git commit -m "P05: 完成定时器与PWM，A档5条+B档4条，附示波器实测波形"
git push
```

> **提交信息写清楚做了什么**。半年后你只会看这些信息——写 "aaa" 等于没写。

提交完把链接发给带教人：

```
https://github.com/你的用户名/你的仓库/tree/main/projects/P05-定时器与PWM
```

### 第 8 步 · 参加评审

每个项目结束要**当面讲 10 分钟**，按 [`REVIEW_TEMPLATE.md`](REVIEW_TEMPLATE.md) 打分（六维 × 5 分 = 30 分）。

评审的规矩：

- **必须你自己操作**，评审人不代劳；操作不出来的功能视为没做出来
- 出现报错时评审人**先不提示**，看你能否自己缩小范围
- **一定会被问的三题**（防抄例程）：
  1. 这个项目里你遇到的最大的坑是什么？怎么发现的、怎么解决的？
  2. 你的数据是怎么测出来的？用的哪个档位 / 哪个测量点？
  3. 如果现在改一个需求，你要改哪几个地方？

> 所以做项目时就要养成习惯：**测一个值就截一张图、记一行数据**。到评审时，这些证据本身就是答案。

## 四、交付规范：作业长什么样

- **每个项目一个目录**：`projects/PXX-项目名/`（编号与任务卡一致）
- **四件套齐全**：源码 + 实测证据 + README + 验收自测清单
- **交付日**：slot 结束前 2 天 23:59（具体日期见 [`GANTT.csv`](GANTT.csv) 的"交付日"列）
- **延期**：需提前说明，并在下个项目开始后 2 天内补交
- **允许查资料、问同学、问指导人**；**不允许直接复制别人的工程交上来**

## 五、卡住了怎么查

### 三级查询路径（再贴一次，这是最高频的动作）

| 顺序 | 查哪里 | 解决什么 |
|---|---|---|
| 1 | `tutorials/PXX-*.md` 的"常见问题表" | 本步骤的具体报错 |
| 2 | `hints/PXX-*.md` | 知识点速查、参考资源、常见坑、调试技巧 |
| 3 | [`PITFALLS.md`](PITFALLS.md) | 前人踩过的真坑（现象 → 原因 → 解决） |
| 4 | [`FAQ_入门必看.md`](FAQ_入门必看.md) | 16 个高频问题（环境/调试/仪器/交付） |
| 5 | 同学 → 学长 → 集体答疑 | 前三步都没解决时 |

### 五个最高频的坑（先看这五个）

1. **按键按不按都读到同一个电平** → 上拉/下拉配反了。蓝板 PA0 按下为高，必须配**下拉输入**
2. **下载不进去** → 查五件事：供电、SWD 三线（SWDIO/SWCLK/GND）、驱动、别占调试口、CubeMX 的 SYS→Debug 设为 Serial Wire
3. **写好的代码重新生成后没了** → 你的代码必须写在 `USER CODE BEGIN/END` 之间（**变量放 0 区，函数放 4 区**）
4. **编译报 `declaration may not appear after executable statement`** → Keil 没勾 **C99 Mode**
5. **Git 一直弹窗要密码且不对** → GitHub 停用了密码认证，要用 Token；另外查有没有"GitHub 加速镜像"改写了 `github.com`

## 六、带教人：怎么用这套方案开课

### 开班前（按顺序做完这 6 件事）

| # | 做什么 | 看哪 |
|---|---|---|
| 1 | 读总纲，确认 32 周日历与节奏 | [`MASTER_PLAN.md`](MASTER_PLAN.md) §1~§4 |
| 2 | **核对本校校历**：法定节假日、军训时间、期末复习周 —— 写回 §2.1 的扣除表 | [`MASTER_PLAN.md`](MASTER_PLAN.md) §2.1 |
| 3 | 确定班级规模，算评审人力，决定是否启用学长初筛 | [`MASTER_PLAN.md`](MASTER_PLAN.md) §6.1 |
| 4 | 按人数核对采购清单，**提前 2 周下单**（等货要时间） | [`BOM_采购清单.md`](BOM_采购清单.md) |
| 5 | 统一开发板型号为 **F103C8T6 蓝板**（混用其它型号会让教程引脚全部失效） | [`BOM_采购清单.md`](BOM_采购清单.md) §5 |
| 6 | 明确"谁付费"（学校经费 / 项目经费 / 学员自付）——这条不写清，P01 可能开不了工 | [`BOM_采购清单.md`](BOM_采购清单.md) §3 |

### 开学第一周

- 让学员做 [`ONBOARDING.md`](ONBOARDING.md) 的 12 分自测，按能力定路径（**按能力不按年级**）
- 检查 P00 的练习仓库（这一周内完成一次即可，不需当面评审）
- **提醒学员把带教人加为仓库协作者**，否则私有仓库打不开

### 每周固定动作

| 机制 | 频次 | 内容 |
|---|---|---|
| 集体答疑 | 每周 1 次，1 小时 | 学员带具体问题来，不接受"我不会" |
| 学长分片答疑 | 每人每周固定 30 分钟 | 按人固定时段，不是随时打断 |
| 技术分享 | 每月 1 次，20 分钟 | 讲一个真实踩的坑，讲稿进 `PITFALLS.md` |

### 每个项目结束

- 按 [`REVIEW_TEMPLATE.md`](REVIEW_TEMPLATE.md) 打分（**必须填"评审人"**）
- 判"有条件通过"时，补交项要写到"**哪天、交什么、谁来复核**"
- B 档欠账登记在表里，学期末统一清算

### 学长职责

- 每 2~3 名新生配 1 名学长
- 负责第一次代码/接线 review，**15 分钟/人**初筛四件套是否齐全
- 只把"有条件通过 / 不通过"的交给指导人复核
- 带人记录写进评审表，计入评优

> **首年没有学长怎么办**：本方案首届学员上面没有走过这条线的人。首年用"**同伴互评 + 指导人抽查 1/3**"替代，第二年再用上一届学员做学长。

## 八、常见疑问

**Q：这个仓库里的 STM32 方案，我能用在自己的学校/社团吗？**
可以。[`LICENSE`](LICENSE) 是文档 CC BY 4.0 + 代码 MIT，自由用于教学与二次开发，保留出处即可。

**Q：我用的不是 F103C8T6，能用吗？**
教程按 F103C8T6 蓝板写死了引脚（LED 在 PC13、按键在 PA0）。换板子的话**引脚、时钟、寄存器说明都要自己换算**，不建议。真要换，先读 [`tutorials/README.md`](tutorials/README.md) 的硬件前提。

**Q：一条任务卡里的 📖 链接点进去没反应？**
正常情况下 117 个链接全部有效（已用脚本逐条校验）。若发现失效，说明任务卡与教程的锚点不同步了——按 [`tutorials/README.md`](tutorials/README.md) 的锚点命名规则（`pXX-aN`）对齐即可。

**Q：B 档太难，可以不做吗？**
**两档都是全员要求**。A 档是底线（不做完＝项目不通过，必须重做）；B 档是上限，**当次可以欠账**，但要在评审表里登记补交计划，**学期末必须补齐，否则不能进下一阶段**。

**Q：寒暑假 8 周完全不排任务，会不会忘光？**
会。所以建议在寒假/暑假各布置 2 个轻量回炉任务（不计入 32 周，带教人自定）。P06 结束到 P07 开始隔了 8 周，而 P07 直接是 ★★★★ 难度，开学前需要热身。

**Q：为什么名义 32 周不够用？**
法定节假日约吃掉 12 个工作日，军训通常再吃掉 2~3 周。详见 [`MASTER_PLAN.md`](MASTER_PLAN.md) §2.1 的扣除表——**开班前必须按本校校历核对一次**。

**Q：我可以只用这套方案的一部分吗？**
可以。任务卡、教程、提示三个目录相对独立，只取 P01~P06 的秋季部分也成立（春季 P07~P10 依赖 P06 的协议封装）。
