# 大一 STM32 入门培养方案

> 面向**大一新生、零基础**的 STM32 单片机培训方案：一年 32 周，10 个项目，从装工具到独立做出一个完整作品。
> 所有学生学同一套内容，A 档保底 / B 档进阶，两档都是全员必做。

---

## 📍 第一次来？先读这里（3 分钟）

**你现在打开的 GitHub，是一个存放和管理代码的网站。** 这个仓库里放的，就是你这一年的**完整培养方案**——任务、知识点、排期、采购清单，全都在里面。老师会让大家照着它一步步做。

**你有两件事要分清**：

| | 是什么 | 你该做什么 |
|---|---|---|
| **这个仓库**（`stm32-freshman-plan`） | 课程方案本身，**只读参考** | 仔细看，不要往上提交任何东西 |
| **你自己的仓库** | 你按 P00 建的、属于自己的那个 | **你的所有作业都提交到这里** |

> 作业不是发文件给老师，而是**把代码提交到你自己的仓库，把链接发给老师**——老师打开就能看到你的代码，以及你每一步的修改过程。

**接下来按这个顺序走**：

| 步骤 | 做什么 | 去哪 |
|---|---|---|
| 1️⃣ | 弄明白 GitHub 是个什么网站、页面上各部分怎么用 | 📖 [`GITHUB_新手上路.md`](GITHUB_新手上路.md) |
| 2️⃣ | 了解整套方案的结构与节奏 | 👇 继续往下读本页 |
| 3️⃣ | **动手**：装 Git、注册账号、建**自己的**仓库、完成第一次提交 | ✅ [`tasks/P00-Git与GitHub入门.md`](tasks/P00-Git与GitHub入门.md) |
| 4️⃣ | 把 P00 的仓库地址发给带教人 | — |

以上 1~3 步是**开课前**要完成的（属于 P00 零周预备课，不计入 32 周）。做完这些，再开始 P01。

## 这套方案解决什么问题

大一新生常见的三个坎：**没写过程序、不会装开发环境、不知道单片机是干什么的**。所以这套方案不是"讲单片机知识"，而是**用 10 个项目把人从零带到能自己做出东西**：

- C 语言不单独开课，**嵌在项目里补**（P02 专门补一轮，后面每个项目都在用）
- 工具链从"点哪个菜单"讲起，不默认你会
- 每周一次固定答疑，卡住有人管
- 最后 4 周自己选题、自己做，交一个能演示的完整作品

## 仓库结构

```
.
├── GITHUB_新手上路.md      # ← 第一次来先读这个：GitHub 是什么、页面怎么用
├── tasks/                  # 任务区：只放任务与验收，不放知识点
│   ├── P00-Git与GitHub入门.md
│   ├── P01-环境搭建与第一个工程.md
│   └── ...
├── tutorials/              # 教程区：手把手怎么完成任务（每条任务都能点进来）
│   ├── P00-Git与GitHub入门.md
│   ├── P01-环境搭建与第一个工程.md
│   └── ...
├── hints/                  # 提示区：知识点、参考资源、常见坑、调试技巧
│   ├── P00-Git与GitHub入门.md
│   ├── P01-环境搭建与第一个工程.md
│   └── ...
├── MASTER_PLAN.md          # 总纲：日历、节奏、考核、支持机制
├── ONBOARDING.md           # 零基础起跑与插班定级
├── REVIEW_TEMPLATE.md      # 项目评审表与学期评审表
├── BOM_采购清单.md         # 采购清单与预算
├── GANTT.csv               # 逐项目排期（可导入 Excel）
├── PITFALLS.md             # 踩坑库
└── FAQ_入门必看.md         # 大一新生最常卡的 16 个问题
```

**三个目录的分工**：

| 目录 | 回答什么问题 | 什么时候看 |
|---|---|---|
| `tasks/` | **要做什么、怎么算过关** | 开始一个项目时 |
| `tutorials/` | **具体怎么做**（知识点详解 + 操作步骤 + 可复制代码） | 动手卡住时（任务卡里点 📖 链接直接跳） |
| `hints/` | 知识点速查、参考资源、常见坑 | 查资料、排查问题时 |

**任务区与提示区分开的原因**：任务区保持干净——只看「要做什么、怎么算过关」；知识点和踩坑全部放提示区，卡住时再查，不干扰执行。

## 核心规则

| 规则 | 说明 |
|---|---|
| 统一主线 | 不分软硬件方向，10 个项目所有人一起走 |
| A / B 档 | 全员必做：A 是保底，B 是进阶 |
| 周期 | 简单项目 2 周、综合项目 4 周；**不设每日/每周任务** |
| 交付 | 四件套：源码 + 实测证据 + README + 验收自测清单 |
| 评审 | 每个项目结束交东西 + 当面讲 10 分钟；讲不清不算完成 |
| 铁律 | A 档不做完 = 项目不通过，必须重做 |
| 答疑 | 每周固定 1 次，1 小时，带着具体问题来 |

## 开课前零周：P00 Git 与 GitHub 入门（不计入 32 周）

**开学前两周内自学完成**，不需要开发板，只需要一台电脑。这是整套方案的地基——后面 10 个项目的每一次交付都靠它。

| 项 | 说明 |
|---|---|
| 内容 | Git 三区概念、add/commit/log/status 四命令、建 GitHub 账号、建远程仓库、第一次 push、`.gitignore` |
| 时长 | 1~2 周（自学，节奏自定） |
| 是否计入 32 周 | **不计入**，属于开课前的预备课 |
| 交付 | 一个自己的练习仓库（含 `hello.txt`、`.gitignore`、README） |
| 验收 | 开课后第一周由带教人检查一次仓库，不需当面评审 |
| 成果去向 | P01 直接复用这个仓库：单片机工程提交到它的 `projects/` 目录 |

> 为什么单独前置：如果等做 P01 时再学，你会在"LED 还没点亮"的压力下把版本管理糊弄过去。工具链里 Git 和 IDE 是同级的前置依赖。

任务卡见 `tasks/P00-Git与GitHub入门.md`，知识点与常见坑见 `hints/P00-Git与GitHub入门.md`。

## 怎么用这个方案

1. **开学前**：完成 P00（Git 与 GitHub 入门），把练习仓库建好。
2. 带教人先读 `MASTER_PLAN.md`，确认日历与节奏。
3. 学员入学先做 `ONBOARDING.md` 的自测（零基础直接走"零基础路径"）。
4. 按 `tasks/` 顺序推进；每个项目开始前看一遍 `hints/` 里的知识点。
5. 交付时把四件套放进个人仓库 `projects/PXX-项目名/`，按 `REVIEW_TEMPLATE.md` 评审。
6. 踩了坑就往 `PITFALLS.md` 补一条（评审加分）。
