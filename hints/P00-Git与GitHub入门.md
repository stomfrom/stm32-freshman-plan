# P00 提示：Git 与 GitHub 入门

## 知识点

1. 版本管理解决什么问题：每次提交都是一个可回退的存档点，改坏了能退回来，还能看清每一步改了什么。
2. Git 与 GitHub 的区别：Git 是**装在你电脑上的工具**（离线也能用），GitHub 是**存放仓库的网站**；Git 可以完全不联网使用。
3. 三个区域：工作区（你正在编辑的文件）→ 暂存区（`git add` 放进来的改动）→ 本地仓库（`git commit` 存档）。`git status` 就是看这三个区域的当前状态。
4. 四个最常用命令：`git status`（现在什么状态）、`git add`（把改动放进暂存区）、`git commit`（存成一个版本）、`git log`（看历史）。**这四条覆盖日常 80% 的用法。**
5. 本地仓库与远程仓库：`git push` 把本地提交传到 GitHub，`git clone` 把远程仓库完整拷到本地（含全部历史）。
6. 提交信息怎么写：一句话说清"这次改了什么、为什么改"，例如"新增 LED 闪烁程序""修复按键抖动导致重复触发"。半年后你只会看这些信息，写"aaa"等于没写。
7. `.gitignore` 的作用：列出"不需要纳入版本管理"的文件。单片机项目里编译产物（`.o`、`.hex`、`Debug/`、`Objects/`）每次都变、且能重新生成，**必须排除**，否则仓库会被塞满垃圾、且每次编译都显示"有改动"。
8. 分支的基本概念：分支让你在不影响主线的副本上试新想法，试好了再合并回主线。

## 常见坑

- **反复弹出要求输入账号密码的窗口，怎么输都不对**：这是最常见也最让人崩溃的问题。原因通常是三种：① 密码认证已被 GitHub 停用，必须用 **Personal Access Token** 或凭据管理器，不能输账号密码；② 本机装了 **GitHub 加速镜像**（把 `github.com` 自动改写到别的网站），而镜像站只读、不接受推送，于是凭据永远对不上；③ 之前输错过一次，系统把错误凭据缓存了，之后一直用错的那份。
  **解决顺序**：先确认自己是不是在用加速镜像（查 `git config --global --get-regexp url.` 有没有 `insteadOf` 改写规则）→ 改用推荐方式认证（`gh auth login` 或凭据管理器）→ 清掉缓存的错误凭据后重试。
- **`git push` 提示 rejected / non-fast-forward**：远程有你本地没有的提交（常见于在网页上直接改过文件）。先 `git pull` 把远程改动合并下来，再 push。
- **`git commit` 说 "nothing to commit"**：忘了先 `git add`，改动还在工作区、没进暂存区。
- **提交了一堆不该提交的文件**：编译产物、临时文件、大压缩包。**先把 `.gitignore` 写对再提交**；已经提交了的，需要从仓库里移除后再提交一次。
- **在错误的目录执行 `git init`**：比如在 `C:\Users\你的名字` 下初始化，把整个用户目录变成仓库。执行前用 `pwd`（或 Windows 的 `cd`）确认当前路径。
- **`git config` 没加 `--global`**：配置只对当前仓库生效，换个目录又要重配。个人电脑上一般都用 `--global`。
- **误以为"提交=上传"**：`git commit` 只存在本地，`git push` 才上传。很多人 commit 完就去网页刷新，发现什么都没有。

## 调试技巧（出问题时怎么自己定位）

- **先看状态再问人**：`git status` 的输出几乎能解释一半的问题（改动在哪、暂存了没有、有没有冲突、要不要 pull）。
- **看懂三行关键输出**：`On branch xxx`（在哪个分支）、`Changes not staged`（改了但没 add）、`Changes to be committed`（add 了但没 commit）——这三行就能定位你卡在哪一步。
- **用 `git log --oneline` 快速看历史**：一眼看清提交次数与信息，确认 push 前本地确实有提交。
- **`git diff` 看具体改了什么**：不确定自己改了什么、或合并前想确认差异时用它，比来回切文件可靠。
- **出问题先别删仓库**：Git 里几乎所有误操作都能救回来，删掉重建才是真的丢历史。卡住时先截图问人。
