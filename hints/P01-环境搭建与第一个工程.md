# P01 提示：环境搭建与第一个工程：点灯

## 知识点

1. STM32 是什么：内核（Cortex-M）、Flash（存程序）、RAM（存变量）、外设（GPIO/定时器/串口等）四块基本构成。
2. 开发流程：CubeMX 配硬件 → 生成工程骨架 → 在用户代码区写逻辑 → 编译 → 烧录 → 运行。
3. GPIO 输出模式：推挽输出适合直接驱动 LED，开漏输出需要外部上拉。
4. 时钟树：外部晶振（HSE）→ PLL 倍频 → SYSCLK → AHB/APB 分频给各外设；LED 闪烁慢和它无关，串口波特率错和它有关。
5. HSE 与 HSI 的区别：HSE 是板上的外部晶振，精度高；HSI 是芯片内部 RC，精度低。
6. CubeMX 生成代码的规则：`/* USER CODE BEGIN */` 与 `/* USER CODE END */` 之间的代码在重新生成时不会被覆盖。
7. `.ioc` 文件的作用：它是 CubeMX 的工程配置本体，必须提交到仓库；重新生成工程靠它。
8. SWD 调试口：只需 SWDIO、SWCLK、GND 三根线就能烧录与在线调试。

## 参考资源

1. STM32CubeMX 用户手册中「Project Manager」与「Clock Configuration」两章。
2. 你所买开发板的原理图（找 LED 接在哪个引脚、是高电平点亮还是低电平点亮）。
3. HAL 库 `HAL_GPIO_TogglePin` / `HAL_Delay` 的 API 说明。

## 常见坑

- **LED 点了不亮**：先确认引脚号对不对，再确认是高电平点亮还是低电平点亮（很多板子 LED 一端接 VCC，需要输出低电平才亮），最后用万用表量引脚电压。
- **CubeMX 重新生成后自己写的代码没了**：代码写在 `USER CODE BEGIN/END` 之外的区域，重新生成时会被覆盖——必须写在保护区里。
- **Keil 报找不到芯片 / 无法下载**：多半是 Pack 包没装、调试器驱动没装，或 SWD 线接反；先看烧录器指示灯。
- **`HAL_Delay` 卡死在第一个调用**：CubeMX 里忘了配 SysTick 或被误关，检查 `HAL_Init()` 是否正常返回。
- **Git 提交把编译产物也传上去了**：仓库几百 MB 全是 .o 文件，必须提前写好 `.gitignore`。
- **中文路径导致编译失败**：工程路径和用户名里不要有中文或空格，老工具链经常在这里出问题。

## 调试技巧（无逻辑分析仪时的替代手段）

- **最少代码法**：点灯不亮时先把程序简化成"上电直接置高引脚、不调延时"，排除延时和时钟问题。
- **万用表量引脚**：程序跑起来后用万用表直流电压档量 LED 引脚，1Hz 闪烁时读数会在两个值之间跳变，能证明程序在跑。
- **串口打点**：任何"不确定程序走到哪"的时候，在关键位置 `printf` 一句，看串口输出到哪一步停住。
- **换一块板子/换一个引脚验证**：怀疑硬件坏了就先换引脚或换板，十几秒就能排除一大类问题。
