# P06 提示：UART 与自定义协议：帧解析与 CRC

## 知识点

1. 串口参数四要素：波特率、数据位、停止位、校验位，两端必须完全一致。
2. 同步与异步：串口是异步通信，靠约定的波特率对齐，没有时钟线，所以波特率误差大就会乱码。
3. 帧同步：接收方不知道数据从哪个字节开始是一帧，靠"帧头"这个固定字节序列来对齐。
4. 状态机解析法：把接收过程拆成"等帧头 / 收长度 / 收数据 / 校验 / 完成"几个状态，逐字节推进。
5. 校验和的局限与 CRC 的价值：简单累加和检测不出交换顺序的错误，CRC 能检测绝大多数突发错误。
6. 环形缓冲区：写指针与读指针循环移动，解决"接收速度与处理速度不一致"的问题。
7. 串口空闲中断的作用：一帧数据发完总线会空闲一段时间，利用这个事件判断"这一帧收完了"。
8. 超时保护：如果一帧收了一半就再也没有后续字节，必须有超时机制丢弃残帧，否则协议状态机永远卡在中间状态。

## 常见坑

- **帧头字节出现在数据里导致误同步**：数据字段里恰好有和帧头相同的字节，会把数据当成新帧开头；解决办法是帧头用双字节、或对数据进行转义。
- **收了一半的帧永远卡住状态机**：没有超时机制，一旦丢字节就永远等不齐长度，必须加超时或空闲检测复位状态机。
- **环形缓冲区读写指针竞争**：中断里写、主循环里读，两个指针没做保护会导致数据错乱，至少要把指针操作做成原子性的。
- **CRC 算法与对端不一致**：初值、多项式、是否反转、是否异或输出四个参数任意一个不同就校验不过，必须双方约定并写进文档。
- **用 `printf` 在中断里打印**：串口发送是阻塞的，在中断里打印会拖长中断时间并可能丢失接收数据。
- **调试时改了协议忘记同步改文档**：对端按老文档实现，联调对不上；协议文档要跟着代码一起更新。

## 调试技巧（无逻辑分析仪时的替代手段）

- **十六进制打印每个收到的字节**：用 `%02X` 打印，能直观看出帧头在哪、长度对不对、校验差多少。
- **先自发自收**：把单片机的发送引脚与接收引脚短接（或用一个串口回环），自己发自己收，先验证收发链路通了再联调。
- **校验值单独打印**：把计算得到的校验值和对端发来的校验值都打出来对比，一眼看出是算法不一致还是数据不对。
- **降速排查**：把波特率降到 9600 再测，如果变正常了说明是处理速度或中断时间的问题，不是协议逻辑问题。
- **错误计数器**：给每类异常各配一个计数器并周期性上报，跑一段时间后看哪类错误在涨，比逐个断点调试快得多。
