# P00 Git 与 GitHub 入门（开课前零周预备课）

| 项目编号 | P00 | 周期 | 开学前自学（不计入 32 周） |
|---|---|---|---|
| 学期 | 零周 · 预备课 | 建议完成时间 | 2026-09-01 ~ 2026-09-13（开学前两周内） |
| 难度 | ★ | 适用 | A、B 两档全员必做 |

## 前置要求

- 无。这是整套方案的第一课，**开课前完成**；只需要一台电脑。
- 不需要开发板，不需要单片机，本课只碰 Git 与 GitHub。

## 为什么先学这个

后面 10 个项目、每一次交付、每一次评审，都要用到这套流程。如果等到做 P01 时再学，你会在"LED 还没点亮"的压力下糊弄过去——**而版本管理是唯一一样能让你少走几年弯路的基础工具**：它让你改坏了能退回去，也让老师能看见你这一年到底做了什么。

> 📖 **从没接触过 GitHub？先花 10 分钟读根目录的 [`GITHUB_新手上路.md`](../GITHUB_新手上路.md)**：讲清 GitHub 是个什么网站、打开仓库页面后各部分怎么看、哪些按钮不要乱点。读完再回来做下面的任务。

## 任务

### A 档 · 全员必做（保底）

- [ ] 1. 用自己的话写一段不超过 100 字的说明：Git 与网盘（或 QQ 传文件）有什么不同。写进下面第 8 条的仓库 README 里。
- [ ] 2. 在电脑上安装 Git，装完打开命令行执行 `git --version`，把输出的版本号截图。
- [ ] 3. 执行 `git config --global user.name "你的名字"` 和 `git config --global user.email "你的邮箱"`，然后用 `git config --global --list` 把这两项配置截图。
- [ ] 4. 新建一个文件夹，在里面放一个 `hello.txt`，用命令把该文件夹变成 Git 仓库（`git init`），并截图 `git status` 的输出。
- [ ] 5. 把 `hello.txt` 提交到仓库：先 `git add`，再 `git commit`（写一条有意义的中文提交信息），然后用 `git log` 截图看到这次提交。
- [ ] 6. 修改 `hello.txt` 的内容，再用 `git status` 观察"已修改但未提交"的状态并截图；然后提交第二次。
- [ ] 7. 注册一个 GitHub 账号（用常用邮箱），在网站上新建一个**私有**仓库，仓库名自定。
- [ ] 8. 把这个本地仓库与 GitHub 上的远程仓库连起来，并完成第一次 `push`；推送后在**浏览器打开仓库网页**，确认能看到 `hello.txt` 与两条提交记录，并截图。在这个仓库里写一份 README，把你第 1 条的说明放进去。
- [ ] 9. 在仓库里新建 `.gitignore` 文件，把 `.o`、`.hex`、`Debug/`、`Objects/` 这几类编译产物写进去（后面做单片机项目时马上就会用到），提交并推送。

### B 档 · 全员必做（进阶）

- [ ] 1. 建立分支：新建分支 `feature/edit-hello`，在分支上修改 `hello.txt` 并提交，然后把该分支合并回主分支，截图 `git log --graph --oneline` 的结果。
- [ ] 2. 做一次"改坏了再救回来"的练习：修改 `hello.txt` 后**先不提交**，用命令把这次修改撤销掉，确认文件回到修改前的样子并截图。
- [ ] 3. 把远程仓库上的内容用 `clone` 重新拉取到另一个文件夹，打开确认文件与提交历史完整，说明 `clone` 与"下载压缩包"的区别。
- [ ] 4. 在 GitHub 网页上查看自己仓库的提交历史，点开某一次提交，讲清"这次提交改了哪几行"；把截图放进 README。
- [ ] 5. 写一份让不看代码的人也能看懂的 README：包含本仓库是做什么的、目录里有什么、怎么运行或查看。提交并推送。
- [ ] 6. 做一次"提交回顾"实验：故意写一条无意义的提交信息（如"aaa"），然后说明为什么这样的信息在半年后对你自己也没用，并把正确的写法写进 README。

## 交付物

1. 源码 / 设计文件：本地练习仓库（含 `hello.txt`、`.gitignore`、README）。
2. 实测证据：`git --version`、`git config --list`、`git status`、`git log`、GitHub 仓库网页、提交历史页面的截图（共不少于 6 张）。
3. README：第 A 档第 1 条的说明、仓库用途与目录说明、以及你实际用到的 Git 命令清单。
4. 验收自测清单：逐条勾选任务并附证据文件名。

## 验收标准

- `git --version` 能正常输出版本号，`git config --global --list` 里能看到你自己配置的用户名与邮箱。
- GitHub 上存在你的私人仓库，浏览器打开能看到文件内容与不少于 2 条提交记录（不是只有 1 条）。
- 远程仓库里能看到 `.gitignore`，且里面包含 `.o`、`.hex`、`Debug/`、`Objects/` 四类规则。
- 能当场演示完整流程：修改文件 → `git status` 看到变化 → `add` → `commit` → `push` → 网页刷新看到新提交（评审时操作，不看笔记）。
- 能用自己的话解释：为什么改坏了能恢复、提交信息为什么要写清楚。
- 截图齐全且能对应到每条任务（评审时抽查 3 张，能说清分别是哪一步）。
- 分支合并练习后，`git log --graph --oneline` 能看出分支与合并的结构（B 档）。

## 提交要求

- 本课的交付物就是你自己的**练习仓库**，请在开课前把仓库地址发给带教人。
- 本课的成果将在 P01 中直接使用：P01 要求你把单片机工程提交到**同一个仓库**的 `projects/` 目录下。
- 不需要当面评审；带教人在开课后第一周内检查一次仓库即可。
