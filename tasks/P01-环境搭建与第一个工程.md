# P01 环境搭建与第一个工程：点灯

| 项目编号 | P01 | 周期 | 2 周 |
|---|---|---|---|
| 学期 | 秋季 slot 1 | 起止日期 | 2026-09-14 ~ 2026-09-27 |
| 难度 | ★ | 适用 | A、B 两档全员必做 |

## 前置要求

- 无。这是第一个项目，零基础从这里开始；只需要一台电脑和一块 STM32 开发板。

## 任务

### A 档 · 全员必做（保底）

- [ ] 1. 在电脑上安装 STM32CubeMX 与 Keil MDK（或 VS Code + PlatformIO，二选一），截图记录软件名称与版本号。
- [ ] 2. 用 STM32CubeMX 新建一个工程：选定开发板对应的芯片型号，把调试口设为 SWD，把系统时钟源设成外部晶振。
- [ ] 3. 在 CubeMX 的引脚图上把板载 LED 对应的引脚配置成 GPIO_Output 推挽输出，生成 Keil（或 PlatformIO）工程。
- [ ] 4. 在生成的工程里写代码，让板载 LED 以 1Hz 闪烁（亮 500ms、灭 500ms）。
- [ ] 5. 编译工程，确认 0 错误 0 警告；用烧录器下载到开发板，确认 LED 真的在闪。
- [ ] 6. 安装 Git，在 GitHub（或 Gitee）建一个个人仓库，把工程提交上去，并写好 `.gitignore` 排除编译产物。
- [ ] 7. 提交后打开远程仓库网页，确认能看到你的 `.c` 源文件，且没有 `Objects/`、`Debug/` 这类编译产物目录。

### B 档 · 全员必做（进阶）

- [ ] 1. 在 CubeMX 的时钟树界面截图，逐项说明：外部晶振频率、PLL 倍频系数、最终 SYSCLK 频率各是多少。
- [ ] 2. 重定向 `printf` 到串口，用 115200 波特率在串口助手上打印一行开机信息（含你的项目名与日期）。
- [ ] 3. 修改 CubeMX 配置，把 LED 换到另一个 GPIO 引脚上重新生成工程并点灯成功，说明 CubeMX 重新生成后哪些文件被覆盖了。
- [ ] 4. 在 README 里画一个连接框图，标出「电脑 → 烧录器 → 单片机 → LED」之间的连线与供电关系。

## 交付物

1. 源码 / 设计文件：完整可编译的工程（含 `.ioc` 配置文件的 CubeMX 工程）、个人 Git 仓库地址。
2. 实测证据：LED 闪烁的视频或连拍照片、串口助手收到打印信息的截图、CubeMX 时钟树截图。
3. README：软件版本、芯片型号、LED 引脚号、时钟树关键参数、烧录步骤。
4. 验收自测清单：逐条勾选任务并附证据文件名。

## 验收标准

- 上电后 LED 以 1Hz 稳定闪烁，连续观察 5 分钟不出现停闪或乱闪。
- Keil 编译输出 0 错误；警告数 ≤ 2 条，且能在 README 里说明警告原因。
- 拔掉烧录器重新上电，程序仍能自动运行（说明已烧进 Flash，不是调试器在跑）。
- 远程仓库里能同时看到源码与 `.gitignore`，看不到 `Objects/`、`Debug/` 目录。
- 串口助手在 115200 波特率下能完整收到开机信息，无乱码。
