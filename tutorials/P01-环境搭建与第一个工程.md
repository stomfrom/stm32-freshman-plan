## 0 · 开工前的准备

### 0.1 开发流程（先建立全局观）

```
①  CubeMX 配硬件      →  在图形界面上点引脚、配时钟、选外设
②  CubeMX 生成工程    →  自动生成初始化代码骨架（.c/.h）
③  在 USER CODE 区写逻辑 →  你只写业务代码，配置代码不手动改
④  Keil 编译          →  F7
⑤  烧录到板子         →  F8（通过 ST-Link）
⑥  运行观察           →  LED 闪、串口打印
```

**关键规则**：你的代码**只写在** `/* USER CODE BEGIN */` 和 `/* USER CODE END */` 之间。这两个标记外面的代码会在你下次用 CubeMX 重新生成时**被覆盖**。

### 0.2 硬件清单

| 物品 | 说明 |
|---|---|
| STM32F103C8T6 最小系统板 | 常见"蓝板" |
| ST-Link 烧录器（或板载） | 用于下载与调试 |
| **USB 转 TTL 串口模块（CH340）** | **B2 的串口打印要用，必须提前备好**（板载 USB 不能替代） |
| 杜邦线 | 连接 SWD；B2 还要额外 3 根接串口模块 |
| USB 线 | 供电 + 连接烧录器（至少一条能传数据，不能是纯充电线） |

## A1 · 安装 CubeMX 与 Keil

**任务**：在电脑上安装 STM32CubeMX 与 Keil MDK，截图记录软件名称与版本号。

### 知识点

**两个软件分工**：

| 软件 | 干什么 | 类比 |
|---|---|---|
| **STM32CubeMX** | 图形化配置芯片（引脚、时钟、外设），生成初始化代码 | 画图纸 |
| **Keil MDK** | 编辑代码、编译、烧录、调试 | 施工 + 验收 |

**为什么用 CubeMX**：不用手写几百行寄存器初始化代码，而且**引脚冲突它会直接报错**。

**本方案统一使用 Keil MDK + STM32CubeMX**，所有教程都按 Keil 编写（`fputc` 重定向、MicroLIB、F7/F8、Options for Target 都是 Keil 专有）。如果你想用 VS Code + PlatformIO，printf 重定向要改成 `_write()`、C99 默认开、工程加文件的方式也不同——这部分差异需要你自己补，教程不再覆盖；卡住时按 Keil 走。

### 操作步骤

**1. 安装 STM32CubeMX**

1. 到 ST 官网搜 `STM32CubeMX`，下载安装包（需要注册 ST 账号）
2. 安装时若提示安装 JDK，让它自动装
3. 首次运行会提示下载芯片固件包（`F1` 系列），**必须下载**——否则新建工程时选不到芯片

**2. 安装 Keil MDK**

1. 到 Keil 官网下载 `MDK-ARM`，安装
2. 装完后**还要装芯片支持包**：到 Keil 官网下载 `Keil.STM32F1xx_DFP`，双击安装（或让 Keil 自动下载）

> **⚠️ 关于 Keil 的代码上限**：MDK-Lite / 社区版有 **32 KB 代码限制**，超过会编译报错或无法生成可执行文件。查看方法：编译后看 `Build Output` 里 `Code + RO-data + RW-data` 之和。只点灯的项目离上限很远，但后面加上 HAL 库 + 串口 + OLED 驱动后可能逼近上限——那时需要用学校/项目购买的正式 License，或精简不用的外设。

**3. 记录版本号**

打开两个软件，在 `Help` → `About` 里看版本号，截图。

| 软件 | 版本号 |
|---|---|
| STM32CubeMX | ____ |
| Keil MDK | ____ |

### 验证方法

- CubeMX 能打开、能在新建工程时搜到 `STM32F103C8`
- Keil 能打开
- 两个版本号都有截图

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| CubeMX 搜不到芯片 | 固件包没下载 | 在 CubeMX 里 `Help`→`Manage embedded software packages` 下载 F1 包 |
| Keil 编译报找不到器件 | 没装 DFP 支持包 | 装 `STM32F1xx_DFP` |
| CubeMX 启动报缺 Java | 没装 JDK | 重装 CubeMX 并选自动装 JDK |

## A2 · CubeMX 新建工程

**任务**：用 STM32CubeMX 新建一个工程：选定开发板对应的芯片型号，把调试口设为 SWD，把系统时钟源设成外部晶振。

### 知识点

**调试口设为 SWD 为什么必须做**：F103 复位后，SWJ-DP 默认就是 **SWD + JTAG 使能**状态，所以刚拿到的板子一般能直接用 SWD 烧录。在 CubeMX 里显式选 `Serial Wire`，作用是：① 明确告诉 CubeMX 你要用调试口，生成的初始化代码里带上对应配置；② 防止以后不小心把 **PA13 / PA14** 复用成普通 GPIO，把调试口自己占掉。

真正会让板子"变砖"的，是**程序里主动关闭 SWJ、重映射调试引脚，或者让芯片进了低功耗模式**——那种情况才需要特殊手段救回来；正常烧录不会因为没选 Debug 就变砖。

**外部晶振（HSE）vs 内部时钟（HSI）**：

| | HSE 外部晶振 | HSI 内部 RC |
|---|---|---|
| 精度 | 高（±20ppm 级） | 低（±1% 级） |
| 最高频率 | 能到 72MHz | 也够用但偏差大 |
| 影响 | 串口波特率准、定时准确 | 串口容易乱码、定时偏 |
| 建议 | **用 HSE** | 板子没焊晶振时才用 |

### 操作步骤

1. 打开 **STM32CubeMX** → `File` → **`New Project`**
2. 在 `Part Number` 搜索框输入 `STM32F103C8`
3. 在列表里选中 **`STM32F103C8Tx`** → 点 **`Start Project`**
4. 左侧 **`System Core`** → **`SYS`** → `Debug` 选 **`Serial Wire`**
5. 左侧 **`System Core`** → **`RCC`** → `High Speed Clock (HSE)` 选 **`Crystal/Ceramic Resonator`**
6. 切到顶部 **`Clock Configuration`** 标签：
   - 找到 `HCLK (MHz)` 的输入框，填 **`72`**，回车
   - CubeMX 会自动算出 PLL 倍频等参数（`PLLMul` 显示 `X9`）
   - 若出现**红色**，说明参数冲突，按提示调整分频

### 验证方法

- 引脚图上能看到 `PA13`、`PA14` 被标为 SWD 功能（不是普通 GPIO）
- `Clock Configuration` 里 `HCLK` 显示 `72 MHz`，且没有红色告警
- `RCC` 里 `HSE` 显示 `Crystal/Ceramic Resonator`

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 时钟树一片红 | 参数组合无解 | 先设 HCLK=72 让工具自动算；或临时降为 64MHz |
| 板子没焊外部晶振 | 选了 HSE 但硬件没有 | **只选 HSI**（`Clock Configuration` 里把 HSE 关掉）；`Bypass` 只用于"外部有源时钟源直接灌 8MHz"的情形，别选错 |
| 忘了设 SWD | — | **回头补上**，这步不能省 |

## A3 · 配置 LED 引脚并生成工程

**任务**：在 CubeMX 的引脚图上把板载 LED 对应的引脚配置成 GPIO_Output 推挽输出，生成 Keil 工程。

### 知识点

**GPIO 输出模式**：

| 模式 | 特点 | 用途 |
|---|---|---|
| **推挽输出（Push Pull）** | 能主动输出高和低 | **驱动 LED**、一般场合 |
| 开漏输出（Open Drain） | 只能拉低，高电平靠外部上拉 | I2C 总线、多设备共享线 |

**推挽是默认选择**，驱动 LED 用它就对了。

**先确认 LED 接法**：看板子原理图或丝印，确认 LED 接在哪个引脚、是高电平点亮还是低电平点亮。

| 板子 | LED 引脚 | 点亮条件 |
|---|---|---|
| 常见蓝板 | **PC13** | **低电平**（接 GND 才亮） |
| 部分板 | PA5 等 | 高电平 |

### 操作步骤

1. 回到 CubeMX，在右侧芯片图里**左键点击 `PC13`** → 弹窗选 **`GPIO_Output`**
2. 左侧多出 **`System Core` → `GPIO`** 菜单 → 点进去
3. 找到 `PC13`，设置：

   | 参数 | 设为 |
   |---|---|
   | `GPIO output level` | `High`（初始熄灭，低电平点亮时） |
   | `GPIO mode` | `Output Push Pull` |
   | `GPIO Pull-up/Pull-down` | `No pull-up and no pull-down` |
   | `Maximum output speed` | `Low`（驱动 LED 不需要高速） |
   | `User Label` | **`LED`**（填了以后代码里会出现 `LED_Pin`，更好读） |

4. 点顶部 **`Project Manager`** 标签：
   - `Project Name` 填 **`P01_LED_Blink`**
   - `Project Location` 选**纯英文、无空格**的**父目录**（如 `D:\stm32`）——CubeMX 会在它下面**再建一个同名子目录**，所以实际工程路径是 `D:\stm32\P01_LED_Blink`（后面 `cd` 进工程时要按真实路径走）
   - `Toolchain / IDE` 选 **`MDK-ARM`**（CubeMX 这个下拉框只有 `MDK-ARM` 一项，对应 Keil MDK **V5** 工程，不需要再选版本）
   - 左侧 `Code Generator` 里勾 **`Generate peripheral initialization as a pair of .c/.h files`**
5. 点右上角 **`GENERATE CODE`**
6. 生成完成后点 **`Open Project`**，Keil 会自动打开工程
7. **⭐ 第一次打开工程后第一件事**：Keil → `Options for Target`（魔术棒图标）→ **`C/C++`** 标签 → 勾选 **`C99 Mode`**。

   > ⚠️ **必须勾**：CubeMX 生成的默认工程是 **C90**，而本套教程的示例代码大量使用"语句之后再声明变量"和 `for (uint8_t i = ...)` 这类 C99 写法。不勾就会报 `declaration may not appear after executable statement`。**每新建一个工程都要勾一次。**

### 验证方法

- Keil 里能看到工程结构（`Core/Src/main.c`、`Core/Inc/main.h` 等）
- `main.c` 里能找到 `MX_GPIO_Init` 函数，里面有你配的 PC13
- `main.h` 里能看到 `LED_Pin`、`LED_GPIO_Port` 的宏定义
- Keil 的 `Options for Target` → `C/C++` 里 **`C99 Mode`** 已勾选

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 点引脚没反应 | 引脚被别的功能占用了 | CubeMX 会报冲突，先解决冲突 |
| 生成的工程打不开 | Keil 版本与 CubeMX 里选的不一致 | 重新生成，选对版本 |
| 路径含中文导致失败 | 老工具链不支持 | 换成纯英文路径 |

## A4 · 写 1Hz 闪烁代码

**任务**：在生成的工程里写代码，让板载 LED 以 1Hz 闪烁（亮 500ms、灭 500ms）。

### 知识点

**1Hz 闪烁 = 周期 1 秒**，即亮 500ms + 灭 500ms。

```
      ┌──────┐      ┌──────┐
      │ 亮   │      │ 亮   │
──────┘      └──────┘      └──
      <500ms><500ms>
      <──── 1秒（1Hz）────>
```

**两个 HAL 函数够用**：

| 函数 | 作用 |
|---|---|
| `HAL_GPIO_WritePin(port, pin, state)` | 设置引脚电平（`GPIO_PIN_SET`=高 / `GPIO_PIN_RESET`=低） |
| `HAL_Delay(ms)` | 阻塞延时指定毫秒 |

### 操作步骤

打开 `Core/Src/main.c`，找到 `while (1)` 循环，在 `/* USER CODE BEGIN WHILE */` 与 `/* USER CODE END WHILE */` 之间写：

```c
while (1)
{
    /* USER CODE BEGIN WHILE */
    /* 低电平点亮：RESET=亮, SET=灭 */
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);   /* 点亮 */
    HAL_Delay(500);                                              /* 亮 500ms */

    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);     /* 熄灭 */
    HAL_Delay(500);                                              /* 灭 500ms */

    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    /* USER CODE END 3 */
}
```

> **如果你的板子是高电平点亮**：把两个 `GPIO_PIN_RESET` 和 `GPIO_PIN_SET` 对调。

> **如果你的 LED 不在 PC13**：`LED_GPIO_Port` 和 `LED_Pin` 会跟着你配的引脚自动变（因为你填了 User Label `LED`）。没填 Label 的话，要手写成 `GPIOC, GPIO_PIN_13`。

### 验证方法

- 代码能编译通过（下一步验证）
- 逻辑上：亮 500ms、灭 500ms，循环

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 编译报 `LED_Pin` 未定义 | User Label 没填 | 用 `GPIOC, GPIO_PIN_13` 代替 |
| 代码写完重新生成后没了 | 写在了 USER CODE 区外面 | 只写在 `USER CODE BEGIN/END` 之间 |

## A5 · 编译下载验证

**任务**：编译工程，确认 0 错误 0 警告；用烧录器下载到开发板，确认 LED 真的在闪。

### 操作步骤

**1. 编译**

Keil 里按 **`F7`**（或点 `Build` 图标）。看下方 `Build Output`：

```
Build started: Project: P01_LED_Blink
...
0 Error(s), 0 Warning(s).
```

**0 错误**是必须的；警告如果 ≤2 条且你能解释原因，也可以接受。

**2. 连接硬件**

| ST-Link | 板子 | 说明 |
|---|---|---|
| SWDIO | SWDIO | 必需 |
| SWCLK | SWCLK | 必需 |
| GND | GND | **必需**（必须共地） |
| 3.3V | 3.3V | **只在板子没有独立供电时才接**；板子已经用 USB 供电就**不要接** |

> **只接 SWDIO / SWCLK / GND 三根就够了**。开发板自己用 USB 供电时，ST-Link 的 3.3V 一定不要接——两路 3.3V 对冲可能损坏板子或烧录器。

**3. 配置烧录**

Keil → `Options for Target`（魔术棒）→ **`Debug`** 标签 → 右上角选 **`ST-Link Debugger`** → 点旁边 **`Settings`** → 在 `Debug` 页确认能识别到芯片（能看到 `ARM Cortex-M3` 之类）。

再切到 **`Flash Download`** 页核对两件事（CubeMX 生成的工程通常已经配好，但要会查）：

- `Programming Algorithm` 列表里应该有 **`STM32F10x Med-density Flash`**；空的就点 `Add` 添加——漏了会报 `No Algorithm found`
- 勾上 **`Reset and Run`**（下载完自动复位运行，省得每次手按复位键）

**4. 下载**

按 **`F8`**（或点 `Download` 图标）。成功时输出：

```
Programming Done.
Verify OK.
```

**5. 观察**

- 板上 LED 应以约 1 秒周期闪烁
- **拔掉烧录器、重新上电**，LED 仍然闪（证明程序真的烧进了 Flash）

### 验证方法

- 编译 0 错误
- 下载提示 `Programming Done` / `Verify OK`
- LED 以约 1Hz 闪烁，连续观察 5 分钟不停不乱
- **断开烧录器后重新上电仍能自动运行**

### 常见问题

**⭐ 下载报"找不到设备"**

按顺序查四件事：

| # | 检查项 | 怎么查 |
|---|---|---|
| 1 | 板子供电了吗 | 看板上电源指示灯亮不亮 |
| 2 | SWD 线接对了吗 | SWDIO/SWCLK/GND 三根，别接反 |
| 3 | 烧录器驱动装了吗 | 设备管理器里看有没有黄色感叹号 |
| 4 | 调试口被占用了吗 | 关掉其他用 ST-Link 的软件（比如上一个 Keil 窗口） |

| 其他现象 | 原因 | 怎么办 |
|---|---|---|
| 编译报一堆错 | 头文件路径/支持包问题 | 确认 DFP 包装了 |
| 下载报 `No Algorithm found` | `Flash Download` 页没加载编程算法 | 点 `Add` 选 `STM32F10x Med-density Flash` |
| LED 不亮 | 引脚号错 / 高低电平反了 | 对着原理图确认，先试着对调 SET/RESET |
| LED 常亮不闪 | `HAL_Delay` 卡死（SysTick 没配） | 检查 CubeMX 里 SYS 配置 |
| 程序下载后没跑 | 只下载没复位 | 按板子复位键，或 Keil 里勾 `Reset and Run` |

## A6 · 提交到个人仓库

**任务**：把 P01 工程提交到你**在 P00 建的那个个人仓库**里（放到 `projects/P01-环境搭建与第一个工程/src/`），并写好 `.gitignore` 排除编译产物。

### 知识点

**这是 P00 学到的流程的直接复用**。唯一的新内容是两条：

1. **单片机工程的编译产物特别多**，`.gitignore` 必须写好，否则仓库会被几百个中间文件塞满。
2. **一年只用同一个仓库**：所有项目都放到同一个仓库的 `projects/PXX-项目名/` 下面（与任务卡编号一致），不要每个项目新建一个仓库。

**Keil 工程的典型编译产物**（具体目录名以你本机实际工程树为准；CubeMX 生成的 MDK-ARM 工程常见为 `MDK-ARM/<工程名>/`，也可能出现 `Objects/`、`Listings/`）：

```
MDK-ARM/<工程名>/   ← 常见：.o .axf .hex .map 等构建输出
Objects/            ← 部分工程：.o .axf .hex .map
Listings/           ← .lst 列表文件
Debug/              ← 调试配置与产物
*.uvguix.*          ← Keil 的界面布局（每台机器不同，必须忽略）
```

### 操作步骤

**1. 把工程放进仓库的 `projects/` 目录**

在你 P00 建的仓库根目录下新建目录 `projects/P01-环境搭建与第一个工程/src/`，把 CubeMX 生成的**整个工程文件夹内容**（`.ioc`、`Core/`、`Drivers/`、`MDK-ARM/` 等全部）复制到 `src/` 里面。

目标结构：

```
你的仓库/
├── README.md
├── hello.txt
├── .gitignore
└── projects/
    └── P01-环境搭建与第一个工程/
        └── src/
            └── （CubeMX 工程的完整内容）
```

## B1 · 读懂时钟树

**任务**：在 CubeMX 的时钟树界面截图，逐项说明：外部晶振频率、PLL 倍频系数、最终 SYSCLK 频率各是多少。

### 知识点

**时钟树的链路**：

```
外部晶振 8MHz ──> /1 ──> PLL 输入 8MHz
                            │
                      ×9 倍频（PLLMul = X9）
                            │
                            v
                     PLL 输出 72MHz ──> SYSCLK = 72MHz
                                          │
                        ┌─────────────────┼─────────────────┐
                        v                 v                 v
                    AHB (72MHz)      APB1 (/2 = 36MHz)   APB2 (/1 = 72MHz)
                                     └→ 定时器时钟 72MHz  └→ USART1 时钟 72MHz
```

**几个关键点**：

| 概念 | 含义 |
|---|---|
| HSE | 外部高速晶振，F103 蓝板通常是 **8MHz** |
| PLL | 锁相环，负责倍频（把 8MHz 变 72MHz） |
| SYSCLK | 系统主时钟，F103 最高 **72MHz** |
| AHB / APB1 / APB2 | 三条总线，各自分频后给不同外设用 |
| **APB1 定时器时钟** | APB1 分频不为 1 时，**定时器时钟 = APB1 时钟 × 2**，默认配置下就是 72MHz（P05 会用到） |

### 操作步骤

1. CubeMX 里点顶部 **`Clock Configuration`**
2. 截图整个时钟树
3. 在 README 里逐项填写：

```markdown
## 时钟树配置说明

| 项 | 值 | 说明 |
|---|---|---|
| 外部晶振（HSE） | 8 MHz | 板载晶振频率 |
| PLL 输入分频 | /1 | HSE 直接进 PLL |
| PLL 倍频系数 | ×9 | 8 × 9 = 72 |
| SYSCLK | 72 MHz | 系统主时钟 |
| AHB 分频 | /1 | 72 MHz |
| APB1 分频 | /2 | 36 MHz（定时器 ×2 = 72 MHz） |
| APB2 分频 | /1 | 72 MHz |
```

### 验证方法

- 能说清 `8 × 9 = 72` 这条链
- 能解释"为什么 APB1 是 36MHz 但定时器时钟是 72MHz"
- 截图与实际配置一致

## B2 · printf 重定向打印开机信息

**任务**：重定向 `printf` 到串口，用 115200 波特率在串口助手上打印一行开机信息（含你的项目名与日期）。

### 操作步骤

**1. CubeMX 里启用串口**

左侧 `Connectivity` → `USART1` → `Mode` 选 **`Asynchronous`** → `Parameter Settings` 里 `Baud Rate` = **`115200`**（引脚 PA9/PA10 会自动变绿）→ 重新生成代码。

**2. Keil 里勾 MicroLIB**

`Options for Target` → `Target` 标签 → 勾 **`Use MicroLIB`**。勾它是为了**避免半主机（semihosting）链接问题、并减小代码体积**——不勾时若出现链接错误或串口没有输出，先回来检查这个勾选。

**3. 加代码**（在 `main.c` 的对应 USER CODE 区）

```c
/* USER CODE BEGIN Includes */
#include <stdio.h>
/* USER CODE END Includes */

/* USER CODE BEGIN 0 */
int fputc(int ch, FILE *f)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, 0xFFFF);
    return ch;
}
/* USER CODE END 0 */
```

**4. 主循环前打印开机信息**（`/* USER CODE BEGIN 2 */`）

```c
printf("\r\n=== P01_LED_Blink boot OK, 2026-09-20 ===\r\n");
```

**5. 接线与测试**

| 开发板 | USB 转串口模块 |
|---|---|
| PA9 (TX) | RX |
| PA10 (RX) | TX |
| GND | GND |

**装一个串口助手**：Windows 上常用 `SSCOM`、`XCOM`、`MobaXterm` 或 `PuTTY`，任选一个即可（本方案不绑定具体软件）。

**找到 COM 号**：`设备管理器` → **`端口 (COM 和 LPT)`** → 找到形如 `USB-SERIAL CH340 (COM5)` 的那一项，括号里的 `COM5` 就是你要选的端口（插拔模块时这一项会跟着出现/消失，可用来确认是它）。

打开串口助手 → 选这个 COM 号 → 波特率 **115200** → 打开串口 → 按板子复位键，应看到开机信息。

### 验证方法

- 串口助手收到完整一行开机信息，无乱码
- 按复位键能重复打印（说明初始化正常）
- 信息里含项目名与日期（任务要求）

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 全是乱码 | 波特率不一致，或系统时钟没配成 72MHz | 两端都设 115200；检查时钟树 |
| 完全没输出 | TX/RX 接反了 | 交换两根线（TX 接对方 RX） |
| 只输出几个字符 | 没勾 MicroLIB | 勾上 |
| 编译报错 | `FILE` 未定义 | 确认 `#include <stdio.h>` 加了 |

## B3 · 换引脚重新生成

**任务**：修改 CubeMX 配置，把 LED 换到另一个 GPIO 引脚上重新生成工程并点灯成功，说明 CubeMX 重新生成后哪些文件被覆盖了。

### 操作步骤

1. CubeMX 里，把 PC13 的 `GPIO_Output` 取消（右键引脚 → **`Reset_State`**）
2. 把 **PA5** 设成 `GPIO_Output`，`User Label` 填 **`LED`**
3. `GENERATE CODE` 重新生成
4. Keil 重新编译下载，LED 应在新的引脚上闪。**注意：蓝板只有 PC13 一个板载 LED**，换到 PA5 后**必须外接一颗 LED**（`PA5 → 1kΩ → LED 阳极 → LED 阴极 → GND`）才有现象；不接就没有任何可观察的变化。
5. 在 README 里写清"哪些被覆盖、哪些保留"：

```markdown
## CubeMX 重新生成的影响

| 文件 | 是否被覆盖 |
|---|---|
| `main.c` 的 `MX_GPIO_Init` 等初始化函数 | ✅ 被覆盖（按新配置重写） |
| `main.c` 里 USER CODE BEGIN/END 之间的代码 | ❌ 保留 |
| `main.h` 的引脚宏定义（`LED_Pin` 等） | ✅ 被覆盖（PC13 → PA5） |
| `Core/Inc/*.h`、`Core/Src/*.c` 的其他文件 | ✅ 按配置重新生成 |
| 你自己新建的文件（如 `key.c`） | ❌ 不受影响（CubeMX 不认识它们） |
```

### 验证方法

- 换引脚后 LED 在新引脚上正常闪
- 你之前写在 USER CODE 区的 printf 代码**还在**（没被覆盖）
- 能准确说出哪些被覆盖、哪些保留

## B4 · 画连接框图

**任务**：在 README 里画一个连接框图，标出「电脑 → 烧录器 → 单片机 → LED」之间的连线与供电关系。

### 知识点

**为什么要画这个**：它能让你在出问题时**知道去量哪根线**。"程序下载不进去"的时候，你就有了一张检查清单。

### 操作步骤

用 ASCII 或手绘，画清连线和供电：

```
┌──────────┐  USB   ┌──────────┐  SWDIO ──┐
│   电脑   │───────>│  ST-Link │  SWCLK ──┤
│ (Keil)   │        │  烧录器  │  GND ────┤
└──────────┘        └────┬─────┘          │
                         │ 3.3V           │
                         │                v
                         │        ┌───────────────┐
                         └───────>│ STM32F103C8T6 │
                            供电  │     最小系统板 │
                                  └───────┬───────┘
                                          │ PC13（低电平点亮）
                                          v
                                    ┌──────────┐
                                    │   LED    │
                                    │ (板载)   │
                                    └──────────┘
```

要点：

| 项 | 说明 |
|---|---|
| 电脑 → ST-Link | USB 线，供电 + 数据 |
| ST-Link → 板子 | SWDIO、SWCLK、GND（三线必需），3.3V 可选 |
| **共地** | 两边 GND 必须连，否则信号没有参考电平 |
| 板子 → LED | 通过 PC13 引脚，低电平点亮 |

### 验证方法

- 框图里有明确的连接关系（谁连谁、哪根线是什么信号）
- 标出了供电关系与共地
- 评审时能照着图指出"如果下载不了，先量哪两根线"
