### 0.1 为什么把 C 语言放在这里补

你在课堂上学过 C 语言的语法，但在单片机上写代码需要的**具体用法**和做题不一样。这个项目把最常用的六样东西——**数组、函数、结构体、位运算、指针、格式化输出**——用你能跑起来的 LED 程序串一遍。

**学完能干什么**：看懂别人写的驱动代码、把自己重复的代码收拾干净。

### 0.2 万用表的三个档位（B 档要用）

| 档位 | 符号 | 用途 |
|---|---|---|
| 直流电压 | `V⎓` 或 `V−` | 测电压（3.3V、5V） |

## A1 · 用数组做 8 种闪烁节奏

**任务**：用数组重写 LED 闪烁程序：把 8 个不同的延时值存进数组，主循环依次取用，让闪烁变成 8 种不同节奏。

### 知识点

**数组**：一串**同类型**的数据，用一个名字管理，用下标访问。

```c
uint16_t delays[8] = {100, 200, 300, 400, 500, 400, 300, 200};
/*         ^^^^^^^  数组名        ^^^ 下标 0              下标 7 ^^^ */
```

| 概念 | 说明 |
|---|---|
| 声明 | `类型 名字[元素个数]` |
| 初始化 | 用 `{ }` 列出所有值 |
| 访问 | `名字[下标]`，**下标从 0 开始** |
| 越界 | 访问 `delays[8]` 是错的（合法下标只有 0~7）|

**下标越界是嵌入式最常见的崩溃原因之一**——它不会报错，只会悄悄改坏别的变量。

### 操作步骤

在 `main.c` 的 `/* USER CODE BEGIN 0 */` 里定义：

```c
/* 8 种闪烁节奏：亮的时间（毫秒），灭的时间固定 200ms */
static const uint16_t on_time[8] = { 100, 200, 300, 400, 500, 600, 700, 800 };
#define ON_TIME_CNT   (sizeof(on_time) / sizeof(on_time[0]))   /* 自动算出 8 */
```

主循环（`/* USER CODE BEGIN WHILE */`）：

```c
uint8_t i = 0;
while (1)
{
    /* USER CODE BEGIN WHILE */
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);   /* 点亮 */
    HAL_Delay(on_time[i]);                                        /* 亮 i 号时长 */
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);     /* 熄灭 */
    HAL_Delay(200);

    i++;
    if (i >= ON_TIME_CNT) i = 0;      /* 循环回第 0 个 */
    /* USER CODE END WHILE */
}
```

**注意 `ON_TIME_CNT` 的写法**：`sizeof(数组)/sizeof(数组[0])` 能自动算出元素个数。以后往数组里加值不用改这个常量。

### 验证方法

- LED 亮的时间呈"渐长再重复"的变化：100 → 200 → … → 800 → 回到 100
- 用手机秒表粗测，最长的那一下约 0.8 秒
- 顺序无错乱、无跳过

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 节奏乱了/卡死 | 下标越界了 | 检查 `i >= ON_TIME_CNT` 判断 |
| 看着都一样 | 延时值差异太小 | 拉开差距（如 100/400/800） |
| 编译报 `sizeof` 警告 | 数组非 const 时算长度 | 加 `const` 或手写常量 |

## A2 · 把 LED 操作封装成函数

**任务**：把「点亮」「熄灭」「翻转」三种 LED 操作各封装成一个函数，主循环只调用函数，不直接写寄存器或 HAL 调用。

### 知识点

**为什么要封装**：

```c
/* 封装前：主循环里满是这样的一行 —— 读起来累，改起来到处改 */
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);

/* 封装后：主循环像说明书 */
led_on();
led_off();
led_toggle();
```

**好处**：① 读代码不用猜意图；② 换引脚只改函数内部一处；③ 名字本身就是注释。

**函数三要素**：返回类型、函数名、参数。这里不需要返回值和参数，写 `void`。

### 操作步骤

在 `/* USER CODE BEGIN 0 */` 里定义函数：

```c
/* LED 在 PC13，低电平点亮 —— 把"反逻辑"藏在函数里，外面只管 on/off */
static void led_on(void)
{
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
}

static void led_off(void)
{
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
}

static void led_toggle(void)
{
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
}
```

主循环改成调用它们：

```c
while (1)
{
    led_on();
    HAL_Delay(500);
    led_off();
    HAL_Delay(500);

    /* 顺便演示 toggle */
    led_toggle();
    HAL_Delay(100);
    led_toggle();
    HAL_Delay(100);
}
```

**`static` 的含义**：这个函数只在当前 `.c` 文件里可见。用在"内部辅助函数"上是个好习惯——避免和别的文件里的同名函数冲突。

### 验证方法

- 功能与 P01 一致（1Hz 闪烁）加上一段快速闪烁
- **主循环里搜不到 `HAL_GPIO_`**（全被封装进函数了）
- 能讲清"为什么把低电平点亮的反逻辑藏在 `led_on` 里"

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报重复定义 | 函数写在多个地方 | 只保留一份 |
| 编译警告未使用 | 定义了没调用 | 确保都调用了，或暂时删掉 |
| 逻辑反了 | 忘了 low=亮 | 改 `GPIO_PIN_RESET` / `GPIO_PIN_SET` |

## A3 · 用结构体描述 LED

**任务**：用一个结构体描述 LED 对象（成员含引脚号、当前状态），并为它写 `led_init` 与 `led_blink` 两个函数，在程序里实际用起来。

### 知识点

**结构体**：把**一组相关的、类型可以不同**的变量打包成一个新类型。

```c
typedef struct {
    GPIO_TypeDef *port;      /* 端口：GPIOA/GPIOC... */
    uint16_t      pin;       /* 引脚：GPIO_PIN_13 */
    uint8_t       state;     /* 当前状态：0=灭 1=亮 */
} led_t;
```

**为什么用结构体而不是零散变量**：将来你有 3 个 LED、4 个按键，用结构体就能"一份代码管多个对象"：

```c
led_t led1, led2;          /* 两个 LED，各有自己的引脚与状态 */
led_blink(&led1, 500);     /* 同一套逻辑，传不同对象 */
```

**`->` 与 `.` 的区别**：`led1.state`（对象本身用 `.`）、`p->state`（指针用 `->`）。两者等价于 `(*p).state`。

### 操作步骤

```c
/* USER CODE BEGIN 0 */
typedef struct {
    GPIO_TypeDef *port;
    uint16_t      pin;
    uint8_t       state;      /* 0=灭  1=亮 */
} led_t;

/* 初始化：记录引脚，并让 LED 熄灭 */
static void led_init(led_t *led, GPIO_TypeDef *port, uint16_t pin)
{
    led->port  = port;
    led->pin   = pin;
    led->state = 0;
    HAL_GPIO_WritePin(led->port, led->pin, GPIO_PIN_SET);   /* 灭 */
}

/* 按状态刷新输出 */
static void led_apply(led_t *led)
{
    /* 低电平点亮：state=1 → RESET(亮) */
    HAL_GPIO_WritePin(led->port, led->pin,
                      led->state ? GPIO_PIN_RESET : GPIO_PIN_SET);
}

/* 闪烁指定次数，每次 on/off 各 half_ms */
static void led_blink(led_t *led, uint16_t half_ms, uint8_t times)
{
    for (uint8_t k = 0; k < times; k++)
    {
        led->state = 1; led_apply(led); HAL_Delay(half_ms);
        led->state = 0; led_apply(led); HAL_Delay(half_ms);
    }
}
/* USER CODE END 0 */
```

主循环里用起来：

```c
led_t my_led;
led_init(&my_led, LED_GPIO_Port, LED_Pin);

while (1)
{
    led_blink(&my_led, 500, 2);    /* 慢闪 2 次 */
    HAL_Delay(500);
    led_blink(&my_led, 100, 5);    /* 快闪 5 次 */
    HAL_Delay(1000);
}
```

### 验证方法

- 程序能跑：慢闪 2 次 → 停 0.5s → 快闪 5 次 → 停 1s → 循环
- 能指出结构体的三个成员各自存什么
- 能解释 `&my_led` 为什么要取地址（函数要改对象本身，必须传地址）

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 编译报 `led_t` 未定义 | typedef 写在了使用之后 | 把 typedef 放到函数之上 |
| 传参报类型不匹配 | 传了 `my_led` 而不是 `&my_led` | 加 `&` |
| 灯逻辑反了 | `apply` 里条件写反 | 低电平点亮时 `state ? RESET : SET` |

## A4 · 四个位运算宏

**任务**：写出 `BIT_SET` / `BIT_CLEAR` / `BIT_TOGGLE` / `BIT_READ` 四个位运算宏，用它们管理一个**软件位标志字节**（如 `led_flags`），并用 `BIT_READ` 把 8 个位逐位读出来打印；再补充：用 `GPIOx->ODR`（或 `BSRR`）直写一次 LED，对比与 `HAL_GPIO_WritePin` 的效果差异。

### 知识点

**为什么要位运算**：单片机的一个寄存器有 32 位，每一位控制一个功能。要**只改其中一位、不动其他位**，就必须用位运算。

| 操作 | 运算符 | 记忆 |
|---|---|---|
| 置 1 | `\|=` | "或上 1 就是 1" |
| 清 0 | `&= ~` | "与上 0 才是 0"（**`~` 不能少**）|
| 翻转 | `^=` | "异或 1 翻转，异或 0 不变" |
| 读取 | `&` | "与 1 取出那一位" |

```c
reg |= (1 << n);        /* 第 n 位置 1 */
reg &= ~(1 << n);       /* 第 n 位清 0 */
reg ^= (1 << n);        /* 第 n 位翻转 */
bit = (reg >> n) & 1;   /* 读第 n 位 */
```

**⭐ 最容易错的一行**：清零必须写 `&= ~(1 << n)`。写成 `&= (1 << n)` 会把**除了第 n 位以外的所有位都清成 0**。

**宏为什么每个参数都要加括号**：

```c
#define SQ(x) x*x        /* ❌ SQ(1+2) 展开成 1+2*1+2 = 5，不是 9 */
#define SQ(x) ((x)*(x))  /* ✅ 展开成 ((1+2)*(1+2)) = 9 */
```

**⭐ 宏名不能叫 `SET_BIT` / `CLEAR_BIT` / `TOGGLE_BIT` / `READ_BIT`**：`stm32f1xx.h` 里已经有同名宏，而且 CMSIS 的 `READ_BIT(REG,BIT)` 第二个参数是**掩码**不是位号，语义完全不同。你重定义之后，HAL 内部用到它们的地方会被静默替换成你的版本——编译不报错，运行时出现极难查的错误。所以本教程统一用 `BIT_` 前缀。

### 操作步骤

**1. 定义四个宏**（`/* USER CODE BEGIN 0 */`）：

```c
/* USER CODE BEGIN 0 */
/* 位运算四件套：每个参数都要加括号！
 * 名字用 BIT_ 前缀，避开 stm32f1xx.h 里已有的 SET_BIT/CLEAR_BIT/READ_BIT。 */
#define BIT_SET(reg, n)      ((reg) |=  (1U << (n)))
#define BIT_CLEAR(reg, n)    ((reg) &= ~(1U << (n)))
#define BIT_TOGGLE(reg, n)   ((reg) ^=  (1U << (n)))
#define BIT_READ(reg, n)     (((reg) >> (n)) & 0x01U)
/* USER CODE END 0 */
```

**2. 先用宏管理一个软件位标志字节**（推荐的第一步——只操作纯软件变量，不碰硬件寄存器，绝不会踩坑）：

```c
/* 用一个字节管理 LED 状态，用宏操作 */
static uint8_t led_flags = 0;
#define LED_BIT   0            /* 位 0 表示 LED 状态 */

static void led_on_v2(void)     { BIT_SET(led_flags, LED_BIT);
                                  HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET); }
static void led_off_v2(void)    { BIT_CLEAR(led_flags, LED_BIT);
                                  HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET); }
static void led_toggle_v2(void) { BIT_TOGGLE(led_flags, LED_BIT);
                                  HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin); }
static uint8_t led_is_on(void)  { return BIT_READ(led_flags, LED_BIT); }

/* 把 led_flags 的 8 个位从高到低逐位打印出来
 * （printf 到串口的重定向在 A5 做；先把函数写出来，串口配好后再调用） */
static void led_flags_dump(void)
{
    printf("led_flags = 0x%02X -> ", (unsigned)led_flags);
    for (int8_t n = 7; n >= 0; n--)
    {
        printf("%u", (unsigned)BIT_READ(led_flags, n));
    }
    printf("\r\n");
}
```

> 用 `BIT_READ` 逐位打印还有一个好处：**你亲眼看到位 0 在 0/1 之间翻转**，而不是只相信"灯亮了"。

**3. 再补一次"直写寄存器"的对比**：用参数化的 `GPIO_TypeDef *port`（不要写死 `GPIOA` / `GPIOC`）：

```c
/* 直写 ODR：读-改-写，只动目标位 */
static void led_on_reg(GPIO_TypeDef *port, uint16_t pin)
{
    port->ODR &= ~(uint32_t)pin;      /* ODR 对应位清 0 → 输出低 → 点亮（低电平点亮） */
}

static void led_off_reg(GPIO_TypeDef *port, uint16_t pin)
{
    port->ODR |= (uint32_t)pin;       /* ODR 对应位置 1 → 输出高 → 熄灭 */
}

/* 调用：led_on_reg(LED_GPIO_Port, LED_Pin);  /  led_off_reg(LED_GPIO_Port, LED_Pin); */
```

**效果对比**（三种写法最终都是同一个引脚变电平，LED 现象完全一样，差异在代码层面）：

| | `HAL_GPIO_WritePin` | `port->ODR` 直写 | `port->BSRR` 直写 |
|---|---|---|---|
| 写法 | 一行函数调用 | `\|=` / `&=~`，读-改-写 | `port->BSRR = pin`（置高）/ `port->BSRR = (uint32_t)pin << 16`（拉低） |
| 速度 | 多一层函数调用 | 最快 | 快，且**一次写入、原子** |
| 风险 | 参数检查、不会误改其他位 | 读-改-写不是原子操作，误写掩码会连带改别的位 | 写错位会改到别的引脚 |
| 建议 | **业务代码首选** | 用来理解寄存器，对比用 | 看数据手册时对得上 |

> **结论**：HAL 内部其实也是去写 `BSRR`/`BRR`。自己直写能看清"位操作到底改了哪一位"，但少了参数检查，写错端口/引脚不会报错，只会在板子上表现为"灯不亮"。**先用 HAL 调通，再直写一次做对比。**

要求：**四个宏都被真实调用过**（能在源码里指出调用位置），并且 `led_flags_dump()` 打印形如 `led_flags = 0x01 -> 00000001`（LED 亮）和 `led_flags = 0x00 -> 00000000`（LED 灭）。

### 验证方法

- 功能与 A2 完全一致（同一套亮灭节奏）
- 4 个宏**都有实际调用**（不是只写在头文件里）
- `led_flags_dump()` 的输出与 LED 实际状态一致：位 0 与灯同步变化
- 能用一句话说出 ODR 直写与 `HAL_GPIO_WritePin` 的差异（HAL 内部写的也是 `BSRR`/`BRR`；直写少了函数调用和参数检查，但可读性差）
- 能回答："为什么清零要用 `&=~`？"（因为 `&=` 与 0 得 0、与 1 保持不变，所以要先把目标位取反）
- 能回答："宏参数为什么加括号？"（举例 `SQ(1+2)` 展开错误）

## A5 · 串口打印数组与结构体值

**任务**：用串口打印出上面用到的数组内容与结构体成员值，确认打印结果与预期一致。

### 操作步骤

先把 printf 重定向（若 P01 已做，跳过）：

```c
/* USER CODE BEGIN Includes */
#include <stdio.h>
/* USER CODE END Includes */

/* USER CODE BEGIN 0 */
int fputc(int ch, FILE *f)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, 0xFFFF);
    return ch;
}
/* USER CODE END 0 */
```

打印数组与结构体：

```c
/* 打印数组全部元素 */
printf("on_time[] = ");
for (uint8_t k = 0; k < ON_TIME_CNT; k++)
{
    printf("%u ", on_time[k]);          /* %u 打印 unsigned */
}
printf("(count=%u)\r\n", (unsigned)ON_TIME_CNT);

/* 打印结构体成员 */
printf("led: port=0x%08lX pin=0x%04X state=%u\r\n",
       (unsigned long)my_led.port, (unsigned)my_led.pin, (unsigned)my_led.state);
```

> **为什么不写 `%p`**：`%p` 在 MicroLIB 下的输出形式不可控（补不补 `0x`、几位、大写小写都可能不一样），不同工程间比对时对不上。打印地址统一把它转成 `unsigned long`，用 `0x%08lX`——**格式固定、宽度固定**。

预期输出：

```
on_time[] = 100 200 300 400 500 600 700 800 (count=8)
led: port=0x40011000 pin=0x2000 state=0
```

**格式符速查**：

| 符 | 用于 |
|---|---|
| `%d` | int（有符号） |
| `%u` | unsigned int |
| `%x` / `%02X` | 十六进制（`%02X` 补零、大写） |
| `%p` | 指针地址（MicroLIB 下格式不可控，建议转 `unsigned long` 用 `%08lX`） |
| `%s` | 字符串 |
| `%lu` | unsigned long |

### 验证方法

- 数组 8 个值全部打印，与源码里的初始化值**逐一吻合**
- 结构体的 `pin=0x2000` —— 验证一下：`GPIO_PIN_13` 就是 `(1<<13)` = 8192 = `0x2000` ✅
- 打印结果与你预期一致（这就是"确认与预期一致"的意思：不是随便能打出来就行，而是**值要对**）

## B1 · 串口格式化表格输出

**任务**：用 `printf` 输出一张格式化的表格：每秒打印一行，包含**运行秒数 / LED 状态 / 按键电平**，要求列对齐。

> 📌 本任务**只做输出**，不做接收和命令解析——串口接收、缓冲区、命令表单在 **P06** 才学。P02 在第 3~4 周，那时你还没学过怎么收数据，先把"把数据排成好看的表格"这一件事练熟。

### 知识点

**1. 固定宽度 = 列对齐**

`printf` 的格式串里可以在 `%` 和转换符之间加宽度：

| 写法 | 含义 | 例子 |
|---|---|---|
| `%6lu` | 右对齐、宽 6 | `     7` |
| `%-3s` | 左对齐、宽 3 | `ON ` |
| `%02X` | 十六进制、2 位、补零 | `0A` |

列对齐的关键：**表头和每一行用同样的宽度**，再用 `|` 分隔，打印出来就是一张表。

**2. 怎么得到"运行秒数"**：`HAL_GetTick()` 返回上电以来的毫秒数，`HAL_GetTick() / 1000` 就是秒。不要用 `HAL_Delay(1000)` 去"数秒"——`HAL_Delay` 会阻塞，表格会卡在打印那一行。

**3. 为什么不在中断里打印**：`printf` 是逐字符阻塞发送，一行二十来个字符在 115200 下要 1~2ms；放进中断会拖慢甚至打乱整个系统。**打印永远放主循环。**

### 操作步骤

**1. （可选）把 PA0 配成按键输入**

如果板子上有按键接在 PA0（按下为高电平）：CubeMX → 点 `PA0` → 选 `GPIO_Input` → `GPIO Pull-up/Pull-down` 选 `Pull-down`。没有按键也没关系，这一列会一直打印 `0`，不影响表格练习。

**2. 写代码**（`main.c` 的 USER CODE 区）

```c
/* USER CODE BEGIN Includes */
#include <stdio.h>
/* USER CODE END Includes */

/* USER CODE BEGIN 0 */
static uint32_t s_last_print  = 0;      /* 上次打印表格的时刻（ms） */
static uint32_t s_last_toggle = 0;      /* 上次翻转 LED 的时刻（ms） */

/* 表头：只打印一次。宽度必须和下面的数据行一致 */
static void table_header(void)
{
    printf("| %6s | %-3s | %-3s |\r\n", "sec", "LED", "KEY");
    printf("|--------|-----|-----|\r\n");
}

/* 数据行：运行秒数 / LED 状态 / 按键电平 */
static void table_row(uint32_t sec, const char *led, uint8_t key)
{
    printf("| %6lu | %-3s | %-3u |\r\n",
           (unsigned long)sec, led, (unsigned)key);
}

/* LED 是否亮：PC13 低电平点亮，所以读回 RESET 表示亮 */
static uint8_t led_is_on(void)
{
    return (HAL_GPIO_ReadPin(LED_GPIO_Port, LED_Pin) == GPIO_PIN_RESET) ? 1 : 0;
}
/* USER CODE END 0 */
```

**3. 主循环**：

```c
/* USER CODE BEGIN 2 */
table_header();
/* USER CODE END 2 */

while (1)
{
    /* USER CODE BEGIN WHILE */
    uint32_t now = HAL_GetTick();

    /* 每 500ms 翻转一次 LED：用 A2 封装好的 led_toggle() */
    if (now - s_last_toggle >= 500)
    {
        s_last_toggle = now;
        led_toggle();
    }

    /* 每 1000ms 打印一行表格 */
    if (now - s_last_print >= 1000)
    {
        s_last_print = now;

        uint8_t key = (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_SET) ? 1 : 0;
        table_row(now / 1000, led_is_on() ? "ON" : "OFF", key);
    }
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    /* USER CODE END 3 */
}
```

**预期输出**：

```
|    sec | LED | KEY |
|--------|-----|-----|
|      1 | ON  | 0   |
|      2 | OFF | 0   |
|      3 | ON  | 0   |
|      4 | OFF | 1   |
```

竖线对齐、每行宽度一致；LED 列在 `ON`/`OFF` 之间交替，KEY 列随按键变化。

### 验证方法

- 串口助手（115200、UTF-8）每秒收到一行，列与列之间竖线对齐、不抖动
- 运行秒数逐行 +1，与串口助手记录的时间能对上
- LED 列随 LED 实际亮灭在 `ON` / `OFF` 之间变化
- 按住按键时 KEY 列从 0 变 1（没接按键则恒为 0，可接受）
- 连续看 10 行无错位、无乱码

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 所有行挤在一行 | 只写了 `\n` | 改成 `\r\n` |
| 列对不齐 | 表头和数据行的宽度不一致 | 两处用同一组 `%6s`/`%6lu`、`%-3s` |
| 打印一行要很久、LED 卡顿 | 行太长，`printf` 逐字节阻塞发送 | 缩短行宽、降低打印频率，别在中断里 printf |
| 秒数不涨 | `s_last_print` 没初始化或被重复初始化 | 用 `static` 全局变量，只在定义处赋初值 |
| KEY 列一直是 0 | PA0 没配成输入，或按键没接 | 检查 CubeMX 的 PA0 配置 |

### ⏭ 附：串口命令表单（这段到 P06 再学）

> 下面是原 B1 的"收命令 → 解析 → 执行"代码。它需要**串口接收、缓冲区、状态机**这些前置知识，**P06 才教**。现在不用做、也不用逐行看懂；等做完 P06 的 A1/A4 再回来，这段会变得很直观。**P02 的验收只要求上面的表格输出。**

知识点（先扫一眼即可）：字符串比较用 `strcmp`，相等时返回 0：

```c
if (strcmp(cmd, "led_on") == 0) { ... }    /* 相等时返回 0！ */
```

**⚠️ 常见错误**：`if (cmd == "led_on")` —— 这在 C 里比较的是**指针地址**，永远不相等。必须用 `strcmp`。

**缓冲区积累与整行处理**：串口一个字节一个字节来，要**先攒成一行**（遇到回车符 `\n` 或 `\r` 才算一行结束），再整行比对。不能收到一个字符就比对。

```c
/* USER CODE BEGIN 0 */
#include <string.h>
#include <stdlib.h>      /* atoi 需要它 */

/* 处理一行命令 */
static void handle_line(char *line)
{
    if (strcmp(line, "led_on") == 0)
    {
        led_on_v2();
        printf("OK: led_on\r\n");
    }
    else if (strcmp(line, "led_off") == 0)
    {
        led_off_v2();
        printf("OK: led_off\r\n");
    }
    else if (strncmp(line, "blink ", 6) == 0)        /* 前缀匹配 */
    {
        int n = atoi(line + 6);                       /* 从第 6 个字符开始取数字 */
        if (n > 0 && n <= 20)
        {
            led_blink(&my_led, 200, (uint8_t)n);
            printf("OK: blink %d\r\n", n);
        }
        else
        {
            printf("ERR: blink 次数需在 1~20\r\n");
        }
    }
    else
    {
        printf("ERR: 未知命令 \"%s\"（支持 led_on / led_off / blink N）\r\n", line);
    }
}
/* USER CODE END 0 */
```

主循环里收行（**P06 之前不要照抄进工程**）：

```c
static char    line_buf[32];
static uint8_t line_len = 0;
uint8_t rx;

while (1)
{
    if (HAL_UART_Receive(&huart1, &rx, 1, 10) == HAL_OK)
    {
        if (rx == '\n' || rx == '\r')          /* 回车 = 一行结束 */
        {
            if (line_len > 0)
            {
                line_buf[line_len] = '\0';     /* 字符串结尾必须补 0 */
                handle_line(line_buf);
                line_len = 0;
            }
        }
        else if (line_len < sizeof(line_buf) - 1)
        {
            line_buf[line_len++] = rx;
        }
        /* 超长时丢弃多余字符，防止溢出 */
    }
}
```

只要记住一句：**接收和命令解析是 P06 的内容**；P02 用 `printf` 把数据排成表格就够了。

## B2 · 指针求平均值

**任务**：写一个求平均值的函数，参数用指针接收数组，计算并返回平均值，在串口上打印结果。

### 知识点

**数组名传给函数时，实际传的是首地址**：

```c
float average(const uint16_t *arr, uint8_t len);
/*                 ^^^^^^^^^^^^ 指针：指向数组第一个元素 */
```

**两种访问写法等价**：

| 写法 | 含义 |
|---|---|
| `arr[i]` | 下标访问（推荐，好读） |
| `*(arr + i)` | 指针运算（等价，理解原理用） |

**`const` 的含义**：承诺"我不会改你传进来的数据"。加上它可以让调用方放心。

**⚠️ 指针本身不知道数组有多长**——所以必须**同时传长度**。这是新手最容易漏的一点。

### 操作步骤

```c
/* USER CODE BEGIN 0 */
static float average(const uint16_t *arr, uint8_t len)
{
    if (arr == NULL || len == 0) return 0.0f;   /* 防御性检查 */

    uint32_t sum = 0;                           /* 用 32 位防溢出 */
    for (uint8_t i = 0; i < len; i++)
    {
        sum += arr[i];
    }
    return (float)sum / (float)len;
}
/* USER CODE END 0 */
```

调用并打印：

```c
float avg = average(on_time, ON_TIME_CNT);
printf("average = %.2f ms (count=%u)\r\n", avg, (unsigned)ON_TIME_CNT);
```

用数组 `{100,200,300,400,500,600,700,800}` 手算验证：`sum = 3600`，`平均 = 3600/8 = 450.00`。

> **⭐ 格式串里的转换符个数必须与实参个数严格相等**，少一个就会从栈上读垃圾值——这也是串口打印出莫名其妙数字的常见原因。上面的 `%.2f` 对应 `avg`、`%u` 对应 `(unsigned)ON_TIME_CNT`，正好两个。

### 验证方法

- 打印出的平均值与手算一致（450.00）
- 能把同一个函数用在另一个数组上（证明它是通用的）
- 能讲清"为什么必须传长度，不能只传指针"
- 能讲清"为什么 `sum` 用 `uint32_t` 而不是 `uint16_t`"（8 个 800 加起来是 3600，`uint16_t` 上限 65535 勉强够，但如果数组更大就会溢出——养成用宽类型的习惯）

## B4 · 万用表测电阻

两种做法：

| 做法 | 说明 | 精度 |
|---|---|---|
| **拆下来测** | 焊下电阻单独测 | 准 |

3. **先短接两支表笔**，读数应接近 0 —— 这一步是确认表和表笔正常
4. 找板子上对应的电阻（用位号丝印定位），表笔分别接触电阻两端
5. 记录

| 项 | 值 |
|---|---|
| 电阻位号 | ____ |
| 原理图标称值 | ____ Ω |
| 实测值（在路） | ____ Ω |
| 偏差 | ____% |
| 是否偏小（并联导致） | 是/否 |

### 验证方法

- 有实测记录，且与标称值做了对比
- 能解释"为什么在路测可能偏小"

## B5 · 万用表通断档

**任务**：用万用表的通断档，验证一条杜邦线从一端到另一端是通的、两根不相干的线之间是不通的，记录测试结果。

### 知识点

**通断档怎么工作**：给测点之间加一个小电流，如果电阻很小（通常 <50Ω），表就"滴滴"响——表示**导通**。

**这是排查硬件最常用的功能**：

- 查杜邦线好坏
- 查虚焊（该通的不通）
- 查短路（不该通的通了）

### 操作步骤

1. 万用表旋钮转到**通断档**（二极管符号或声波符号那一档）
2. **自检**：两支表笔直接碰在一起 → 应该"滴"响，读数接近 0
3. **测杜邦线**：一支表笔接触线的一端（金属部分）、另一支接触另一端

| 测试 | 预期 | 实测 |
|---|---|---|
| 表笔互碰（自检） | 滴响 | ✅/❌ |
| 杜邦线一端 ↔ 同一条线另一端 | **滴响（通）** | ✅/❌ |
| 杜邦线 A ↔ 另一条杜邦线 B | **不响（不通）** | ✅/❌ |
| 两条线相邻但不接触的金属部分 | 不响 | ✅/❌ |

> **最重要的一条经验**：**测"不该通"的时候才最能发现问题**。只测"该通的通不通"会漏掉短路。

### 验证方法

- 自检能响（证明量程正常）
- 同一条线两端能响
- 两根不同的线之间不响
- 有完整的测试记录表

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 自检都不响 | 档位选错，或表笔插孔错 | 确认是通断档、红笔在 VΩ 孔 |
| 该通的不响 | 线内部断了 | 这是**发现坏线**了，换一条 |
| 不该通的也响 | 两条线的金属部分碰在一起了 | 分开线头再测 |
