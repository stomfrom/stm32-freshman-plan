## A1 · 用数组做 8 种闪烁节奏

**任务**：用数组重写 LED 闪烁程序：把 8 个不同的延时值存进数组，主循环依次取用，让闪烁变成 8 种不同节奏。

### 知识点

**数组**：一串**同类型**的数据，用一个名字管理，用下标访问。

```c
uint16_t delays[8] = {100, 200, 300, 400, 500, 400, 300, 200};
/*         ^^^^^^^  数组名        ^^^ 下标 0              下标 7 ^^^ */
```

| 概念 | 说明 |
|---|---|
| 声明 | `类型 名字[元素个数]` |
| 初始化 | 用 `{ }` 列出所有值 |
| 访问 | `名字[下标]`，**下标从 0 开始** |
| 越界 | 访问 `delays[8]` 是错的（合法下标只有 0~7）|

**下标越界是嵌入式最常见的崩溃原因之一**——它不会报错，只会悄悄改坏别的变量。

### 操作步骤

在 `main.c` 的 `/* USER CODE BEGIN 0 */` 里定义：

```c
/* 8 种闪烁节奏：亮的时间（毫秒），灭的时间固定 200ms */
static const uint16_t on_time[8] = { 100, 200, 300, 400, 500, 600, 700, 800 };
#define ON_TIME_CNT   (sizeof(on_time) / sizeof(on_time[0]))   /* 自动算出 8 */
```

主循环（`/* USER CODE BEGIN WHILE */`）：

```c
uint8_t i = 0;
while (1)
{
    /* USER CODE BEGIN WHILE */
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);   /* 点亮 */
    HAL_Delay(on_time[i]);                                        /* 亮 i 号时长 */
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);     /* 熄灭 */
    HAL_Delay(200);

    i++;
    if (i >= ON_TIME_CNT) i = 0;      /* 循环回第 0 个 */
    /* USER CODE END WHILE */
}
```

**注意 `ON_TIME_CNT` 的写法**：`sizeof(数组)/sizeof(数组[0])` 能自动算出元素个数。以后往数组里加值不用改这个常量。

### 验证方法

- LED 亮的时间呈"渐长再重复"的变化：100 → 200 → … → 800 → 回到 100
- 用手机秒表粗测，最长的那一下约 0.8 秒
- 顺序无错乱、无跳过

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 节奏乱了/卡死 | 下标越界了 | 检查 `i >= ON_TIME_CNT` 判断 |
| 看着都一样 | 延时值差异太小 | 拉开差距（如 100/400/800） |
| 编译报 `sizeof` 警告 | 数组非 const 时算长度 | 加 `const` 或手写常量 |

## A2 · 把 LED 操作封装成函数

**任务**：把「点亮」「熄灭」「翻转」三种 LED 操作各封装成一个函数，主循环只调用函数，不直接写寄存器或 HAL 调用。

### 知识点

**为什么要封装**：

```c
/* 封装前：主循环里满是这样的一行 —— 读起来累，改起来到处改 */
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);

/* 封装后：主循环像说明书 */
led_on();
led_off();
led_toggle();
```

**好处**：① 读代码不用猜意图；② 换引脚只改函数内部一处；③ 名字本身就是注释。

**函数三要素**：返回类型、函数名、参数。这里不需要返回值和参数，写 `void`。

### 操作步骤

在 `/* USER CODE BEGIN 0 */` 里定义函数：

```c
/* LED 在 PC13，低电平点亮 —— 把"反逻辑"藏在函数里，外面只管 on/off */
static void led_on(void)
{
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
}

static void led_off(void)
{
    HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET);
}

static void led_toggle(void)
{
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
}
```

主循环改成调用它们：

```c
while (1)
{
    led_on();
    HAL_Delay(500);
    led_off();
    HAL_Delay(500);

    /* 顺便演示 toggle */
    led_toggle();
    HAL_Delay(100);
    led_toggle();
    HAL_Delay(100);
}
```

**`static` 的含义**：这个函数只在当前 `.c` 文件里可见。用在"内部辅助函数"上是个好习惯——避免和别的文件里的同名函数冲突。

### 验证方法

- 功能与 P01 一致（1Hz 闪烁）加上一段快速闪烁
- **主循环里搜不到 `HAL_GPIO_`**（全被封装进函数了）
- 能讲清"为什么把低电平点亮的反逻辑藏在 `led_on` 里"

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报重复定义 | 函数写在多个地方 | 只保留一份 |
| 编译警告未使用 | 定义了没调用 | 确保都调用了，或暂时删掉 |
| 逻辑反了 | 忘了 low=亮 | 改 `GPIO_PIN_RESET` / `GPIO_PIN_SET` |

## A3 · 用结构体描述 LED

**任务**：用一个结构体描述 LED 对象（成员含引脚号、当前状态），并为它写 `led_init` 与 `led_blink` 两个函数，在程序里实际用起来。

### 知识点

**结构体**：把**一组相关的、类型可以不同**的变量打包成一个新类型。

```c
typedef struct {
    GPIO_TypeDef *port;      /* 端口：GPIOA/GPIOC... */
    uint16_t      pin;       /* 引脚：GPIO_PIN_13 */
    uint8_t       state;     /* 当前状态：0=灭 1=亮 */
} led_t;
```

**为什么用结构体而不是零散变量**：将来你有 3 个 LED、4 个按键，用结构体就能"一份代码管多个对象"：

```c
led_t led1, led2;          /* 两个 LED，各有自己的引脚与状态 */
led_blink(&led1, 500);     /* 同一套逻辑，传不同对象 */
```

**`->` 与 `.` 的区别**：`led1.state`（对象本身用 `.`）、`p->state`（指针用 `->`）。两者等价于 `(*p).state`。

### 操作步骤

```c
/* USER CODE BEGIN 0 */
typedef struct {
    GPIO_TypeDef *port;
    uint16_t      pin;
    uint8_t       state;      /* 0=灭  1=亮 */
} led_t;

/* 初始化：记录引脚，并让 LED 熄灭 */
static void led_init(led_t *led, GPIO_TypeDef *port, uint16_t pin)
{
    led->port  = port;
    led->pin   = pin;
    led->state = 0;
    HAL_GPIO_WritePin(led->port, led->pin, GPIO_PIN_SET);   /* 灭 */
}

/* 按状态刷新输出 */
static void led_apply(led_t *led)
{
    /* 低电平点亮：state=1 → RESET(亮) */
    HAL_GPIO_WritePin(led->port, led->pin,
                      led->state ? GPIO_PIN_RESET : GPIO_PIN_SET);
}

/* 闪烁指定次数，每次 on/off 各 half_ms */
static void led_blink(led_t *led, uint16_t half_ms, uint8_t times)
{
    for (uint8_t k = 0; k < times; k++)
    {
        led->state = 1; led_apply(led); HAL_Delay(half_ms);
        led->state = 0; led_apply(led); HAL_Delay(half_ms);
    }
}
/* USER CODE END 0 */
```

主循环里用起来：

```c
led_t my_led;
led_init(&my_led, LED_GPIO_Port, LED_Pin);

while (1)
{
    led_blink(&my_led, 500, 2);    /* 慢闪 2 次 */
    HAL_Delay(500);
    led_blink(&my_led, 100, 5);    /* 快闪 5 次 */
    HAL_Delay(1000);
}
```

### 验证方法

- 程序能跑：慢闪 2 次 → 停 0.5s → 快闪 5 次 → 停 1s → 循环
- 能指出结构体的三个成员各自存什么
- 能解释 `&my_led` 为什么要取地址（函数要改对象本身，必须传地址）

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 编译报 `led_t` 未定义 | typedef 写在了使用之后 | 把 typedef 放到函数之上 |
| 传参报类型不匹配 | 传了 `my_led` 而不是 `&my_led` | 加 `&` |
| 灯逻辑反了 | `apply` 里条件写反 | 低电平点亮时 `state ? RESET : SET` |

## A4 · 四个位运算宏

**任务**：写出 `SET_BIT` / `CLEAR_BIT` / `TOGGLE_BIT` / `READ_BIT` 四个位运算宏，并用这 4 个宏改写任务 2 的三个函数，确认功能不变。

### 知识点

**为什么要位运算**：单片机的一个寄存器有 32 位，每一位控制一个功能。要**只改其中一位、不动其他位**，就必须用位运算。

| 操作 | 运算符 | 记忆 |
|---|---|---|
| 置 1 | `\|=` | "或上 1 就是 1" |
| 清 0 | `&= ~` | "与上 0 才是 0"（**`~` 不能少**）|
| 翻转 | `^=` | "异或 1 翻转，异或 0 不变" |
| 读取 | `&` | "与 1 取出那一位" |

```c
reg |= (1 << n);        /* 第 n 位置 1 */
reg &= ~(1 << n);       /* 第 n 位清 0 */
reg ^= (1 << n);        /* 第 n 位翻转 */
bit = (reg >> n) & 1;   /* 读第 n 位 */
```

**⭐ 最容易错的一行**：清零必须写 `&= ~(1 << n)`。写成 `&= (1 << n)` 会把**除了第 n 位以外的所有位都清成 0**。

**宏为什么每个参数都要加括号**：

```c
#define SQ(x) x*x        /* ❌ SQ(1+2) 展开成 1+2*1+2 = 5，不是 9 */
#define SQ(x) ((x)*(x))  /* ✅ 展开成 ((1+2)*(1+2)) = 9 */
```

### 操作步骤

```c
/* USER CODE BEGIN 0 */
/* 位运算四件套：每个参数都要加括号！ */
#define BIT_SET(reg, n)      ((reg) |=  (1U << (n)))
#define BIT_CLEAR(reg, n)    ((reg) &= ~(1U << (n)))
#define BIT_TOGGLE(reg, n)   ((reg) ^=  (1U << (n)))
#define BIT_READ(reg, n)     (((reg) >> (n)) & 0x01U)
/* USER CODE END 0 */
```

**注意**：这四个宏操作的是"一个数值"，不是 HAL 的引脚。所以这个任务要**直接操作 GPIO 的 ODR 寄存器**才用得上前三个：

```c
/* 用位运算宏改写 A2 的三个函数（PC13 是 GPIOC 的第 13 位） */
#define LED_PORT_BASE   GPIOA_BASE   /* 若 LED 在 PC13，用 GPIOC_BASE；这里演示通用写法 */
```

> 更简单的做法（也是推荐做法）：宏用在**你自己定义的位标志**上，而不是直接操作硬件寄存器——这样既能练位运算，又不会踩寄存器的坑：

```c
/* 用一个字节管理 LED 状态，用宏操作 */
static uint8_t led_flags = 0;
#define LED_BIT   0            /* 位 0 表示 LED 状态 */

static void led_on_v2(void)     { BIT_SET(led_flags, LED_BIT);
                                  HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET); }
static void led_off_v2(void)    { BIT_CLEAR(led_flags, LED_BIT);
                                  HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_SET); }
static void led_toggle_v2(void) { BIT_TOGGLE(led_flags, LED_BIT);
                                  HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin); }
static uint8_t led_is_on(void)  { return BIT_READ(led_flags, LED_BIT); }
```

要求：**四个宏都被真实调用过**（能在源码里指出调用位置）。

### 验证方法

- 功能与 A2 完全一致
- 4 个宏**都有实际调用**（不是只写在头文件里）
- 能回答："为什么清零要用 `&=~`？"（因为 `&=` 与 0 得 0、与 1 保持不变，所以要先把目标位取反）
- 能回答："宏参数为什么加括号？"（举例 `SQ(1+2)` 展开错误）

## A5 · 串口打印数组与结构体值

**任务**：用串口打印出上面用到的数组内容与结构体成员值，确认打印结果与预期一致。

### 操作步骤

先把 printf 重定向（若 P01 已做，跳过）：

```c
/* USER CODE BEGIN Includes */
#include <stdio.h>
/* USER CODE END Includes */

/* USER CODE BEGIN 0 */
int fputc(int ch, FILE *f)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, 0xFFFF);
    return ch;
}
/* USER CODE END 0 */
```

打印数组与结构体：

```c
/* 打印数组全部元素 */
printf("on_time[] = ");
for (uint8_t k = 0; k < ON_TIME_CNT; k++)
{
    printf("%u ", on_time[k]);          /* %u 打印 unsigned */
}
printf("(count=%u)\r\n", (unsigned)ON_TIME_CNT);

/* 打印结构体成员 */
printf("led: port=%p pin=0x%04X state=%u\r\n",
       (void *)my_led.port, my_led.pin, my_led.state);
```

预期输出：

```
on_time[] = 100 200 300 400 500 600 700 800 (count=8)
led: port=0x40011000 pin=0x2000 state=0
```

**格式符速查**：

| 符 | 用于 |
|---|---|
| `%d` | int（有符号） |
| `%u` | unsigned int |
| `%x` / `%02X` | 十六进制（`%02X` 补零、大写） |
| `%p` | 指针地址 |
| `%s` | 字符串 |
| `%lu` | unsigned long |

### 验证方法

- 数组 8 个值全部打印，与源码里的初始化值**逐一吻合**
- 结构体的 `pin=0x2000` —— 验证一下：`GPIO_PIN_13` 就是 `(1<<13)` = 8192 = `0x2000` ✅
- 打印结果与你预期一致（这就是"确认与预期一致"的意思：不是随便能打出来就行，而是**值要对**）

## B1 · 串口命令表单

**任务**：在串口上做一个简单命令表单：收到 `led_on` 就点亮、`led_off` 就熄灭、`blink 5` 就闪 5 次，不认识的命令回一行提示。

### 知识点

**字符串比较用 `strcmp`**：

```c
if (strcmp(cmd, "led_on") == 0) { ... }    /* 相等时返回 0！ */
```

**⚠️ 常见错误**：`if (cmd == "led_on")` —— 这在 C 里比较的是**指针地址**，永远不相等。必须用 `strcmp`。

**缓冲区积累与整行处理**：串口一个字节一个字节来，要**先攒成一行**（遇到回车符 `\n` 或 `\r` 才算一行结束），再整行比对。不能收到一个字符就比对。

### 操作步骤

```c
/* USER CODE BEGIN 0 */
#include <string.h>

/* 处理一行命令 */
static void handle_line(char *line)
{
    if (strcmp(line, "led_on") == 0)
    {
        led_on_v2();
        printf("OK: led_on\r\n");
    }
    else if (strcmp(line, "led_off") == 0)
    {
        led_off_v2();
        printf("OK: led_off\r\n");
    }
    else if (strncmp(line, "blink ", 6) == 0)        /* 前缀匹配 */
    {
        int n = atoi(line + 6);                       /* 从第 6 个字符开始取数字 */
        if (n > 0 && n <= 20)
        {
            led_blink(&my_led, 200, (uint8_t)n);
            printf("OK: blink %d\r\n", n);
        }
        else
        {
            printf("ERR: blink 次数需在 1~20\r\n");
        }
    }
    else
    {
        printf("ERR: 未知命令 \"%s\"（支持 led_on / led_off / blink N）\r\n", line);
    }
}
/* USER CODE END 0 */
```

主循环里收行：

```c
static char    line_buf[32];
static uint8_t line_len = 0;
uint8_t rx;

while (1)
{
    if (HAL_UART_Receive(&huart1, &rx, 1, 10) == HAL_OK)
    {
        if (rx == '\n' || rx == '\r')          /* 回车 = 一行结束 */
        {
            if (line_len > 0)
            {
                line_buf[line_len] = '\0';     /* 字符串结尾必须补 0 */
                handle_line(line_buf);
                line_len = 0;
            }
        }
        else if (line_len < sizeof(line_buf) - 1)
        {
            line_buf[line_len++] = rx;
        }
        /* 超长时丢弃多余字符，防止溢出 */
    }
}
```

### 验证方法

- 串口助手（**勾选"发送新行"**，否则收不到回车符）发 `led_on` → LED 亮 + 回 `OK`
- 发 `blink 5` → 闪 5 次 + 回 `OK: blink 5`
- 发 `blink abc` 或 `xxxxx` → 回 `ERR: ...`，程序不卡死
- 连续测试 5 条以上命令都正确

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 命令没反应 | 串口助手没勾"发送新行" | 勾上（要发 `\r\n`） |
| 比较永远不相等 | 用了 `==` 而不是 `strcmp` | 改用 `strcmp(...) == 0` |
| 打印乱码/后面带垃圾 | 忘了补 `'\0'` | `line_buf[line_len] = '\0'` |
| 输入超长导致死机 | 缓冲区溢出 | 加长度限制（上面已加） |
| `atoi` 报未定义 | 没包含头文件 | `#include <stdlib.h>` |

## B2 · 指针求平均值

**任务**：写一个求平均值的函数，参数用指针接收数组，计算并返回平均值，在串口上打印结果。

### 知识点

**数组名传给函数时，实际传的是首地址**：

```c
float average(const uint16_t *arr, uint8_t len);
/*                 ^^^^^^^^^^^^ 指针：指向数组第一个元素 */
```

**两种访问写法等价**：

| 写法 | 含义 |
|---|---|
| `arr[i]` | 下标访问（推荐，好读） |
| `*(arr + i)` | 指针运算（等价，理解原理用） |

**`const` 的含义**：承诺"我不会改你传进来的数据"。加上它可以让调用方放心。

**⚠️ 指针本身不知道数组有多长**——所以必须**同时传长度**。这是新手最容易漏的一点。

### 操作步骤

```c
/* USER CODE BEGIN 0 */
static float average(const uint16_t *arr, uint8_t len)
{
    if (arr == NULL || len == 0) return 0.0f;   /* 防御性检查 */

    uint32_t sum = 0;                           /* 用 32 位防溢出 */
    for (uint8_t i = 0; i < len; i++)
    {
        sum += arr[i];
    }
    return (float)sum / (float)len;
}
/* USER CODE END 0 */
```

调用并打印：

```c
float avg = average(on_time, ON_TIME_CNT);
printf("average = %.2f ms  (sum=%u, count=%u)\r\n",
       avg, /* 可另算 sum */ (unsigned)ON_TIME_CNT);
```

用数组 `{100,200,300,400,500,600,700,800}` 手算验证：`sum = 3600`，`平均 = 3600/8 = 450.00`。

### 验证方法

- 打印出的平均值与手算一致（450.00）
- 能把同一个函数用在另一个数组上（证明它是通用的）
- 能讲清"为什么必须传长度，不能只传指针"
- 能讲清"为什么 `sum` 用 `uint32_t` 而不是 `uint16_t`"（8 个 800 加起来是 3600，`uint16_t` 上限 65535 勉强够，但如果数组更大就会溢出——养成用宽类型的习惯）

## B3 · 万用表测电压

**任务**：用万用表的直流电压档，实测开发板上 3.3V 与 5V 引脚的实际电压，记录两组读数。

### 知识点

**测量步骤的顺序很重要**：先选对档位和插孔，再接触测点。档位选错可能烧表。

**为什么实测值不会正好是 3.30V**：电源有纹波、万用表有精度误差、负载会影响输出。实测 3.25~3.35V 都是正常的。

### 操作步骤

1. 万用表旋钮转到 **`V⎓ 20V`** 档（或 `V−`，量程选 20V 那档）
2. 表笔插孔确认：黑笔 **COM**、红笔 **VΩ**
3. 把**黑表笔**接触板子的 **GND** 引脚，**红表笔**接触 **3.3V** 引脚
4. 读稳定后的数值，记录
5. 同样方法测 **5V** 引脚

| 测量点 | 标注值 | 实测值 | 偏差 | 是否在 ±5% 内 |
|---|---|---|---|---|
| 3.3V 引脚 | 3.30 V | ____ V | ____% | ✅/❌ |
| 5V 引脚（USB 供） | 5.00 V | ____ V | ____% | ✅/❌ |

> **若板子上没有 5V 引脚**：可以直接测 USB 口的 VBUS 或标注 `5V` 的排针。

### 验证方法

- 两组读数都有记录
- 3.3V 实测在 3.14~3.47V 之间（±5%）
- 若超出范围，能在 README 里给出至少一种可能原因（如 USB 线压降、板上 LDO 负载、万用表精度）

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 读数为 0 | 表笔没接触好，或黑笔没接 GND | 重新接触，确认接地 |
| 读数一直是 1 或显示 OL | 档位选得太小（超量程） | 换更大量程 |
| 读数为负 | 表笔接反了 | 交换表笔（或忽略符号） |
| 读数乱跳 | 接触不良 | 换测点，或用手压稳 |

## B4 · 万用表测电阻

**任务**：用万用表的电阻档测出板载 LED 限流电阻的阻值，与开发板原理图上标注的值对比，记录偏差。

### 知识点

**⚠️ 在路测电阻会被并联支路干扰**：电阻在电路板上时，两端可能还连着别的元件，测出来的是"并联后的等效阻值"，往往比标称值**偏小**。

两种做法：

| 做法 | 说明 | 精度 |
|---|---|---|
| **拆下来测** | 焊下电阻单独测 | 准 |
| **在路测** | 直接在板上测 | 偏小，但能判断"大致对得上" |

**本项目用"在路测"就够**——目的是学会用表、理解"测量值 vs 标称值"的差异，不要求拆焊。

### 操作步骤

1. 在原理图上找到 LED 的限流电阻（通常在 LED 与引脚之间），记下**位号**（如 `R1`）和**标称阻值**
2. 万用表旋钮转到 **`Ω`** 档（量程选 2kΩ 或 20kΩ，限流电阻通常几百欧到几 kΩ）
3. **先短接两支表笔**，读数应接近 0 —— 这一步是确认表和表笔正常
4. 找板子上对应的电阻（用位号丝印定位），表笔分别接触电阻两端
5. 记录

| 项 | 值 |
|---|---|
| 电阻位号 | ____ |
| 原理图标称值 | ____ Ω |
| 实测值（在路） | ____ Ω |
| 偏差 | ____% |
| 是否偏小（并联导致） | 是/否 |

### 验证方法

- 有实测记录，且与标称值做了对比
- 能解释"为什么在路测可能偏小"
- 短接表笔时读数接近 0（证明表和表笔正常）

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 读数一直在跳 | 表笔接触不稳 | 压稳表笔 |
| 读到负数或 OL | 电阻值超出所选量程 | 换更大档位 |
| 找不到电阻 | 板子上没丝印 | 顺着 LED 的走线找，或查原理图网络标号 |
| 读数远小于标称 | 在路并联了其他支路 | 正常现象，记录下来即可 |

## B5 · 万用表通断档

**任务**：用万用表的通断档，验证一条杜邦线从一端到另一端是通的、两根不相干的线之间是不通的，记录测试结果。

### 知识点

**通断档怎么工作**：给测点之间加一个小电流，如果电阻很小（通常 <50Ω），表就"滴滴"响——表示**导通**。

**这是排查硬件最常用的功能**：

- 查杜邦线好坏
- 查虚焊（该通的不通）
- 查短路（不该通的通了）

### 操作步骤

1. 万用表旋钮转到**通断档**（二极管符号或声波符号那一档）
2. **自检**：两支表笔直接碰在一起 → 应该"滴"响，读数接近 0
3. **测杜邦线**：一支表笔接触线的一端（金属部分）、另一支接触另一端

| 测试 | 预期 | 实测 |
|---|---|---|
| 表笔互碰（自检） | 滴响 | ✅/❌ |
| 杜邦线一端 ↔ 同一条线另一端 | **滴响（通）** | ✅/❌ |
| 杜邦线 A ↔ 另一条杜邦线 B | **不响（不通）** | ✅/❌ |
| 两条线相邻但不接触的金属部分 | 不响 | ✅/❌ |

> **最重要的一条经验**：**测"不该通"的时候才最能发现问题**。只测"该通的通不通"会漏掉短路。

### 验证方法

- 自检能响（证明量程正常）
- 同一条线两端能响
- 两根不同的线之间不响
- 有完整的测试记录表

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 自检都不响 | 档位选错，或表笔插孔错 | 确认是通断档、红笔在 VΩ 孔 |
| 该通的不响 | 线内部断了 | 这是**发现坏线**了，换一条 |
| 不该通的也响 | 两条线的金属部分碰在一起了 | 分开线头再测 |
