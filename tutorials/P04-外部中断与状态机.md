## 0 · 开工前的准备

### 0.1 为什么用中断

P03 用的是**轮询**——主循环不停问"按键按了吗"。问题有两个：

1. **浪费 CPU**：大部分时间都在问"没按"
2. **可能错过**：如果主循环里有耗时操作，按键按下的瞬间正好没轮到查询，这一下就丢了

**外部中断（EXTI）**让硬件来通知 CPU：引脚电平一变，立刻跳到中断服务函数。响应及时，不占用主循环。

```
轮询：  主循环 ──问──问──问──问──问──   （按键变化夹在两次问之间就可能漏掉）
中断：  主循环 ──────────────┐
                            └─ 按键一变 → 硬件立刻打断 → 跳进中断函数
```

### 0.2 新增概念：中断服务函数（ISR）

中断发生时自动执行的函数。**它的写法有一条铁律**：

> **短小、只置标志、不做耗时操作**（不延时、不打印、不做复杂计算）

原因：中断执行期间会打断其他所有事。在里面 `printf` 或 `HAL_Delay`，会拖慢整个系统、甚至丢数据。

### 0.3 确认硬件

沿用 P03 的板子。**必须确认按键是按下高电平还是低电平**——这决定 A1 里选上升沿还是下降沿：
- 按下为高（蓝板 PA0 默认）→ 用**上升沿**
- 按下为低（按键接地）→ 用**下降沿**

## A1 · 按键改外部中断

**任务**：把按键改成外部中断触发（下降沿），并在 CubeMX 里使能对应的 EXTI 中断与 NVIC。

### 知识点

**EXTI 是什么**：外部中断控制器，负责监听引脚电平变化并通知 CPU。它和 GPIO 是两套东西，但**共用同一个引脚**——你把 PA0 配成 EXTI0，它既是普通输入引脚，也具备中断能力。

**触发方式**：

| 触发方式 | 什么时候触发 | 适用 |
|---|---|---|
| Rising edge（上升沿） | 低 → 高 | 按键按下接电源（按下为高） |
| Falling edge（下降沿） | 高 → 低 | 按键按下接地（按下为低） |
| Rising/Falling（双边沿） | 任意变化 | 需要同时捕捉按下与松开 |

> 任务卡写的是"下降沿"。**如果你的按键是按下为高电平（蓝板 PA0），实际要选上升沿**——按你的板子来，并在 README 里说明你选了哪种、为什么。

**NVIC 与优先级**：NVIC 是中断总管，负责决定谁先执行。不使能 NVIC，中断配了也不会触发。

### 操作步骤

1. 打开 CubeMX 工程，在引脚图上**左键点击 `PA0`**
2. 这次选 **`GPIO_EXTI0`**（不是 GPIO_Input）
3. 左侧 `System Core` → `GPIO` → 找到 PA0，设置：

   | 参数 | 设为 |
   |---|---|
   | `GPIO mode` | `External Interrupt Mode with Rising edge trigger detection`（按下为高时选 Rising；按下为低选 Falling） |
   | `GPIO Pull-up/Pull-down` | 与你的按键匹配（蓝板 PA0 → `Pull-down`） |
   | `User Label` | `KEY` |

4. 左侧 `System Core` → **`NVIC`** → 勾上 **`EXTI line0 interrupt`** 的 `Enabled`
   - `Preemption Priority`（抢占优先级）先填 **1**，其余保持默认
5. `GENERATE CODE` 重新生成

**生成后确认**：`main.c` 里会出现 `MX_GPIO_Init` 里配置 PA0 为 `GPIO_MODE_IT_RISING` 之类的代码，以及 `stm32f1xx_it.c` 里有 `EXTI0_IRQHandler`。

### 验证方法

- 编译下载后，程序能正常跑（说明中断配置没把系统搞死）
- 在中断回调里打个断点（或用 A2 的标志位法）确认按一下会进一次中断
- **按一下只进一次**——如果进多次，是抖动或标志没清（见常见问题）

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 中断完全不触发 | NVIC 里没使能 EXTI line0 | 去 NVIC 页勾上并重新生成 |
| 按一次进多次中断 | 按键抖动，或没清中断标志 | 中断里加简单过滤；确认 HAL 回调机制 |
| 进中断后程序卡死 | 中断里做了 `printf` 或 `HAL_Delay` | 中断里只置标志（见 A2） |
| 选了下降沿但按下没反应 | 你的按键是按下为高 | 改成 Rising edge |

## A2 · 中断只置标志

**任务**：在中断服务函数里只置一个标志位，其余判断与动作全部放到主循环里执行。

### 知识点

**为什么中断里只置标志**：

```
中断里直接做事：  按键一抖 → 进中断 → printf(耗时) → 还没打印完又抖一次 → 中断重入 → 乱套
中断里只置标志：  按键一抖 → 置个标志(几纳秒) → 退出 → 主循环慢慢处理
```

**HAL 的中断回调机制**：你**不需要**直接改 `EXTI0_IRQHandler`。HAL 已经把中断处理拆好了：

```
硬件触发 → EXTI0_IRQHandler()  [HAL 提供，不用动]
         → HAL_GPIO_EXTI_Callback(引脚号)  [你在这里写代码]
```

你只需要重写 `HAL_GPIO_EXTI_Callback` 这个弱函数。

### 操作步骤

在 `main.c` 的 `/* USER CODE BEGIN 4 */` 区域写：

```c
/* 中断与主循环共享的标志：必须加 volatile，否则主循环可能读不到变化 */
volatile uint8_t key_pressed_flag = 0;

/* 外部中断回调：HAL 在中断上下文里调用它 */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == KEY_Pin)      /* 确认是按键引脚触发 */
    {
        key_pressed_flag = 1;     /* 只置标志，别的什么都不做 */
    }
}
```

在 `while(1)` 里处理：

```c
while (1)
{
    /* USER CODE BEGIN 3 */
    if (key_pressed_flag)
    {
        key_pressed_flag = 0;              /* 先清标志，再处理 */
        HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
        printf("KEY event\r\n");
    }
    /* USER CODE END 3 */
}
```

**两个关键点**：

1. **`volatile` 不能省**。它告诉编译器"这个变量可能被中断改，每次都必须真的去内存读"。不加的话编译器可能把它优化到寄存器里缓存，主循环就永远读到旧值，表现为**按了没反应**。
2. **回调里不能有 `printf`、`HAL_Delay`、复杂循环**。只置标志，几纳秒就退出。

### 验证方法

- 按一下，LED 翻转一次、串口打印一行
- 打开 `stm32f1xx_it.c` 看 `EXTI0_IRQHandler`，确认里面是 `HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0)`，你没有改它
- 在源码里指出：中断上下文中只有一条赋值语句

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 按了没反应 | 标志变量没加 `volatile` | 补上 |
| 按一次打印好几行 | 抖动导致多次进中断 | 见 A3 的时间过滤，或加软件去抖 |
| 编译报 `KEY_Pin` 未定义 | User Label 没填或生成失败 | 用 `GPIO_PIN_0` 代替 |
| 串口乱码/丢字 | 在中断里 printf 了 | 把 printf 移到主循环 |

## A3 · 区分短按与长按

**任务**：用 `HAL_GetTick()` 做时间戳，判断按下持续时间，区分短按（<500ms）与长按（≥1s）两种事件。

### 知识点

**`HAL_GetTick()`**：返回开机以来的**毫秒数**，由 SysTick 每毫秒自动加一。用它做时间戳，不用自己写计时器。

**判定思路**：按键事件需要"按下"和"松开"两个时刻：

```
按下(t1) ──────── 按住时长 = t2 - t1 ──────── 松开(t2)

  t2 - t1 < 500ms   → 短按
  t2 - t1 ≥ 1000ms  → 长按
  500~1000ms 之间   → 按任务卡定义，归入短按（或不处理）
```

**关键：三种事件（短按/长按/双击）用同一个状态机统一处理**，不要写三段独立的 if——那是 B1 加双击时会崩的做法。

### 操作步骤

在 `/* USER CODE BEGIN 0 */` 定义状态：

```c
typedef enum { EV_NONE = 0, EV_SHORT, EV_LONG } key_evt_t;

volatile uint8_t  key_down_flag = 0;   /* 中断置位：按键被按下 */
uint32_t          t_press = 0;         /* 按下时刻 */
```

中断回调改成只记录"有按下"（不改电平判断，交给主循环）：

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == KEY_Pin) { key_down_flag = 1; }
}
```

主循环里用一个小状态机：

```c
/* 状态变量放 while(1) 之前 */
uint8_t  key_busy = 0;       /* 1 = 正在跟踪一次按压 */

while (1)
{
    /* USER CODE BEGIN 3 */
    uint32_t now = HAL_GetTick();

    if (!key_busy && key_down_flag)
    {
        key_down_flag = 0;
        key_busy = 1;
        t_press  = now;                  /* 记录按下时刻 */
    }

    if (key_busy)
    {
        /* 电平回到松开态 → 这次按压结束 */
        if (HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin) == GPIO_PIN_RESET)
        {
            uint32_t dur = now - t_press;   /* 按住时长 */
            key_busy = 0;

            if (dur >= 1000)      printf("LONG  dur=%lu ms\r\n", (unsigned long)dur);
            else if (dur < 500)   printf("SHORT dur=%lu ms\r\n", (unsigned long)dur);
            else                  printf("MID   dur=%lu ms\r\n", (unsigned long)dur);
        }
        else if (now - t_press >= 1000)
        {
            /* 长按可以按住不动就上报（不等松开），按需选择 */
        }
    }
    /* USER CODE END 3 */
}
```

> **`now - t_press` 不要写成 `now > t_press + 500`**：`HAL_GetTick()` 是 32 位，约 49 天回绕一次，减法写法在回绕时仍然正确。

### 验证方法

- 快速按一下 → 串口打 `SHORT`，`dur` 值约 100~300ms
- 按住 2 秒再松 → 打 `LONG`，`dur` 约 2000ms
- 按住 700ms → 打 `MID`（若你的判定表把 500~1000 归为短按，则调整条件）

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 一直打 LONG | 松开检测条件与你的按键电平不符 | 按下为低时，松开态是 `GPIO_PIN_SET` |
| `dur` 是巨大数字 | 类型溢出或时间基准错 | 用 `uint32_t` 并检查 SysTick 正常 |
| 短按被判成长按 | 阈值写反 | 确认 `<500` 与 `>=1000` 的方向 |
| 按一次打两条 | 中断又置了标志（抖动） | 加最小间隔过滤，或软件去抖 |

## A4 · 串口输出事件与时间戳

**任务**：在串口上输出每次事件的类型（短按/长按）与当时的时间戳，连续操作 20 次核对。

### 知识点

**为什么要带时间戳**：光有"SHORT"看不出对不对。带上 `t=123456 ms` 才能事后核对——两条日志的差值就是实际按住时长，能验证阈值判定是否正确。

**日志格式建议**：定长字段方便眼睛扫：

```
[  1234 ms] SHORT dur= 210 ms
[  6789 ms] LONG  dur=2013 ms
```

用 `%6lu` 之类的宽度控制对齐。

### 操作步骤

把 A3 的打印改成统一格式：

```c
uint32_t evt_cnt = 0;

/* 事件上报宏，统一格式 */
#define REPORT(evt_name, t, dur) \
    printf("[%8lu ms] %-5s dur=%6lu ms  #%lu\r\n", \
           (unsigned long)(t), (evt_name), (unsigned long)(dur), \
           (unsigned long)(++evt_cnt))

/* 使用： */
if (dur >= 1000)     REPORT("LONG",  now, dur);
else if (dur < 500)  REPORT("SHORT", now, dur);
else                 REPORT("MID",   now, dur);
```

连续操作 20 次，把串口输出导出，填这张表放进 README：

| 序号 | 我的动作 | 程序判定 | 是否正确 | 备注 |
|---|---|---|---|---|
| 1 | 轻点 | SHORT | ✅ | dur≈180 |
| 2 | 按住 2s | LONG | ✅ | dur≈2010 |
| … | | | | |

### 验证方法

- 20 条日志齐全、序号连续
- 每条日志的 `dur` 与你实际按住的时长目测吻合（误差 <100ms）
- 判定正确率 100%（若有个别误判，写清原因）

## A5 · 画状态转移图

**任务**：画出状态机状态转移图：标出每个状态、每个状态的进入条件与退出条件（手绘拍照或画图工具均可）。

### 知识点

**状态机三要素**：

| 要素 | 说明 | 本项目例子 |
|---|---|---|
| 状态（State） | 系统当前处于什么情况 | IDLE / PRESSED / WAIT_DOUBLE |
| 事件（Event） | 触发状态转移的外部输入 | 按下、松开、超时 |
| 转移条件（Guard） | 什么条件下才转移 | 按住 ≥1s、松开间隔 <300ms |

**为什么必须画图**：B1 要加双击，直接往上堆 if 会变成"面条代码"。先画图，代码就是照着图翻译，改起来也不会乱。

### 操作步骤

用 ASCII 或手绘画出（**能讲清即可**）：

```
                    ┌──────────────────────────────────────┐
                    │                                      │
                    v                                      │
              ┌──────────┐   按下    ┌──────────┐          │
   初始 ─────>│   IDLE   │──────────>│ PRESSED  │          │
              │  (空闲)  │           │ (已按下) │          │
              └──────────┘           └────┬─────┘          │
                    ^                     │                │
                    │  松开且 dur<1s      │ 松开且 dur≥1s  │
                    │  → 上报 SHORT       │ → 上报 LONG    │
                    └─────────────────────┴────────────────┘

  加入双击后（B1）：
    SHORT 上报前先进 WAIT_DOUBLE 状态，等 300ms：
      ├─ 300ms 内又按下 → 上报 DOUBLE
      └─ 300ms 内没有    → 上报 SHORT，回 IDLE
```

**每个状态要写清**（这是任务的验收点）：

| 状态 | 进入条件 | 退出条件 |
|---|---|---|
| IDLE | 初始 / 一次事件上报完 | 检测到按下 → PRESSED |
| PRESSED | 检测到按下 | 松开且时长<1s → 上报 SHORT；松开且时长≥1s → 上报 LONG |
| WAIT_DOUBLE | 上报 SHORT 之前 | 300ms 内再按下 → 上报 DOUBLE；超时 → 上报 SHORT |

### 验证方法

- 图上每个状态都标了进入/退出条件
- 评审时能照着图**讲清代码的每个分支**对应哪条转移
- 图与代码逻辑一致（如果代码里多了一条图上没有的转移，说明图漏了）

## B1 · 加入双击判定

**任务**：加入双击判定：两次短按间隔 <300ms 判定为双击，输出第三种事件类型。

### 知识点

**双击的判定难点**：短按是"立刻上报"，但双击要求"等一等，看还有没有第二次按"。所以短按上报**必须延迟**：

```
按下 → 松开（时长<500ms）→ 不立即上报！进入等待窗口
                            ├─ 300ms 内又按下 → DOUBLE
                            └─ 300ms 过去了   → SHORT
```

**窗口取值**：200~300ms 是主流区间。
- 太短 → 手速稍慢的两次点击被判成两个 SHORT
- 太长 → 想连按两次分别生效的场景会被吞成 DOUBLE

### 操作步骤

在 A3 的状态机上扩展，增加一个状态和时间戳：

```c
/* 状态变量 */
uint8_t  key_state  = 0;   /* 0=IDLE  1=PRESSED  2=WAIT_DOUBLE */
uint32_t t_press    = 0;
uint32_t t_release  = 0;   /* 上次松开时刻，用于双击窗口 */

#define DOUBLE_GAP_MS   300
#define LONG_MS        1000
#define SHORT_MAX_MS    500
```

主循环逻辑：

```c
uint32_t now = HAL_GetTick();

switch (key_state)
{
case 0:   /* IDLE */
    if (key_down_flag) { key_down_flag = 0; key_state = 1; t_press = now; }
    break;

case 1:   /* PRESSED：等松开 */
    if (HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin) == GPIO_PIN_RESET)
    {
        uint32_t dur = now - t_press;
        if (dur >= LONG_MS) { REPORT("LONG", now, dur); key_state = 0; }
        else if (dur < SHORT_MAX_MS) { t_release = now; key_state = 2; }  /* 进双击窗口 */
        else { REPORT("MID", now, dur); key_state = 0; }
    }
    break;

case 2:   /* WAIT_DOUBLE：等第二次按下 */
    if (key_down_flag) { key_down_flag = 0; REPORT("DOUBLE", now, now - t_release); key_state = 1; t_press = now; }
    else if (now - t_release >= DOUBLE_GAP_MS) { REPORT("SHORT", t_release, 0); key_state = 0; }
    break;
}
```

> 注意 `case 2` 里再按下时进的是 `PRESSED`（因为第二次按也要等松开），这样三连击也能正确处理。

### 验证方法

- 快速点两下（间隔 <300ms）→ 打 `DOUBLE`
- 点一下、停一下（>300ms）→ 打 `SHORT`
- 点三下（都很快）→ 第一次 DOUBLE，第三次另计（能讲清你的处理策略即可）
- 长按不受影响，仍打 `LONG`

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 双击总被识别成两个 SHORT | 等待窗口没生效，SHORT 被立刻上报 | 确认按下后先进 WAIT_DOUBLE |
| 想连按两次却是 DOUBLE | 窗口太长 | 缩到 200ms |
| 长按有时被吞 | 长按判定在 PRESSED 里没优先判 | 先判 `dur >= LONG_MS` |

## B3 · 改用定时器时基

**任务**：用定时器时基（而不是 `HAL_GetTick`）驱动状态机，说明两种时间基准的差别与各自适用场景。

### 知识点

| | `HAL_GetTick()`（SysTick） | 定时器时基 |
|---|---|---|
| 来源 | 内核 SysTick，1ms 中断 | 你配的 TIMx，周期可自定 |
| 分辨率 | 1ms | 可达微秒级 |
| 中断优先级 | 通常最低 | 可配更高 |
| 适用 | 按键、延时、常规计时 | 严格时序、高速采样、PWM 时基 |
| 代价 | 无额外配置 | 占用一个定时器 |

**为什么要会两种**：P03 用 `HAL_GetTick` 简单够用；但一旦要做"精确到微秒"的时序（P05 的输入捕获、P06 的协议超时），`HAL_GetTick` 的 1ms 分辨率就不够了。

### 操作步骤

1. CubeMX 里配 **TIM2** 为 1ms 中断（P05 会详细讲参数计算：72MHz 下 `PSC=71, ARR=999`）
2. 在 `/* USER CODE BEGIN 4 */` 里写定时器回调：

```c
volatile uint32_t tim_ms = 0;   /* 自己的毫秒计数 */

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2) { tim_ms++; }   /* 中断里只自增 */
}
```

3. 在主循环里启动一次：`HAL_TIM_Base_Start_IT(&htim2);`（放 `USER CODE BEGIN 2`）
4. 把状态机里所有 `HAL_GetTick()` 换成 `tim_ms`
5. 在 README 里写一段对比说明（照上表写，并补上你的实测感受）

### 验证方法

- 功能与 B1 完全一致
- 串口打印 `tim_ms` 与 `HAL_GetTick()` 做对比，两者应大致同步（差值慢慢漂移是正常的，因为一个是内核时钟、一个是外设时钟）
- 能讲清"什么情况下必须用定时器时基"

## B4 · 拆成 key.c / key.h 模块

**任务**：把状态机写成独立的 `key.c` / `key.h` 模块，对外只暴露"取事件"一个接口，主循环不再直接碰 GPIO。

### 知识点

**为什么要拆模块**：现在主循环里混着"按键状态机 + LED 控制 + 打印"。项目一变大，主循环会变成一坨。拆开以后：

- `key.c` 只管"按键事件"，不知道 LED 是什么
- 主循环只管"拿到事件后干什么"

**"只暴露一个接口"的意义**：调用方不该知道状态机有几个状态、用没用中断。它只问："有没有新事件？"这就是**封装**。

### 操作步骤

1. Keil 里 `Add New Item` 新建 `key.c` 和 `key.h`（放到 `Core/Src`、`Core/Inc`）
2. `key.h`：

```c
#ifndef __KEY_H
#define __KEY_H

#include "main.h"

typedef enum {
    KEY_EVT_NONE = 0,
    KEY_EVT_SHORT,
    KEY_EVT_LONG,
    KEY_EVT_DOUBLE
} key_evt_t;

void      key_init(void);        /* 初始化（清零状态） */
void      key_tick(void);        /* 主循环周期调用，推进状态机 */
key_evt_t key_get_event(void);   /* 取事件：取走后自动清空，无事件返回 NONE */

#endif
```

3. `key.c`：把 A3~B1 的状态机搬进来，`key_get_event` 实现为"取出并清空"：

```c
static key_evt_t s_pending = KEY_EVT_NONE;

key_evt_t key_get_event(void)
{
    key_evt_t e = s_pending;
    s_pending = KEY_EVT_NONE;
    return e;
}
/* 状态机判定出事件时： s_pending = KEY_EVT_SHORT; 等 */
```

4. 中断回调也移进 `key.c`（`HAL_GPIO_EXTI_Callback` 是全局弱函数，放哪都行，放这里最合理）
5. 主循环变干净：

```c
key_tick();
key_evt_t e = key_get_event();
switch (e) {
    case KEY_EVT_SHORT:  printf("SHORT\r\n");  HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin); break;
    case KEY_EVT_LONG:   printf("LONG\r\n");   break;
    case KEY_EVT_DOUBLE: printf("DOUBLE\r\n"); break;
    default: break;
}
```

### 验证方法

- 功能不变
- **在 `main.c` 里搜不到 `HAL_GPIO_ReadPin(KEY...`**，也搜不到状态机的 `switch(key_state)`——它们都在 `key.c`
- 评审时能指出 `main.c` 里只剩"调 key_tick → 取事件 → 处理"三步

## B5 · 共享变量的风险与处理

**任务**：在 README 里说明中断与主循环共享的那个标志变量存在什么风险，以及你用什么办法避免了它（如暂时关中断、或用原子读写）。

### 知识点

**共享变量的风险**，具体有三种：

**风险 1：编译器优化（最常见）**
中断改了变量，但主循环里读它时，编译器认为"这变量没人改过"，把它缓存进寄存器。结果主循环永远读到旧值。
→ **对策：加 `volatile`**。

**风险 2：读改写不是原子操作**
`count++` 在汇编上是"读 → 加 → 写"三步。如果主循环执行到一半被中断打断，而中断也改了 `count`，结果会丢一次计数。
→ **对策**：① 主循环里"先关中断、改完再开"；② 或用 `__disable_irq()` / `__enable_irq()` 包住临界区。

**风险 3：多字节变量的读撕裂**
32 位变量在 8/16 位架构上可能分两次读，中途被中断改了就数据错乱。**Cortex-M3 读 32 位对齐变量是单条指令，天然安全**，但 64 位结构体就不行了。
→ **对策**：临界区保护，或拆成单字节标志位。

### 操作步骤

在 README 里写清这几点（这是本任务的全部交付）：

```markdown
## 中断与主循环共享变量的风险与处理

### 我共享了哪些变量
- `key_down_flag`（uint8_t）：中断置 1，主循环读取并清零

### 存在什么风险
1. 不加 volatile 会被编译器优化到寄存器，主循环读不到变化
2. 主循环「读 + 清零」不是原子操作：若恰好被中断打断，可能丢事件或误判

### 我怎么处理的
1. `key_down_flag` 声明为 `volatile uint8_t` —— 解决编译器优化问题
2. 主循环里的「读 + 清零」用临界区包住：
   __disable_irq();
   uint8_t f = key_down_flag; key_down_flag = 0;
   __enable_irq();
3. 状态变量（key_state / t_press 等）**只在主循环里访问**，中断绝不碰 ——
   这是最有效的办法：谁的数据谁管，中断只碰最小的一个标志位

### 为什么不让中断直接改变量
中断时间越长，丢事件与影响其他中断的概率越高；让中断只做「通知」，
把决策权留在主循环，是嵌入式里最稳的结构
```

### 验证方法

- 在源码里能指出 `volatile` 在哪、临界区在哪
- 评审时能回答："如果把 `volatile` 去掉会发生什么？"（答：主循环可能永远读不到标志变化，表现为按键没反应）
- 能讲清"为什么中断只碰一个标志位"是最稳的设计
