## 0 · 开工前的准备

### 0.1 定时器是什么

定时器是一个**会自动数数的硬件**。核心三件套：

```
时钟源 → [预分频器 PSC] → [计数器 CNT] → 数到 [自动重装 ARR] 就归零并产生事件
                                          └→ 可以引发中断，或用来生成 PWM
```

**最关键的公式**（本项目反复用）：

```
定时周期 = (PSC + 1) × (ARR + 1) / 定时器时钟频率
```

**为什么是 PSC+1、ARR+1**：这两个寄存器都是"从 0 开始数"的。PSC=71 表示分频 72 次（0~71），所以实际分频系数是 72。

### 0.2 本项目用的定时器

| 定时器 | 用途 | 挂在哪条总线 |
|---|---|---|
| TIM2 | 1ms 时基中断 | APB1 |
| TIM3 CH1 | PWM 输出 | APB1 |

**重要**：APB1 的定时器时钟是 **72MHz**（F103 在 APB1 分频不为 1 时，定时器时钟是 APB1 时钟的 2 倍，默认配置下就是 72MHz）。算参数前先确认这一点，否则频率会差好几倍。

## A1 · 配置 1ms 定时器中断

**任务**：配置一个定时器为 1ms 周期中断（预分频 + 自动重装值自己算），中断里累加一个计数器。

### 知识点

**参数推导**（这是本任务的核心，必须会自己算）：

```
目标：1ms 周期，定时器时钟 72MHz

1ms = 1/1000 秒
需要计数的个数 = 72MHz × 1ms = 72,000,000 × 0.001 = 72,000

(PSC+1) × (ARR+1) = 72,000

取整数值：PSC = 71  → (71+1) = 72
         ARR = 999 → (999+1) = 1000
         验证：72 × 1000 = 72,000 ✅  → 1ms
```

**为什么这么分**：ARR 决定计数范围（16 位最大 65535，1000 够用），PSC 负责把 72MHz 降到合适频率。两个值相乘等于 72000 即可，怎么分都行（比如 PSC=719, ARR=99 也是 1ms）。

### 操作步骤

1. CubeMX → `Timers` → **`TIM2`**
2. `Clock Source` 选 **`Internal Clock`**
3. `Parameter Settings` 里设：

   | 参数 | 值 | 说明 |
   |---|---|---|
   | `Prescaler (PSC)` | **71** | 预分频 |
   | `Counter Period (ARR)` | **999** | 自动重装 |
   | `Counter Mode` | Up | 向上计数 |
   | `auto-reload preload` | Enable | 改 ARR 时立刻生效 |

4. 切到 `NVIC Settings` 标签 → 勾 **`TIM2 global interrupt`** 的 `Enabled`
5. 确认 `Clock Configuration` 里 APB1 Timer clocks 显示 **72 MHz**
6. `GENERATE CODE`

### 写代码

```c
/* USER CODE BEGIN 0 */
volatile uint32_t tick_1ms = 0;    /* 每 1ms 加一 */
/* USER CODE END 0 */

/* USER CODE BEGIN 4 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2)
    {
        tick_1ms++;               /* 中断里只做这一件事 */
    }
}
/* USER CODE END 4 */
```

在 `main()` 里启动（`/* USER CODE BEGIN 2 */`）：

```c
HAL_TIM_Base_Start_IT(&htim2);    /* 启动定时器并开中断 */
```

### 验证方法

- 编译下载后，在调试器里给 `tick_1ms` 下断点，确认数值在增长
- 更简单的办法：主循环里每 1000 个数打印一次（A2 会做）
- **不需要示波器**也能验证：把 `tick_1ms` 打印出来，与手机秒表对比

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 中断完全不进 | 没调 `HAL_TIM_Base_Start_IT`，或 NVIC 没使能 | 两者都检查 |
| 周期差 10 倍 | 忘了 `(PSC+1)` / `(ARR+1)`，或总线频率记错 | 重算并核对 CubeMX 时钟树 |
| 进一次就再也不进 | 没清中断标志（HAL 会自动清，若你手改了回调要留意） | 不要绕过 HAL 的 IRQHandler |
| 编译报 `htim2` 未定义 | 没包含或定时器没启用 | 确认 CubeMX 里 TIM2 已配好并重新生成 |

## A2 · 每秒打印运行秒数

**任务**：用这个计数器实现"每秒串口打印一次累计运行秒数"，连续运行 10 分钟核对计时是否准确。

### 知识点

**"精确延时"的正确做法**：不要用 `HAL_Delay(1000)` 来数秒——它阻塞主循环。正确做法是**用定时器计数判断到点**：

```c
if (tick_1ms - last_report >= 1000) { last_report = tick_1ms; /* 干那件每秒一次的事 */ }
```

**为什么用减法**：`tick_1ms` 是 32 位会回绕，减法在回绕时依然正确。

### 操作步骤

```c
/* USER CODE BEGIN 2 */
HAL_TIM_Base_Start_IT(&htim2);
uint32_t last_report = 0;
/* USER CODE END 2 */

while (1)
{
    /* USER CODE BEGIN 3 */
    if (tick_1ms - last_report >= 1000)
    {
        last_report = tick_1ms;
        printf("RUN %lu s\r\n", (unsigned long)(tick_1ms / 1000));
    }
    /* USER CODE END 3 */
}
```

**核对方法**：打开手机秒表，与串口输出的秒数同步开始，跑 10 分钟后对比。

| 项 | 记录 |
|---|---|
| 串口显示 | 600 s（10 分钟） |
| 秒表实测 | ____ s |
| 误差 | ____ s |
| 是否合格（≤2s） | |

### 验证方法

- 每行输出间隔均匀（肉眼看不出一顿一顿）
- 10 分钟累积误差 ≤ 2 秒（即 ≤0.33%）

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 打印太快/太慢 | 定时器参数错，实际周期不是 1ms | 回到 A1 重算 |
| 打印不均匀 | 主循环里有阻塞操作 | 检查有没有 `HAL_Delay` |
| 跑几分钟后跳变 | 用了 `>` 而不是 `-` 比较，回绕时出错 | 改成 `tick_1ms - last_report >= 1000` |

## A3 · PWM 实现呼吸灯

**任务**：配置一个 PWM 输出通道，用改变占空比的方式实现 LED 呼吸灯（渐亮渐暗连续循环）。

### 知识点

**PWM 原理**：计数器 CNT 一直在 0~ARR 之间循环。你设一个比较值 CCR：

```
CNT <  CCR  → 输出高电平
CNT >= CCR  → 输出低电平
                ┌────┐    ┌────┐
波形：          │    │    │    │
          ──────┘    └────┘    └──────
                <──CCR──>  <──ARR-CCR──>

占空比 = CCR / (ARR+1)
```

**呼吸灯的本质**：占空比从 0 慢慢加到 100%，再从 100% 降回 0%，循环往复。因为 LED 变化很快、人眼有视觉暂留，看到的就是"渐亮渐暗"。

**频率怎么选**：呼吸灯用 **1kHz** 左右最好——够快看不出闪烁，又留足够的占空比分辨率。

```
1kHz，72MHz： (PSC+1)×(ARR+1) = 72000000 / 1000 = 72,000
取 PSC=71, ARR=999   →  1kHz，占空比分辨率 1000 级（很细腻）
```

> **注意 LED 接在 PC13，而 PC13 没有 PWM 功能！** 所以本项目有两种做法：
> - **做法 1**：用 TIM3 CH1 的引脚（PA6），把 LED 从 PC13 挪到 PA6（外加限流电阻接到 PA6）
> - **做法 2**：保持 LED 在 PC13，用**软件 PWM**（定时器中断里自己数数控制 PC13）
>
> 下面给**做法 1**（标准做法，也是 B 档要用的）；做法 2 见 B5 的变体说明。

### 操作步骤（做法 1）

1. CubeMX → `Timers` → **`TIM3`** → `Clock Source` = **Internal Clock**
2. 展开 `Channel1` → 选 **`PWM Generation CH1`**（右侧引脚图里 `PA6` 会变绿）
3. `Parameter Settings`：

   | 参数 | 值 |
   |---|---|
   | `Prescaler (PSC)` | **71** |
   | `Counter Period (ARR)` | **999** |
   | `PWM Mode` | PWM mode 1 |
   | `Pulse (CCR)` | **0**（初始占空比 0） |

4. `GENERATE CODE`
5. 硬件：把 LED（+ 限流电阻，约 1kΩ）接到 **PA6**，另一端接 GND。（若你的板子 LED 焊死在 PC13，见上面做法 2）
6. 代码：

```c
/* USER CODE BEGIN 2 */
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);   /* 必须启动，否则无输出 */

int32_t duty = 0;        /* 0~1000 */
int32_t step = 10;       /* 每次变化的步进，越大呼吸越快 */
/* USER CODE END 2 */

while (1)
{
    /* USER CODE BEGIN 3 */
    duty += step;
    if (duty >= 1000) { duty = 1000; step = -step; }
    if (duty <= 0)    { duty = 0;    step = -step; }

    __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, duty);  /* 改占空比：改 CCR！ */
    HAL_Delay(10);       /* 每 10ms 变一次，约 2 秒一个完整呼吸周期 */
    /* USER CODE END 3 */
}
```

### 验证方法

- LED 亮度连续渐变，无跳变、无卡顿
- 一个完整"亮→暗→亮"周期约 2 秒（1000/10 × 2 × 10ms = 2s）
- 改 `step` 大小立刻能看出呼吸快慢变化

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 完全没有输出 | 忘调 `HAL_TIM_PWM_Start` | 补上 |
| 改占空比没反应 | 改的是 ARR 不是 CCR | 用 `__HAL_TIM_SET_COMPARE` |
| LED 一直全亮/全灭 | CCR 设成了 0 或 1000 没变化 | 确认 `duty` 在变化 |
| 引脚没反应 | 引脚被别的外设占用，或没接对 | 检查 CubeMX 引脚图与硬件接线 |
| 亮度不连续、一跳一跳 | `step` 太大 | 调小 `step` |

## A4 · 示波器实测 PWM

**任务**：用示波器实测 PWM 波形的频率与占空比，把实测值和 CubeMX 里配置的理论值都记录下来并对比。

### 知识点

**示波器测量设置**：

| 设置 | 值 | 说明 |
|---|---|---|
| 探头衰减 | **×1** | 测 3.3V 不需要 ×10 |
| 耦合 | **DC** | 要看直流电平 |
| 时基 Time/Div | **1ms**（测 1kHz） | 一个周期占 1 格 |
| 电压 V/Div | **1V** | 3.3V 约 3.3 格 |
| 触发 | 上升沿，电平 ≈1.6V | 波形稳定不飘 |

**探头必须接地**：探头上的夹子接板子的 GND，否则测出来是噪声。这是新手第一大错误。

### 操作步骤

1. 探头接 **PA6**，夹子接 **GND**
2. 按上表设置示波器
3. 让程序停在某个固定占空比（比如把 A3 的 `duty` 固定成 500）
4. 读出示波器的自动测量值（`Freq`、`Duty`），或自己数格子
5. 填表（放进 README）：

| 项目 | 理论值 | 实测值 | 偏差 |
|---|---|---|---|
| 频率 | 1 kHz | ____ | ____% |
| 占空比（CCR=500） | 50% | ____ | ____% |
| 幅值 | 3.3 V | ____ | ____ |

**验收**：频率偏差 ≤5%，占空比偏差 ≤3%。

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 波形是杂乱噪声 | 探头夹子没接地 | 接地 |
| 波形上下抖动 | 没开触发，或触发电平不合适 | 用 Normal 触发、电平设 1.6V |
| 测出来频率是 2 倍/一半 | 误把周期当频率读数 | 分清 Freq 与 Period |
| 幅值只有 1.x V | 探头衰减设成了 ×10 但示波器没对应 | 保持一致 |

## A5 · 整理定时器参数

**任务**：把定时器参数（预分频值、自动重装值、目标频率）写成注释或结构体，说明每个值是怎么算出来的。

### 知识点

**为什么要写成结构体**：参数散落在 CubeMX 界面里，半年后你根本想不起来 ARR=999 是干嘛的。写成一张表 + 一段公式注释，换定时器/换频率时只改表。

### 操作步骤

在 `/* USER CODE BEGIN 0 */` 里加：

```c
/* ================= 定时器参数表 =================
 * 定时器时钟：72 MHz（APB1 Timer Clock）
 * 公式：周期 = (PSC+1) × (ARR+1) / 72000000
 *
 * TIM2  目标 1ms   → (PSC+1)(ARR+1)=72000  → PSC=71, ARR=999
 * TIM3  目标 1kHz PWM → (PSC+1)(ARR+1)=72000 → PSC=71, ARR=999
 *       占空比 = CCR / (ARR+1)
 * ============================================== */
typedef struct {
    const char *name;
    uint32_t    psc;
    uint32_t    arr;
    uint32_t    target_hz;      /* 目标频率（中断用周期换算） */
} tim_cfg_t;

static const tim_cfg_t g_tim_cfg[] = {
    { "TIM2_1ms", 71, 999, 1000  },   /* 1ms → 1000Hz */
    { "TIM3_PWM", 71, 999, 1000  },   /* 1kHz PWM    */
};
```

并写一段验证：程序里用 `HAL_RCC_GetPCLK1Freq()` 读出实际总线频率并打印，佐证公式里的 72MHz。

### 验证方法

- 能照着注释手算出 PSC/ARR，并解释为什么这么分
- 评审时被问"如果把 PWM 改成 2kHz 怎么改"能立刻答出（ARR 改成 499 即可）

## B1 · PWM 控制舵机

**任务**：用 PWM 控制一个舵机，让它依次转到 0°、90°、180° 三个位置，用示波器测出每个位置对应的脉宽。

### 知识点

**舵机的控制信号**：**50Hz**（周期 20ms）的 PWM，用**脉宽**（高电平持续时间）表示角度：

| 脉宽 | 角度 |
|---|---|
| 0.5 ms | 0° |
| 1.5 ms | 90° |
| 2.5 ms | 180° |

不同型号略有差异（有的 1.0~2.0ms 对应 0~180°），**以你的舵机规格书为准**。

**参数计算（50Hz）**：

```
(PSC+1) × (ARR+1) = 72,000,000 / 50 = 1,440,000

取 PSC=71 → PSC+1=72
   ARR+1 = 1,440,000 / 72 = 20,000  → ARR = 19999

脉宽 → CCR：
  每 1 个计数 = 20ms / 20000 = 1μs
  0.5ms = 500   → CCR=500
  1.5ms = 1500  → CCR=1500
  2.5ms = 2500  → CCR=2500
```

**1 个计数 = 1μs** 让换算变得非常直观。

### 操作步骤

1. **硬件供电很关键**：舵机**不要用开发板的 3.3V 或 5V 引脚直接供电**（启动电流会拉垮电源导致单片机复位）。用独立 5V 电源，**并且与开发板共地**。
2. CubeMX 改 TIM3 参数：`PSC=71`、`ARR=19999`（若和 A3 共用 TIM3，可另开 TIM4 专门驱动舵机，参数同上）
3. 信号线接舵机（橙/黄线），电源线接独立 5V，地线共地
4. 代码：

```c
/* 1 个计数 = 1μs，脉宽直接填微秒数 */
#define SERVO_0DEG    500     /* 0.5ms */
#define SERVO_90DEG  1500     /* 1.5ms */
#define SERVO_180DEG 2500     /* 2.5ms */

HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);

/* 依次转到三个位置，每个停 1 秒 */
uint16_t angles[] = { SERVO_0DEG, SERVO_90DEG, SERVO_180DEG };
for (int i = 0; i < 3; i++) {
    __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, angles[i]);
    printf("angle step %d, pulse=%u us\r\n", i, angles[i]);
    HAL_Delay(1000);
}
```

5. 示波器测每个位置的脉宽，填表：

| 目标角度 | 理论脉宽 | 实测脉宽 | 舵机实际位置 |
|---|---|---|---|
| 0° | 0.5 ms | ____ | |
| 90° | 1.5 ms | ____ | |
| 180° | 2.5 ms | ____ | |

### 验证方法

- 舵机依次停在三个位置，目测角度正确
- 重复来回 10 次不跑偏、不抖动
- 示波器实测脉宽与理论值偏差 ≤5%

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 舵机不动 | 没启动 PWM，或信号线接错 | 先量信号引脚有没有波形 |
| 舵机抖动/乱转 | 供电不足 | 用独立 5V 电源 + 共地 |
| 单片机复位 | 舵机电流冲击 | 独立供电 + 加 100~470μF 去耦电容 |
| 角度范围不对 | 舵机规格不是 0.5~2.5ms | 查规格书调整 CCR 范围 |

## B2 · PWM 驱动电机 3 档调速

**任务**：用 PWM 驱动直流电机或小风扇实现 3 档调速（慢/中/快），在串口上用命令切换档位。

### 知识点

**直流电机不能直接接 MCU 引脚**：电机电流远超引脚驱动能力（引脚只有几 mA），必须经过**驱动电路**。简单方案：

```
        电源正 ─── 电机 ───┬── MOS/三极管 漏极
                          │
                          ├── 续流二极管（跨接电机，反并联）
                          │
  PWM 信号 ── 栅极/基极 ───┤
                          │
        电源地 ────────────┴── 源极/发射极
```

**续流二极管必装**：电机关断瞬间会产生反向高压，不装会击穿 MOS 管。

**调速原理**：PWM 占空比决定电机平均电压。30% 慢、60% 中、100% 快。

### 操作步骤

1. 搭好驱动电路（MOS 管 + 续流二极管 + 栅极电阻；或用成品驱动模块）
2. PWM 用 **10kHz 左右**（太低会有可听噪声，太高开关损耗大）：

```
(PSC+1)(ARR+1) = 72,000,000 / 10,000 = 7200
取 PSC=71, ARR=99   → 10kHz
```

3. 串口命令切换档位（配合 P06 的协议或简单字符串比较）：

```c
uint8_t speed_level = 0;
const uint16_t speed_table[3] = { 30, 60, 100 };  /* 占空比百分比 */

void set_speed(uint8_t level)     /* level: 0~2 */
{
    if (level > 2) return;
    speed_level = level;
    uint16_t ccr = (uint32_t)speed_table[level] * (99 + 1) / 100;   /* ARR+1=100 */
    __HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, ccr);
    printf("speed = %u%%\r\n", speed_table[level]);
}
```

4. 串口收到 `s0` / `s1` / `s2` 分别调用 `set_speed(0..2)`

### 验证方法

- 三档转速肉眼可辨（慢/中/快差明显）
- 用示波器量占空比，与设定百分比吻合
- 电机启动时单片机不复位（说明供电与续流处理到位）

## B3 · 输入捕获测频

**任务**：用定时器的输入捕获功能测一个外部方波信号的频率，把测量值与信号源设定值对比，记录误差。

### 知识点

**输入捕获干什么**：硬件在检测到边沿时，**自动把当前计数器值存进捕获寄存器**。连续捕获两次就能算出信号周期：

```
周期 = (第二次捕获值 - 第一次捕获值) / 计数频率
频率 = 1 / 周期
```

**两种捕获方式**：
- **PWM 输入模式**：自动测周期，适合测频率
- **普通捕获**：手动读 CCR，适合测脉宽

### 操作步骤

1. CubeMX 配 **TIM4**（或空闲定时器）：
   - `Channel1` → **`Input Capture direct mode`**（引脚如 PB6）
   - `Prescaler = 71`（计数频率 1MHz，即 1 个计数 = 1μs）
   - `Counter Period = 65535`（最大）
   - `Polarity` = Rising Edge
   - NVIC 里勾上 `TIM4 global interrupt`
2. 更简单的做法：把通道配成 **`PWM Input on CH1`**，HAL 会自动测周期
3. 代码：

```c
volatile uint32_t cap_freq = 0;

/* 输入捕获回调 */
void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM4)
    {
        uint32_t period_us = HAL_TIM_ReadCapturedValue(htim, TIM_CHANNEL_1);  /* PWM 输入模式下是周期 */
        if (period_us > 0) cap_freq = 1000000UL / period_us;                  /* 计数 1MHz → 1μs */
    }
}

/* 启动： */
HAL_TIM_IC_Start_IT(&htim4, TIM_CHANNEL_1);
```

4. **自检信号源**：没有外部信号源时，可用另一个定时器的 PWM 输出引脚接到输入捕获引脚（如 TIM3 的 PA6 接 TIM4 的 PB6），设定 1kHz 验证测出来是不是 1kHz
5. 填表：

| 信号源设定 | 测量值 | 误差 |
|---|---|---|
| 1 kHz | ____ | ____% |
| 2 kHz | ____ | ____% |

### 验证方法

- 测量值与设定值误差 <2%
- 改变信号源频率，测量值跟着变
- 能讲清"为什么预分频设 71 让换算变成 1μs 一步"

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 测不到频率（一直 0） | 引脚接错，或没启动捕获 | 检查接线与 `HAL_TIM_IC_Start_IT` |
| 频率是实际值的一半/两倍 | 边沿设置错（测了双边沿） | 改成单边沿 |
| 数值乱跳 | 信号有噪声 | 提高触发质量，或软件取中间值 |
| 超过量程读错 | 信号周期超过 65535μs（<15Hz） | 加大预分频 |

## B4 · PWM 参数表

**任务**：把 PWM 配置抽成一张参数表（通道、频率、初始占空比），加一路 PWM 只改表不改逻辑。

### 知识点

**"数据驱动"的思路**：把易变的东西（频率、占空比）从代码逻辑里抽出来放进表。加一路 PWM 只需要在表里加一行——这就是可维护性。

### 操作步骤

```c
/* PWM 配置表：加一路 PWM 只需在这里加一行 */
typedef struct {
    TIM_HandleTypeDef *htim;
    uint32_t           channel;
    uint32_t           freq_hz;
    uint8_t            init_duty;      /* 百分比 0~100 */
} pwm_cfg_t;

static pwm_cfg_t g_pwm_table[] = {
    { &htim3, TIM_CHANNEL_1,  1000,  50 },   /* 呼吸灯 */
    { &htim3, TIM_CHANNEL_2, 10000,  30 },   /* 电机   */
    { &htim4, TIM_CHANNEL_1,    50,   7 },   /* 舵机（7.5%=1.5ms）*/
};

static void pwm_table_init(void)
{
    for (uint32_t i = 0; i < sizeof(g_pwm_table)/sizeof(g_pwm_table[0]); i++)
    {
        pwm_cfg_t *p = &g_pwm_table[i];
        uint32_t arr_plus1 = 1000000UL / p->freq_hz;      /* 简化：假设 PSC=71，计数 1MHz */
        __HAL_TIM_SET_AUTORELOAD(p->htim, arr_plus1 - 1);
        __HAL_TIM_SET_COMPARE(p->htim, p->channel, arr_plus1 * p->init_duty / 100);
        HAL_TIM_PWM_Start(p->htim, p->channel);
        printf("PWM ch init: %lu Hz, duty=%u%%\r\n",
               (unsigned long)p->freq_hz, p->init_duty);
    }
}
```

> 上面假设所有 PWM 定时器 PSC 都为 71（计数 1MHz）。若不同，把 PSC 也加进表里。

### 验证方法

- 在表里加一行新 PWM，**不改任何逻辑代码**就能多输出一路
- 打印出来的初始化信息与表内容一致
- 评审时能说清"为什么这样写更好维护"

## B5 · 精细时基（只计数不处理）

**任务**：用定时器做一个更精细的时基：把 A 档的 1ms 中断改成"仅计数、不做任何处理"，主循环判断计数器到点再执行任务，说明这样做的好处。

### 知识点

**中断里做太多事的代价**：

```
坏做法：中断里 printf + 控制 LED + 判断逻辑
        → 中断执行时间可能几十毫秒 → 期间别的中断被阻塞、可能丢事件

好做法：中断里只有 tick_1ms++
        → 中断执行时间约 1μs → 主循环按 count 判断到点再干活
```

**好处三条**：
1. **中断极短**，不影响其他中断的实时性
2. **任务可以重叠**：5ms 的任务和 100ms 的任务都能基于同一个 1ms tick 调度
3. **逻辑集中**：所有业务逻辑都在主循环，好调试（中断里没法打断点）

### 操作步骤

```c
/* 中断：只计数 */
volatile uint32_t tick_1ms = 0;
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance == TIM2) tick_1ms++;
}

/* 主循环：把 tick 当作"软件定时器"用 */
uint32_t t_led = 0, t_report = 0;

while (1)
{
    uint32_t now = tick_1ms;

    /* 每 500ms 翻转 LED */
    if (now - t_led >= 500) { t_led = now; HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin); }

    /* 每 1000ms 上报一次 */
    if (now - t_report >= 1000) { t_report = now; printf("tick=%lu\r\n", (unsigned long)now); }

    /* 这里还能加更多不同周期的任务，互不干扰 */
}
```

**做一次对比实验**（放进 README）：

| 方案 | 中断执行时间（估） | 能否同时跑多个周期任务 |
|---|---|---|
| 中断里直接处理 | 长（含 printf） | 难 |
| 中断只计数 | 约 1μs | 容易 |

### 验证方法

- LED 与串口上报各自周期准确、互不干扰
- 在中断里只看到一条 `tick_1ms++`
- 能讲清"为什么中断里不该做耗时操作"
