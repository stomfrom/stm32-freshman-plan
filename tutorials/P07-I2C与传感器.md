## 0 · 开工前的准备

### 0.1 I2C 是什么

**I2C 是两线总线**：一条时钟线 **SCL** + 一条数据线 **SDA**。多设备并联在同一条总线上，靠**地址**区分。

```
        ┌──── 3.3V
        │
       ┌┴┐     上拉电阻（必须！）
       │ │ 4.7kΩ
       └┬┘
        ├──────────────┬──────────────┐
   SCL ─┴──────────────┼──────────────┤
                       │              │
   SDA ────────────────┼──────────────┤
                       │              │
                   ┌───┴───┐     ┌────┴────┐
                   │  MCU  │     │  OLED   │
                   └───────┘     └─────────┘
```

**⭐ 最关键的一点：SDA 和 SCL 必须接上拉电阻**（常见 4.7kΩ）。

为什么：I2C 的引脚是"开漏"输出——只能把线**拉低**，不能主动拉高。所以必须有上拉电阻把线拉高。**没有上拉电阻，总线永远拉不高，通信必然失败。**

> 好消息：大多数 OLED 模块**板上已经自带上拉电阻**，直接接线即可。但如果扫描不到设备，**第一件事就是检查上拉**。

### 0.2 引脚选择

F103 的 I2C1 默认引脚：

| 信号 | 引脚 |
|---|---|
| SCL | **PB6** |
| SDA | **PB7** |

### 0.3 本项目的硬件连接

| OLED 引脚 | 接到 |
|---|---|
| VCC | 3.3V |
| GND | GND |
| SCL | PB6 |
| SDA | PB7 |

## A1 · I2C 扫描总线设备

**任务**：配置硬件 I2C（速率 100kHz 或 400kHz），用 I2C 扫描程序遍历地址段，把总线上所有响应设备地址打印出来。

### 知识点

**I2C 通信的基本单元**：

```
起始条件 → [地址(7位) + 读写位] → [ACK] → [数据] → [ACK] → ... → 停止条件
```

**ACK 是什么**：主机发出地址后，如果总线上某个设备认识这个地址，它会**把 SDA 拉低**一个时钟周期作为应答（ACK）。**扫描程序就是靠"有没有 ACK"来判断设备是否存在。**

**地址的两种写法**：

| 写法 | 例子 | 说明 |
|---|---|---|
| 7 位地址 | `0x3C` | 编程实际用的 |
| 8 位地址 | `0x78` | 驱动资料里常见，= 7 位地址 << 1 |

扫描程序一般打印 **8 位地址**（`0x78`）或 7 位（`0x3C`），两者差一位左移，别被绕晕。

### 操作步骤

1. CubeMX → `Connectivity` → **`I2C1`** → `I2C` 选 **`I2C`**
2. `Parameter Settings` 设：

   | 参数 | 值 |
   |---|---|
   | `I2C Speed Mode` | Standard Mode（100kHz）或 Fast Mode（400kHz） |
   | `Clock Speed` | 100000 或 400000 |
   | `Fast Mode Duty Cycle` | 2（Fast Mode 时） |

3. 确认引脚图里 **PB6/PB7 变绿**
4. `GENERATE CODE`

扫描程序（放 `main.c`，主循环前调用一次即可）：

```c
/* USER CODE BEGIN 0 */
#include <stdio.h>

/* 扫描 I2C1 总线上所有应答的设备，返回找到的个数 */
static uint8_t i2c_scan(void)
{
    uint8_t found = 0;
    printf("I2C scan start (7-bit addr):\r\n");

    for (uint8_t addr = 0x08; addr <= 0x77; addr++)     /* 7 位地址有效范围 */
    {
        /* HAL_I2C_IsDeviceReady(句柄, 地址<<1, 试几次, 超时ms) */
        if (HAL_I2C_IsDeviceReady(&hi2c1, (uint16_t)(addr << 1), 2, 10) == HAL_OK)
        {
            printf("  found device @ 0x%02X (8-bit 0x%02X)\r\n",
                   addr, (uint8_t)(addr << 1));
            found++;
        }
    }
    printf("I2C scan done, %u device(s) found.\r\n", found);
    return found;
}
/* USER CODE END 0 */
```

在 `/* USER CODE BEGIN 2 */` 里调用：

```c
HAL_Delay(100);        /* 等 OLED 内部复位 */
i2c_scan();
```

### 验证方法

- 串口打印出扫描结果，**至少找到一个设备**（OLED 一般是 `0x3C` 或 `0x78`）
- 记下这个地址——后面驱动 OLED 要用

```
I2C scan start (7-bit addr):
  found device @ 0x3C (8-bit 0x78)
I2C scan done, 1 device(s) found.
```

### 常见问题

**⭐ 扫描不到任何设备**（按顺序排查）：

| # | 检查项 | 怎么查 |
|---|---|---|
| 1 | 上拉电阻有没有 | 量 SDA/SCL 对 3.3V 的阻值；模块自带也可能失效 |
| 2 | SDA/SCL 接反了吗 | 交换两根线再试 |
| 3 | 屏供电了吗 | 量 VCC 引脚电压是否 3.3V |
| 4 | 引脚配对了没 | CubeMX 里确认 PB6/PB7 变绿 |
| 5 | 总线空闲时是否为高电平 | 用万用表量 SDA/SCL 静态电压，应是 3.3V |

| 其他现象 | 原因 | 怎么办 |
|---|---|---|
| 扫出一堆不存在的地址 | 缺上拉，总线一直被读成低电平 | 补上拉电阻 |
| 扫到 0x00 | 同上 | 同上 |
| 时好时坏 | 接线接触不良 | 焊一下或换杜邦线 |

## A2 · 驱动 OLED 显示字符串

**任务**：用硬件 I2C 驱动一块 OLED 屏，在屏上显示一行英文字符串。

### 知识点

**OLED 不是"发什么显什么"**：它内部有一块**显存（GDDRAM）**，按"页（Page）"组织：

```
显存结构（128×64 常见）：
  Page0:  128 字节，每字节的低 8 位对应 8 行像素
  Page1:  128 字节
  ...
  Page7:  128 字节
  → 8 页 × 128 字节 = 1024 字节
```

**显示字符要做两件事**：
1. **取字模**：把字符的点阵（每个像素用一位表示）从字模表里取出来
2. **写显存**：把点阵数据按页写进 OLED 的显存

**⭐ 字模取模方式必须与驱动代码一致**：取模软件里有"逐行/逐列"、"高位在前/在后"的选项。选错了显示出来就是**乱码或上下颠倒的花纹**——这是新手最常卡的地方。

### 操作步骤

**1. 直接用附录 A 的驱动**

**不要**去网上另找例程：[附录 A · 最小可运行的 SSD1306 I2C 驱动](#p07-app-a) 就是绑定这块屏（I2C1、PB6/PB7、7 位地址 `0x3C`）的完整可编译版本。做法：

1. 把附录 A 里的 `oled.h`、`oled.c` 抄成两个文件（`Core/Inc/oled.h`、`Core/Src/oled.c`）
2. **逐行读一遍 `oled_init` 的命令表**，对照 [附录 A.4 的命令表](#p07-app-a)，弄清每一条命令在配什么——这一步比抄代码重要得多
3. 若 A1 扫到的地址不是 `0x3C`，改 `oled.h` 里的 `OLED_ADDR_7BIT`

（附录 A 自带的 6×8 字模是示例子集，够显示 `Hello STM32!`、`Counter:` 和数字；要显示其它字符，按 A.5 的方法用 PCtoLCD2002 补全 ASCII 表。）

**2. 把驱动文件加进工程**

把 `oled.c` / `oled.h` 放进 `Core/Src`、`Core/Inc`，在 Keil 里 `Add Existing Files` 加入工程。

**3. 主程序调用**

```c
/* USER CODE BEGIN Includes */
#include "oled.h"
#include <string.h>
/* USER CODE END Includes */

/* USER CODE BEGIN 2 */
oled_init();                                   /* 初始化 + 自动清屏 */
oled_set_pos(0, 0);                            /* 第 0 页（最上面 8 行）、第 0 列 */
oled_print("Hello STM32!", strlen("Hello STM32!"));   /* 6×8 字模，12 个字符 */
/* USER CODE END 2 */
```

### 验证方法

- 屏上显示出 `Hello STM32!`，字符清晰、方向正确（不是花纹、不是倒的）
- 按复位键能重复显示

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 全黑毫无反应 | I2C 没通 / 地址错 / 初始化没调 | 先跑 A1 扫描确认设备在 |
| 乱码花纹 | 字模取模方式不对 | 改取模软件设置，或改驱动的位处理顺序 |
| 上下颠倒 | 扫描方向反了 | 改 `oled_init` 里的扫描方向命令（`0xA1`/`0xC8`）|
| 显示一半就花了 | 显存写入越界 | 检查页地址/列地址范围 |
| 亮一下又灭 | 初始化序列不完整 | 用附录 A 的完整初始化序列 |

## A3 · 显示自增计数器

**任务**：在 OLED 上显示一个每秒自增的计数器，连续观察 1 分钟不出现花屏、跳字或卡死。

### 知识点

**刷新的正确做法**：

```c
/* 错误：每次都清全屏 → 屏闪，而且慢 */
oled_clear();
oled_printf("%lu", (unsigned long)count);

/* 正确：只更新那个区域（定长显示 + 补零），不清屏 */
oled_set_pos(2, 0);                          /* 第 2 页（从第 16 行起） */
oled_printf("%06lu", (unsigned long)count);  /* 固定 6 位宽，前面补零 */
```

**为什么定长显示**：如果数字位数会变（`1` → `10` → `100`），不清屏就会留下旧数字的残迹（比如 `9` 变成 `10` 时留下 `90`）。定长补零能避免。

### 操作步骤

```c
/* USER CODE BEGIN 2 */
oled_init();                                  /* 内部已清屏 */
oled_set_pos(0, 0);
oled_print("Counter:", strlen("Counter:"));

uint32_t t_1s   = 0;
uint32_t count  = 0;
/* USER CODE END 2 */

while (1)
{
    /* USER CODE BEGIN 3 */
    uint32_t now = HAL_GetTick();          /* 若 P05 已配 TIM2，可改用 tick_1ms */

    if (now - t_1s >= 1000)               /* 每秒一次 */
    {
        t_1s = now;
        count++;
        oled_set_pos(2, 0);               /* 只重画计数那一行 */
        oled_printf("%06lu", (unsigned long)count);   /* 固定 6 位宽，自动补零 */
    }
    /* USER CODE END 3 */
}
```

### 验证方法

- 计数器每秒 +1，连续跑 **1 分钟**（到 60）不花屏、不跳字、不卡死
- 数字前补零（如 `000012`），位数不变
- 观察时屏上没有闪烁感

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 数字后面有残影 | 没定长显示，旧位数没擦掉 | 用定长 + 补零 |
| 计数不准 | 用了 `HAL_Delay(1000)` 阻塞，或有其他耗时 | 用 tick 判断；检查循环里有无阻塞 |
| 跑一会儿花屏 | 显存写入越界或 I2C 出错 | 加 I2C 错误重试；检查坐标范围 |
| 整屏闪 | 每帧都 `oled_clear()` | 去掉全屏清，只更新局部 |

## A4 · 串口同步打印

**任务**：把 OLED 的显示内容通过串口同步打印一份，两份内容保持一致（用于离线核对）。

### 知识点

**为什么要有这个**：OLED 是硬件显示，做实验记录/截图时不好保留数据。串口日志能导出、能贴进报告、能事后核对——**它是你的"证据"**。

### 操作步骤

```c
if (now - t_1s >= 1000)
{
    t_1s = now;
    count++;

    oled_set_pos(2, 0);
    oled_printf("%06lu", (unsigned long)count);            /* 屏上定长显示 */
    printf("[OLED] Counter = %lu\r\n", (unsigned long)count);   /* 同步打印 */
}
```

**核对方法**：跑 30 秒，对比屏上的数字与串口最后一行是否一致；中途抽 3 次点对点核对。

| 核对时点 | OLED 显示 | 串口打印 | 一致？ |
|---|---|---|---|
| 第 10 秒 | | | ✅/❌ |
| 第 20 秒 | | | |
| 第 30 秒 | | | |

### 验证方法

- 串口打印的数值与屏上显示**始终一致**
- 打印带 `[OLED]` 前缀，便于在混杂日志里筛选
- 保留串口日志作为交付证据

## B1 · 多页菜单

**任务**：在 OLED 上做一个多页菜单：至少 3 个页面，用按键上下翻页、当前选中项高亮显示。

### 知识点

**菜单的三个组成**：

| 组成 | 说明 |
|---|---|
| 页面/条目列表 | 有哪几项 |
| 当前选中索引 | 现在选中第几项 |
| 翻页规则 | 到头后循环还是停住（本项目**循环**）|

**避免闪烁的关键**：只在**选中项变化时**重绘，不要每轮循环都重绘整屏。

### 操作步骤

```c
/* USER CODE BEGIN 0 */
/* 需要 <stdio.h>（snprintf）与 <string.h>（strlen） */
#define MENU_CNT   3

static const char *menu_items[MENU_CNT] = {
    "1. LED Control",
    "2. Brightness",
    "3. About",
};
static uint8_t menu_sel = 0;

static void menu_draw(void)
{
    for (uint8_t i = 0; i < MENU_CNT; i++)
    {
        /* 选中项前面加 ">"，并可用反色高亮；这里用简单标记 */
        char line[20];
        snprintf(line, sizeof(line), "%c%s", (i == menu_sel) ? '>' : ' ', menu_items[i]);
        oled_set_pos((uint8_t)(i * 2), 0);      /* 每项占 2 页（16 行像素）*/
        oled_print(line, strlen(line));
    }
}

static void menu_move(int8_t dir)
{
    if (dir > 0) menu_sel = (menu_sel + 1) % MENU_CNT;                 /* 下 */
    else         menu_sel = (menu_sel + MENU_CNT - 1) % MENU_CNT;     /* 上（循环）*/
    menu_draw();
}
/* USER CODE END 0 */
```

配合 P04 的按键事件取用：

```c
/* 用两个按键（或一个按键的短按/长按）翻页 */
key_evt_t e = key_get_event();
if (e == KEY_EVT_SHORT)  menu_move(+1);      /* 短按下一项 */
if (e == KEY_EVT_LONG)   menu_move(-1);      /* 长按上一项 */
```

### 验证方法

- 3 个条目都能显示，当前选中项有明确标记
- 按按键能上下切换，**到最后一页再按能回到第一页**
- 翻页响应 ≤200ms，屏上无明显闪烁
- 选中标记与实际索引一致

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 翻页闪屏 | 每次都 `oled_clear()` + 全屏重绘 | 只重绘变化的行 |
| 到头卡住 | 用了 `menu_sel++` 没做环绕 | 用 `% MENU_CNT` 取模 |
| 上一个选中标记没擦掉 | 重绘时没覆盖旧标记位置 | 整行重绘（含前导空格） |
| 按键连跳好几项 | 没去抖 | 复用 P04 的状态机 |

## B2 · 示波器看 I2C 时序

**任务**：用示波器抓 SDA 与 SCL 波形，在图上标出起始条件、地址字节、ACK 位、停止条件各在哪一段。

### 知识点

**I2C 四个关键时序点**：

| 事件 | 特征 |
|---|---|
| **起始条件（Start）** | SCL 为**高**时，SDA **由高变低** |
| **地址字节** | 起始条件后的 8 个时钟：7 位地址 + 1 位读写位 |
| **ACK** | 第 9 个时钟周期，**从机把 SDA 拉低** |
| **停止条件（Stop）** | SCL 为**高**时，SDA **由低变高** |

```
        Start                            ACK          Stop
SDA ────┐   ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌───┐  ┌────
        └───┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘   └──┘
             A6  A5  A4  A3  A2  A1  A0  R/W   ↑
                                           从机拉低
SCL ──┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌──
      └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘
```

### 操作步骤

1. **示波器需要两个通道**：CH1 接 **SCL**、CH2 接 **SDA**，两个夹子都接 GND
2. 设置：
   - 探头衰减 **×1**
   - 时基 **10μs/格** 左右（100kHz 时，一个时钟周期 10μs）
   - 电压 **1V/格**
   - 触发：**CH1 下降沿** 或 **CH2 下降沿**，电平 1.6V
3. 用**单次触发（Single）** 抓一次通信（可以让程序只做一次 OLED 刷新）
4. 在波形图上标注四个位置，截图
5. 写进 README：

| 时序点 | 在图上什么位置 | 特征 |
|---|---|---|
| 起始条件 | | SCL 高时 SDA 下降 |
| 地址字节 | | 起始后 8 个时钟 |
| ACK 位 | | 第 9 个时钟，SDA 被从机拉低 |
| 停止条件 | | SCL 高时 SDA 上升 |

> **没有示波器怎么办**：用**逻辑分析仪**（若能借到，25 元的 8 通道就够）；或用**软件 I2C + GPIO 翻转打点**，用示波器单通道分别看 SDA/SCL。也可以降低 I2C 速率到 10kHz 让波形更容易抓。

### 验证方法

- 抓到了清晰的双通道波形
- 四个时序点都标注出来，且标注位置正确
- 能口头讲清"ACK 是怎么看出来的"（第 9 个时钟 SDA 被拉低）

## B3 · 驱动封装成模块

**任务**：把 OLED 驱动封装成独立模块（`.c` / `.h` 分离，对外只暴露 `oled_init`、`oled_print`、`oled_clear` 等接口），主程序里不出现任何 I2C 底层调用。

### 知识点

**判断封装是否到位**：**主程序里搜不到 `HAL_I2C_`**。所有 I2C 细节都关在驱动里。这样做的价值：

| 好处 | 说明 |
|---|---|
| 换屏只改驱动 | 换驱动芯片/换 SPI 接口，应用层不动 |
| 换 MCU 只改驱动 | 从 F103 换到别的芯片，只重写驱动 |
| 应用层好读 | `oled_print("Hello", 5)` 比一串 I2C 调用清楚得多 |

### 操作步骤

**`oled.h`**（对外接口，与附录 A 完全一致）：

```c
#ifndef __OLED_H
#define __OLED_H

#include <stdint.h>
#include <stddef.h>

/* 初始化屏（SSD1306 命令序列，见附录 A.4） */
void oled_init(void);

/* 清屏 */
void oled_clear(void);

/* 设置写显存的位置：page 0~7（每页 8 行像素），col 0~127 */
void oled_set_pos(uint8_t page, uint8_t col);

/* 在当前位置写字符串（6×8 字模），len = 字节数 */
void oled_print(const char *str, size_t len);

/* 格式化打印：内部 vsnprintf 到缓冲区再调 oled_print */
void oled_printf(const char *fmt, ...);

#endif
```

**`oled.c`**（实现，包含所有 I2C 细节）：

```c
#include "oled.h"
#include "i2c.h"                 /* CubeMX 生成的 I2C 句柄 hi2c1 */

#define OLED_ADDR8   (0x3C << 1) /* = 0x78，HAL 的 DevAddress 要 8 位形式 */

/* 底层两个函数与附录 A 相同，改成 static 只在本模块内可见 */
static void oled_cmd(const uint8_t *cmd, uint16_t len)
{
    HAL_I2C_Mem_Write(&hi2c1, OLED_ADDR8, 0x00, I2C_MEMADD_SIZE_8BIT,
                      (uint8_t *)cmd, len, 50);
}

static void oled_data(const uint8_t *data, uint16_t len)
{
    HAL_I2C_Mem_Write(&hi2c1, OLED_ADDR8, 0x40, I2C_MEMADD_SIZE_8BIT,
                      (uint8_t *)data, len, 50);
}

/* 下面这些实现直接照附录 A，不再重复贴（命令表 / 字模表 / 显存写入） */
void oled_init(void)  { /* 附录 A 的 init_cmds 命令表 */ }
void oled_clear(void) { /* 8 页 × 128 列全写 0x00 */ }

void oled_set_pos(uint8_t page, uint8_t col) { /* 0xB0|page + 列低/高 4 位 */ }

void oled_print(const char *str, size_t len) { /* 取字模 + oled_data(每字符 6 字节) */ }

void oled_printf(const char *fmt, ...) { /* vsnprintf 到 buf[64]，再 oled_print */ }
```

主程序变得很干净：

```c
/* USER CODE BEGIN Includes */
#include "oled.h"
#include <string.h>
/* USER CODE END Includes */

/* USER CODE BEGIN 2 */
oled_init();
oled_clear();

oled_print("STM32 Ready", strlen("STM32 Ready"));
oled_set_pos(2, 0);
oled_printf("%06lu", 12345UL);
/* USER CODE END 2 */
```

### 验证方法

- **主程序（`main.c` 的业务部分）里搜不到 `HAL_I2C_`**——这就是封装到位的证据
- `oled.h` 的接口不超过 5~6 个函数（对外接口要少而清晰）
- 功能正常
- 评审时能指出"如果要换 SPI 的屏，只需改 `oled.c` 内部"

## B4 · 换屏测试

**任务**：做一个"换屏测试"：修改驱动模块里的初始化序列与分辨率参数，适配另一款不同驱动芯片的 OLED（或说明若换成 SPI 接口的屏需要改哪几处）。

### 知识点

**换屏要改什么**——取决于"换的是什么"：

| 换屏类型 | 要改的地方 |
|---|---|
| **同驱动芯片，不同尺寸**（如 128×64 → 128×32） | 分辨率宏、页数、初始化序列里的复用率设置 |
| **不同驱动芯片**（SSD1306 → SH1106） | 初始化命令序列（不同芯片命令不同）、列地址偏移（SH1106 有 2 列偏移）|
| **I2C → SPI 接口** | 重写底层收发函数（`oled_cmd/data` 改为 SPI 发送）、增加 DC/RES/CS 引脚控制 |

**关键设计**：把所有"可能变的东西"抽成宏或配置表放在驱动文件顶部，换屏只改这几行。

### 操作步骤

在 `oled.c` 顶部做配置区：

```c
/* ==================== 屏配置区（换屏只改这里）==================== */
#define OLED_WIDTH      128
#define OLED_HEIGHT     64
#define OLED_PAGES      (OLED_HEIGHT / 8)     /* = 8 */

/* 驱动芯片选择：1=SSD1306  2=SH1106 */
#define OLED_DRIVER     SSD1306

#if (OLED_DRIVER == SH1106)
  #define OLED_COL_OFFSET   2     /* SH1106 显存列地址有 2 列偏移 */
#else
  #define OLED_COL_OFFSET   0
#endif
/* ================================================================= */
```

然后写一份"换屏改动说明"放进 README：

```markdown
## 换屏测试：需要改动的位置

| 目标 | 要改的地方 | 工作量 |
|---|---|---|
| 128×64 → 128×32（SSD1306） | `OLED_HEIGHT` 改 32；初始化序列里的复用率命令 | 2 行 |
| SSD1306 → SH1106 | `OLED_DRIVER` 改 SH1106；`OLED_COL_OFFSET` 改 2；初始化序列替换 | 1 个配置 + 1 段序列 |
| I2C → SPI 接口 | 重写 `oled_cmd` / `oled_data` 两个函数（改用 SPI 发送）；新增 DC/RES/CS 引脚控制 | 2 个函数 |
| 换 MCU 平台 | 只改 I2C 句柄来源（`i2c.h`）与发送函数 | 1 处 |

**结论**：应用层（`main.c` 里的 `oled_print` 调用）**完全不需要改动** —— 这就是 B3 封装的价值。
```

**若手头没有第二块屏**：把上表写清楚（任务允许"或说明…需要改哪几处"，**纸上分析即可，不必真买第二块屏**），并说明改动的理由。有条件的话改 `OLED_HEIGHT` 为 32 试一次，观察显示效果变化。

### 验证方法

- 给出了明确的"改动位置表"，每项都说得清为什么改
- 能讲清"I2C 换 SPI 要动哪两个函数"
- （若实际换了屏）新屏能正常显示

## B5 · 温湿度传感器接入与超限告警

**任务**：在 I2C 总线上再接一个**温湿度传感器**（AHT20，7 位地址 `0x38`；或 SHT30 `0x44`），读出温度与湿度显示到 OLED 上，每秒刷新一次；并做超限告警（如温度 > 30℃ 时屏上显示 `ALERT`）。

### 知识点

**为什么选 AHT20 / SHT30**：它们都是**标准 I2C 从机**，和 OLED 挂在同一条 PB6/PB7 总线上，A1 里的扫描代码、`HAL_I2C_*` 收发函数直接复用。

| 器件 | 7 位地址 | 说明 |
|---|---|---|
| **AHT20** | `0x38` | 国产，模块便宜，20 位温湿度 |
| **SHT30** | `0x44` | 精度更好，命令格式不同（单次测量命令 `0x2C 0x06`） |

**AHT20 的一次测量流程**：

1. 发**触发测量命令** `0xAC 0x33 0x00`
2. 等 **80 ms**（转换时间典型 75ms，给一点余量）
3. 读回 **6 个字节**：`[状态] [湿度19:12] [湿度11:4] [湿度3:0|温度19:16] [温度15:8] [温度7:0]`
4. 换算（20 位数据）：

```
raw_h = (b1 << 12) | (b2 << 4) | (b3 >> 4)          /* 20 位湿度原始值 */
raw_t = ((b3 & 0x0F) << 16) | (b4 << 8) | b5        /* 20 位温度原始值 */

RH = 100 * raw_h / 2^20     （单位 %RH，2^20 = 1048576）
T  = -50 + 200 * raw_t / 2^20 （单位 ℃；AHT20 手册：T = raw/2^20 × 200 − 50）
```

> 换算系数以你手上模块的**数据手册**为准：同一颗芯片不同批次/不同手册版本可能写不同的比例系数，用参考温度计对一次就知道该不该改。代码里把系数写成宏，改一个数就行。

**⭐ 先跑 A1 扫描确认 `0x38` 出现**：接上传感器后重新跑一次扫描，应该能看到 **两个** 设备——`0x3C`（OLED）+ `0x38`（AHT20）。**扫不到就先别写代码**，九成是接线、共地或模块供电问题。

### 操作步骤

**1. 接线**（与 OLED 并联在同一条 I2C 总线上）

| 传感器引脚 | 接到 |
|---|---|
| VCC | 3.3V（按你的模块规格，别超过额定电压）|
| GND | GND（与 OLED、板子共地）|
| SCL | PB6（和 OLED 的 SCL 并在一起）|
| SDA | PB7（和 OLED 的 SDA 并在一起）|

**2. 重新扫描一次**：串口应打印出两行 `found device`，其中一行是 `@ 0x38`。

**3. 读传感器的代码**（`aht20.c` 的核心，HAL 版本）

```c
/* USER CODE BEGIN 0 */
#define AHT20_ADDR8    (0x38 << 1)          /* 7 位 0x38 → HAL 用 8 位 0x70 */

/* 上电准备：等 40ms，并检查校准位（bit3） */
static int aht20_init(void)
{
    uint8_t status = 0;

    HAL_Delay(40);                          /* 上电后 ≥40ms 才能访问 */

    if (HAL_I2C_Master_Receive(&hi2c1, AHT20_ADDR8, &status, 1, 50) != HAL_OK)
        return -1;                          /* 器件不在总线上 */

    if ((status & 0x08) == 0)               /* bit3 = 0：尚未校准 */
    {
        uint8_t cal[3] = { 0xBE, 0x08, 0x00 };
        if (HAL_I2C_Master_Transmit(&hi2c1, AHT20_ADDR8, cal, 3, 50) != HAL_OK)
            return -2;
        HAL_Delay(10);
    }
    return 0;
}

/* 触发一次测量并读回温湿度；返回 0 成功 */
static int aht20_read(float *t_c, float *rh_pct)
{
    uint8_t cmd[3] = { 0xAC, 0x33, 0x00 };  /* 触发测量：0xAC + 两个参数 */
    uint8_t buf[6] = { 0 };

    /* AHT20 没有"寄存器地址"，命令直接发（不要用 Mem_Write 多塞一个地址字节）*/
    if (HAL_I2C_Master_Transmit(&hi2c1, AHT20_ADDR8, cmd, 3, 50) != HAL_OK)
        return -1;

    HAL_Delay(80);                          /* 等转换完成（典型 75ms）*/

    if (HAL_I2C_Master_Receive(&hi2c1, AHT20_ADDR8, buf, 6, 50) != HAL_OK)
        return -2;

    if (buf[0] & 0x80)                      /* bit7 = 忙，说明还没测完 */
        return -3;

    /* 40 位数据跨 6 字节：湿度 20 位在前，温度 20 位在后 */
    uint32_t raw_h = ((uint32_t)buf[1] << 12) | ((uint32_t)buf[2] << 4) | (buf[3] >> 4);
    uint32_t raw_t = (((uint32_t)buf[3] & 0x0F) << 16) | ((uint32_t)buf[4] << 8) | buf[5];

    *rh_pct = 100.0f  * (float)raw_h / 1048576.0f;                 /* 2^20 = 1048576 */
    *t_c    = -50.0f + 200.0f * (float)raw_t / 1048576.0f;   /* AHT20: T = raw/2^20*200 - 50，系数用宏，方便按手册改 */
    return 0;
}
/* USER CODE END 0 */
```

**4. 显示 + 超限告警**（每秒刷新一次，不定长清屏）

```c
/* USER CODE BEGIN 2 */
oled_init();                                /* 内部已清屏 */
aht20_init();
uint32_t t_refresh = 0;
/* USER CODE END 2 */

while (1)
{
    uint32_t now = HAL_GetTick();

    if (now - t_refresh >= 1000)            /* 每秒刷新一次 */
    {
        t_refresh = now;

        float t = 0.0f, h = 0.0f;
        if (aht20_read(&t, &h) == 0)
        {
            /* 拆成整数位/小数位，用整数打印（Keil 的 %f 需要额外设置，见下） */
            int t_i = (int)t;
            int t_f = (int)((t - (float)t_i) * 10.0f);
            if (t_f < 0) t_f = -t_f;        /* 负温度时小数部分取绝对值 */

            oled_set_pos(0, 0);
            oled_printf("T=%d.%dC    ", t_i, t_f);      /* 定长，前面不补零也不会残影 */
            oled_set_pos(2, 0);
            oled_printf("RH=%d%%     ", (int)h);

            /* 超限告警：温度 > 30℃ 时第 4 页显示 ALERT（共 13 个字符，定长覆盖）*/
            oled_set_pos(4, 0);
            if (t > 30.0f) oled_print("ALERT        ", 13);
            else           oled_print("             ", 13);

            printf("[AHT20] T=%.2f C  RH=%.2f %%\r\n", (double)t, (double)h);
        }
        else
        {
            oled_set_pos(0, 0);
            oled_print("Sensor ERR   ", 13);   /* 读失败也要有反馈，程序不能卡死 */
            printf("[AHT20] read failed\r\n");
        }
    }
}
```

> **Keil 里 `printf` 打印 `%f`**：在 `Options for Target` → `Target` 里勾选 **Use MicroLIB**（否则 `%f` 可能输出空白或异常）。上面的显示代码把温度和湿度拆成整数字节打印，就是为了让屏上显示不依赖浮点 printf；串口那行 `%.2f` 才需要 MicroLIB。

### 验证方法

- 串口扫描同时出现 `0x3C` 与 `0x38`
- 屏上温度、湿度每秒刷新，且与串口打印**一致**（与参考温度计比对，误差 ≤ 0.5℃）
- 手指捏住传感器 → 温度上升；对着它哈气 → 湿度上升
- **温度超过 30℃ 时屏上出现 `ALERT`**；降回 30℃ 以下自动消失（可用手掌捂热或吹风机验证）
- 拔掉传感器 → 屏上显示 `Sensor ERR`、串口打印 `read failed`，程序不卡死

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 扫描不到 `0x38` | 接线 / 共地 / 供电 | 重扫；量 VCC；确认 SDA/SCL 没接反 |
| 读回状态 bit7 一直为 1 | 没等够 80ms 或没发触发命令 | 检查命令与 `HAL_Delay(80)` |
| 温湿度一直是 0 或乱值 | 6 字节拼接顺序错 | 对照上面的 `raw_h` / `raw_t` 公式 |
| 温度明显偏高 | 传感器自热（贴着 MCU/稳压器） | 挪开一点，别用手一直捏着 |
| 界面卡住不刷新 | `aht20_read` 失败后没处理返回值 | 加错误分支（见上面 `Sensor ERR`）|

## 附录 A · 最小可运行的 SSD1306 I2C 驱动

> 这份驱动**绑定本文硬件**：I2C1（PB6=SCL / PB7=SDA）、0.96 寸 128×64、SSD1306、7 位地址 `0x3C`。
> 把 `oled.h` + `oled.c` 两个文件分别放进 `Core/Inc`、`Core/Src`，Keil 里 `Add Existing Files` 加入工程，**不改一行就能编译**（前提：CubeMX 已生成 `i2c.h` 与 `hi2c1`）。

### A.1 硬件与地址约定

| 项 | 值 |
|---|---|
| 总线 | I2C1，PB6 = SCL，PB7 = SDA |
| 屏 | 0.96" 128×64，驱动芯片 SSD1306 |
| 7 位地址 | `0x3C`（A1 扫描打印的就是它） |
| 8 位地址 | `0x3C << 1 = 0x78`（HAL 的 `DevAddress` 参数要 8 位形式） |

**为什么会有两个地址**：I2C 一帧是「7 位地址 + 1 位读写位」共 8 位。HAL 库的 `DevAddress` 参数要求**已经左移好的 8 位形式**（`0x78`），而串口扫描、模块资料、逻辑分析仪上看到的多半是 **7 位**（`0x3C`）。记住一句：**`0x78 == 0x3C << 1`，是同一个设备的两种写法**——填错就永远收不到 ACK，表现就是"屏全黑、扫描不到"。

**控制字节**：SSD1306 在 I2C 上没有"寄存器地址"，每次传输的**第一个字节是控制字节**：

| 控制字节 | 含义 |
|---|---|
| `0x00` | 后面跟的全是**命令**（Co=0，D/C#=0） |
| `0x40` | 后面跟的全是**显存数据**（Co=0，D/C#=1） |

所以"发命令"＝先发 `0x00` 再发命令字节；"写显存"＝先发 `0x40` 再发数据字节。HAL 的 `HAL_I2C_Mem_Write(句柄, 从机地址, MemAddress, ...)` 里的 `MemAddress` 参数，正好就是那个控制字节——下面的 `oled_cmd()` / `oled_data()` 就是干这个的。

### A.2 oled.h

```c
/* ============================================================
 * oled.h —— SSD1306 128×64 / I2C1 / 7 位地址 0x3C
 * 配套教程：tutorials/P07-I2C与传感器.md 附录 A
 * ============================================================ */
#ifndef __OLED_H
#define __OLED_H

#include <stdint.h>
#include <stddef.h>

/* 7 位地址：A1 扫描打印的就是它（HAL 里要 8 位形式，见 oled.c） */
#define OLED_ADDR_7BIT   0x3C

void oled_init(void);                          /* 初始化 + 清屏 */
void oled_clear(void);                         /* 清全屏 */
void oled_set_pos(uint8_t page, uint8_t col);  /* 定位：页 0~7，列 0~127 */
void oled_print(const char *str, size_t len);  /* 写字符串（6×8 字模） */
```

### A.3 oled.c

```c
/* ============================================================
 * oled.c —— 最小可运行的 SSD1306 I2C 驱动（128×64）
 * 硬件绑定：I2C1（PB6=SCL / PB7=SDA），7 位地址 0x3C
 * 依赖：CubeMX 已生成 i2c.h 与 I2C_HandleTypeDef hi2c1
 * ============================================================ */
#include "oled.h"
#include "i2c.h"
#include <stdio.h>
#include <stdarg.h>

/* 8 位寻址形式 = 7 位地址 << 1 = 0x78；HAL 的 DevAddress 参数要这种形式 */
#define OLED_ADDR8       (OLED_ADDR_7BIT << 1)

/* 控制字节：0x00 = 后面是命令，0x40 = 后面是显存数据 */
#define OLED_CTRL_CMD    0x00
#define OLED_CTRL_DATA   0x40

static uint8_t s_page = 0;      /* 当前写入页 0~7 */
static uint8_t s_col  = 0;      /* 当前写入列 0~127 */

/* ---------------- 底层两个函数 ---------------- */
/* 发命令：MemAddress 就是控制字节 0x00，HAL 会先发 0x00 再发 cmd 里的字节 */
static void oled_cmd(const uint8_t *cmd, uint16_t len)
{
    if (HAL_I2C_Mem_Write(&hi2c1, OLED_ADDR8, OLED_CTRL_CMD,
                          I2C_MEMADD_SIZE_8BIT, (uint8_t *)cmd, len, 50) != HAL_OK)
    {
        __NOP();                /* 通信失败：调试时在这里下断点 */
    }
}

/* 写显存：控制字节 0x40 */
static void oled_data(const uint8_t *data, uint16_t len)
{
    if (HAL_I2C_Mem_Write(&hi2c1, OLED_ADDR8, OLED_CTRL_DATA,
                          I2C_MEMADD_SIZE_8BIT, (uint8_t *)data, len, 50) != HAL_OK)
    {
        __NOP();
    }
}

/* ---------------- 初始化 ---------------- */
void oled_init(void)
{
    static const uint8_t init_cmds[] = {
        0xAE,        /* 关显示（配置期间先关，避免花屏） */
        0xD5, 0x80,  /* 时钟分频 / 振荡频率 */
        0xA8, 0x3F,  /* 复用率 = 64 行（0x3F = 63，即 64 行） */
        0xD3, 0x00,  /* 显示垂直偏移 = 0 */
        0x40,        /* 显示起始行 = 0 */
        0x8D, 0x14,  /* 电荷泵：0x14 = 开（不开屏不会亮！） */
        0x20, 0x00,  /* 显存寻址模式 = 页寻址 */
        0xA1,        /* 段重映射：列 127 → SEG0（左右方向） */
        0xC8,        /* COM 扫描方向：COM63 → COM0（上下方向） */
        0xDA, 0x12,  /* COM 引脚硬件配置：交替 + 禁用左右反转 */
        0x81, 0xCF,  /* 对比度 = 0xCF */
        0xD9, 0xF1,  /* 预充电周期 */
        0xDB, 0x40,  /* VCOMH 反压 */
        0xA4,        /* 显示跟随显存（0xA5 = 全亮，测试用） */
        0xA6,        /* 正常显示（0xA7 = 反色） */
        0x2E,        /* 关闭滚动 */
        0xAF,        /* 开显示 */
    };

    /* 每条命令前都要先发控制字节 0x00——由 oled_cmd() 负责。
       严格说一个 0x00 后面可以连续跟多条命令，这里逐条发，是为了让你在
       逻辑分析仪上看到"每个命令字节前面都有一个 0x00"。想省传输可以改成
       一次发完：oled_cmd(init_cmds, sizeof(init_cmds)); */
    for (uint16_t i = 0; i < sizeof(init_cmds); i++)
        oled_cmd(&init_cmds[i], 1);

    oled_clear();
}

/* ---------------- 定位与清屏 ---------------- */
void oled_set_pos(uint8_t page, uint8_t col)
{
    page &= 0x07;       /* 128×64 只有 8 页 */
    col  &= 0x7F;       /* 只有 128 列 */
    s_page = page;
    s_col  = col;

    /* 页地址命令 0xB0~0xB7；列地址拆成低 4 位、高 4 位两次发 */
    uint8_t cmds[3] = {
        (uint8_t)(0xB0 | page),                 /* 0xB0 + 页号 */
        (uint8_t)(0x00 | (col & 0x0F)),         /* 列地址低 4 位：0x00~0x0F */
        (uint8_t)(0x10 | ((col >> 4) & 0x0F)),  /* 列地址高 4 位：0x10~0x1F */
    };
    oled_cmd(cmds, 3);
}

void oled_clear(void)
{
    static const uint8_t zeros[128] = {0};
    for (uint8_t p = 0; p < 8; p++)
    {
        oled_set_pos(p, 0);
        oled_data(zeros, sizeof(zeros));    /* 每页 128 字节全写 0 */
    }
    oled_set_pos(0, 0);
}

/* 查表：表里没有的字符按空格处理（显示空白，不会出现乱码花纹） */
static const uint8_t *font6x8_get(char c)
{
    for (uint32_t i = 0; i < sizeof(FONT6x8) / sizeof(FONT6x8[0]); i++)
    {
        if (FONT6x8[i].ch == c) return FONT6x8[i].col;
    }
    return FONT6x8[0].col;
}

/* ---------------- 写字符串 ---------------- */
void oled_print(const char *str, size_t len)
{
    for (size_t i = 0; i < len; i++)
    {
        char c = str[i];

        if (c == '\n' || c == '\r')          /* 换行：下一页第 0 列 */
        {
            s_page = (uint8_t)((s_page + 1) & 0x07);
            oled_set_pos(s_page, 0);
            continue;
        }

        oled_data(font6x8_get(c), 6);        /* 一个字符写 6 列 */
        s_col = (uint8_t)(s_col + 6);

        if (s_col > 122)                     /* 到右边界：自动换到下一页 */
        {
            s_col = 0;
            s_page = (uint8_t)((s_page + 1) & 0x07);
            oled_set_pos(s_page, 0);
        }
    }
}

/* ---------------- 格式化打印 ---------------- */
void oled_printf(const char *fmt, ...)
{
    char buf[64];
    va_list ap;

    va_start(ap, fmt);
    int n = vsnprintf(buf, sizeof(buf), fmt, ap);
    va_end(ap);

    if (n <= 0) return;
    if ((size_t)n >= sizeof(buf)) n = (int)sizeof(buf) - 1;   /* 超长截断 */
    oled_print(buf, (size_t)n);
}
```

### A.4 `oled_init` 的命令表逐条说明

整条命令序列（每个字节前都由 `oled_cmd()` 补一个控制字节 `0x00`）：

```
0xAE, 0xD5, 0x80, 0xA8, 0x3F, 0xD3, 0x00, 0x40,
0x8D, 0x14, 0x20, 0x00, 0xA1, 0xC8, 0xDA, 0x12,
0x81, 0xCF, 0xD9, 0xF1, 0xDB, 0x40, 0xA4, 0xA6,
0x2E, 0xAF
```

| 命令 | 作用 | 少了它会怎样 |
|---|---|---|
| `0xAE` | 关闭显示 | 配置过程中屏上会出现花屏 |
| `0xD5 0x80` | 设置时钟分频 / 振荡频率 | 刷新异常、亮度不稳 |
| `0xA8 0x3F` | 设置复用率 = 64 行 | 只亮一半 / 上下压缩 |
| `0xD3 0x00` | 显示垂直偏移 = 0 | 整屏上下错位 |
| `0x40` | 显示起始行 = 0 | 画面整体滚动 |
| `0x8D 0x14` | **电荷泵使能** | **屏不亮（最常见白屏原因之一）** |
| `0x20 0x00` | 显存寻址模式 = 页寻址 | 数据写乱 |
| `0xA1` | 段重映射（左右方向）| 画面左右镜像 |
| `0xC8` | COM 扫描方向（上下方向）| 画面上下颠倒 |
| `0xDA 0x12` | COM 引脚硬件配置 | 显示出现横条/闪烁 |
| `0x81 0xCF` | 对比度 = 0xCF | 太暗或太亮 |
| `0xD9 0xF1` | 预充电周期 | 亮度不均 |
| `0xDB 0x40` | VCOMH 反压 | 残影、对比度不足 |
| `0xA4` | 显示跟随显存 | 屏上会全亮（0xA5 的测试模式）|
| `0xA6` | 正常显示（非反色）| 黑白颠倒 |
| `0x2E` | 关闭滚动 | 画面自己滚动 |
| `0xAF` | **开显示** | 屏一直黑 |

**页/列寻址怎么下**（写在 `oled_set_pos()` 里，命令为 `0xB0~0xB7`）：

| 命令 | 含义 |
|---|---|
| `0xB0 + page`（page = 0~7） | 选中第几页（一页 = 8 行像素）|
| `0x00 + (col & 0x0F)` | 列地址**低 4 位**（0x00~0x0F）|
| `0x10 + ((col >> 4) & 0x0F)` | 列地址**高 4 位**（0x10~0x1F）|

SSD1306 的列地址是 0~127，但命令只能带 4 位，所以要分两次发：`col = 37` → 低 4 位 `5` 发 `0x05`，高 4 位 `2` 发 `0x12`。写完一页的 128 字节后列地址会自动回到该页第 0 列（页寻址模式）。

### A.5 字模怎么生成（换成你要显示的字符）

附录 A 的 `FONT6x8` 只是**示例子集**（够显示 `Hello STM32!`、`Counter:`、`T=25.3C`、`RH=60%`、`ALERT` 这些）。要显示别的字符，用取模软件补齐：

1. 下载 **PCtoLCD2002**（常用免费字模软件）
2. 模式设置（**必须和驱动一致**，否则乱码/颠倒）：

   | 选项 | 选 |
   |---|---|
   | 字模选项 | **阴码** |
   | 取模方式 | **逐列式** |
   | 取模走向 | **顺向**（bit0 在上）|
   | 输出格式 | **十六进制** |
   | 自定义格式 | **C51 格式** |
   | 字宽×字高 | **6×8**（点阵 5×7 + 1 列间距）|

3. 在输入框里填要生成的字符（如 `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz`），点"生成字模"
4. 把生成的字节**按同样的格式**填进 `FONT6x8[]`：每个字符 6 个字节，例如

   ```c
   { 'H', {0x7F,0x08,0x08,0x08,0x7F,0x00} },   /* 阴码/逐列/顺向 生成的样子 */
   { 'e', {0x38,0x54,0x54,0x54,0x18,0x00} },
   { 'l', {0x00,0x41,0x7F,0x40,0x00,0x00} },
   { 'o', {0x38,0x44,0x44,0x44,0x38,0x00} },
   ```

**怎么验证取模方向对不对**：先只生成一个 `H` 写进屏。如果显示成上下颠倒的 `H`，说明"顺向/逆向"选反了；如果左右颠倒，改 `0xA1` 为 `0xA0`。

### A.6 点亮自检清单（屏不亮时按顺序过）

| # | 检查 | 期望 |
|---|---|---|
| 1 | A1 的扫描能不能看到 `0x3C` | 能看到 → I2C 通了；看不到 → 回去查接线/上拉/供电 |
| 2 | `OLED_ADDR_7BIT` 是不是 `0x3C`，代码里用的是不是 `0x3C << 1` | 8 位形式 = `0x78` |
| 3 | 初始化命令里有没有 `0x8D, 0x14`（电荷泵） | 没有 → 屏永远不亮 |
| 4 | 有没有 `0xAF`（开显示） | 没有 → 一直黑屏 |
| 5 | 写完显存后有没有等一小会儿再断电 | 上电初始化后调一次 `oled_clear()` |
| 6 | Keil 里 `printf("%f")` 是否异常 | `Options for Target` → `Target` → 勾 **Use MicroLIB** |
