## 0 · 开工前的准备

### 0.1 I2C 是什么

**I2C 是两线总线**：一条时钟线 **SCL** + 一条数据线 **SDA**。多设备并联在同一条总线上，靠**地址**区分。

```
        ┌──── 3.3V
        │
       ┌┴┐     上拉电阻（必须！）
       │ │ 4.7kΩ
       └┬┘
        ├──────────────┬──────────────┐
   SCL ─┴──────────────┼──────────────┤
                       │              │
   SDA ────────────────┼──────────────┤
                       │              │
                   ┌───┴───┐     ┌────┴────┐
                   │  MCU  │     │  OLED   │
                   └───────┘     └─────────┘
```

**⭐ 最关键的一点：SDA 和 SCL 必须接上拉电阻**（常见 4.7kΩ）。

为什么：I2C 的引脚是"开漏"输出——只能把线**拉低**，不能主动拉高。所以必须有上拉电阻把线拉高。**没有上拉电阻，总线永远拉不高，通信必然失败。**

> 好消息：大多数 OLED 模块**板上已经自带上拉电阻**，直接接线即可。但如果扫描不到设备，**第一件事就是检查上拉**。

### 0.2 引脚选择

F103 的 I2C1 默认引脚：

| 信号 | 引脚 |
|---|---|
| SCL | **PB6** |
| SDA | **PB7** |

### 0.3 本项目的硬件连接

| OLED 引脚 | 接到 |
|---|---|
| VCC | 3.3V |
| GND | GND |
| SCL | PB6 |
| SDA | PB7 |

## A1 · I2C 扫描总线设备

**任务**：配置硬件 I2C（速率 100kHz 或 400kHz），用 I2C 扫描程序遍历地址段，把总线上所有响应设备地址打印出来。

### 知识点

**I2C 通信的基本单元**：

```
起始条件 → [地址(7位) + 读写位] → [ACK] → [数据] → [ACK] → ... → 停止条件
```

**ACK 是什么**：主机发出地址后，如果总线上某个设备认识这个地址，它会**把 SDA 拉低**一个时钟周期作为应答（ACK）。**扫描程序就是靠"有没有 ACK"来判断设备是否存在。**

**地址的两种写法**：

| 写法 | 例子 | 说明 |
|---|---|---|
| 7 位地址 | `0x3C` | 编程实际用的 |
| 8 位地址 | `0x78` | 驱动资料里常见，= 7 位地址 << 1 |

扫描程序一般打印 **8 位地址**（`0x78`）或 7 位（`0x3C`），两者差一位左移，别被绕晕。

### 操作步骤

1. CubeMX → `Connectivity` → **`I2C1`** → `I2C` 选 **`I2C`**
2. `Parameter Settings` 设：

   | 参数 | 值 |
   |---|---|
   | `I2C Speed Mode` | Standard Mode（100kHz）或 Fast Mode（400kHz） |
   | `Clock Speed` | 100000 或 400000 |
   | `Fast Mode Duty Cycle` | 2（Fast Mode 时） |

3. 确认引脚图里 **PB6/PB7 变绿**
4. `GENERATE CODE`

扫描程序（放 `main.c`，主循环前调用一次即可）：

```c
/* USER CODE BEGIN 0 */
#include <stdio.h>

/* 扫描 I2C1 总线上所有应答的设备，返回找到的个数 */
static uint8_t i2c_scan(void)
{
    uint8_t found = 0;
    printf("I2C scan start (7-bit addr):\r\n");

    for (uint8_t addr = 0x08; addr <= 0x77; addr++)     /* 7 位地址有效范围 */
    {
        /* HAL_I2C_IsDeviceReady(句柄, 地址<<1, 试几次, 超时ms) */
        if (HAL_I2C_IsDeviceReady(&hi2c1, (uint16_t)(addr << 1), 2, 10) == HAL_OK)
        {
            printf("  found device @ 0x%02X (8-bit 0x%02X)\r\n",
                   addr, (uint8_t)(addr << 1));
            found++;
        }
    }
    printf("I2C scan done, %u device(s) found.\r\n", found);
    return found;
}
/* USER CODE END 0 */
```

在 `/* USER CODE BEGIN 2 */` 里调用：

```c
HAL_Delay(100);        /* 等 OLED 内部复位 */
i2c_scan();
```

### 验证方法

- 串口打印出扫描结果，**至少找到一个设备**（OLED 一般是 `0x3C` 或 `0x78`）
- 记下这个地址——后面驱动 OLED 要用

```
I2C scan start (7-bit addr):
  found device @ 0x3C (8-bit 0x78)
I2C scan done, 1 device(s) found.
```

### 常见问题

**⭐ 扫描不到任何设备**（按顺序排查）：

| # | 检查项 | 怎么查 |
|---|---|---|
| 1 | 上拉电阻有没有 | 量 SDA/SCL 对 3.3V 的阻值；模块自带也可能失效 |
| 2 | SDA/SCL 接反了吗 | 交换两根线再试 |
| 3 | 屏供电了吗 | 量 VCC 引脚电压是否 3.3V |
| 4 | 引脚配对了没 | CubeMX 里确认 PB6/PB7 变绿 |
| 5 | 总线空闲时是否为高电平 | 用万用表量 SDA/SCL 静态电压，应是 3.3V |

| 其他现象 | 原因 | 怎么办 |
|---|---|---|
| 扫出一堆不存在的地址 | 缺上拉，总线一直被读成低电平 | 补上拉电阻 |
| 扫到 0x00 | 同上 | 同上 |
| 时好时坏 | 接线接触不良 | 焊一下或换杜邦线 |

## A2 · 驱动 OLED 显示字符串

**任务**：用硬件 I2C 驱动一块 OLED 屏，在屏上显示一行英文字符串。

### 知识点

**OLED 不是"发什么显什么"**：它内部有一块**显存（GDDRAM）**，按"页（Page）"组织：

```
显存结构（128×64 常见）：
  Page0:  128 字节，每字节的低 8 位对应 8 行像素
  Page1:  128 字节
  ...
  Page7:  128 字节
  → 8 页 × 128 字节 = 1024 字节
```

**显示字符要做两件事**：
1. **取字模**：把字符的点阵（每个像素用一位表示）从字模表里取出来
2. **写显存**：把点阵数据按页写进 OLED 的显存

**⭐ 字模取模方式必须与驱动代码一致**：取模软件里有"逐行/逐列"、"高位在前/在后"的选项。选错了显示出来就是**乱码或上下颠倒的花纹**——这是新手最常卡的地方。

### 操作步骤

**1. 准备驱动代码**

OLED 驱动代码较长（初始化命令序列 + 写显存 + 字模表），有几个来源：

| 来源 | 说明 |
|---|---|
| **卖家提供的例程** | 最省事，直接移植（改 I2C 句柄即可） |
| 开源 OLED 驱动库 | 搜"SSD1306 STM32 HAL"，注意确认是 I2C 版不是 SPI 版 |

移植要点：

| 要改的地方 | 改成 |
|---|---|
| I2C 句柄 | `&hi2c1` |
| 从机地址 | 你扫出来的（若库用 8 位地址，填 `0x78`；用 7 位填 `0x3C`） |
| 延时函数 | `HAL_Delay` |

**2. 把驱动文件加进工程**

把 `oled.c` / `oled.h` 放进 `Core/Src`、`Core/Inc`，在 Keil 里 `Add Existing Files` 加入工程。

**3. 主程序调用**

```c
/* USER CODE BEGIN Includes */
#include "oled.h"
/* USER CODE END Includes */

/* USER CODE BEGIN 2 */
OLED_Init();
OLED_Clear();
OLED_ShowString(0, 0, "Hello STM32!", 16);   /* (x, y, 字符串, 字号) */
/* USER CODE END 2 */
```

### 验证方法

- 屏上显示出 `Hello STM32!`，字符清晰、方向正确（不是花纹、不是倒的）
- 按复位键能重复显示

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 全黑毫无反应 | I2C 没通 / 地址错 / 初始化没调 | 先跑 A1 扫描确认设备在 |
| 乱码花纹 | 字模取模方式不对 | 改取模软件设置，或改驱动的位处理顺序 |
| 上下颠倒 | 扫描方向反了 | 改 `OLED_Init` 里的扫描方向命令 |
| 显示一半就花了 | 显存写入越界 | 检查页地址/列地址范围 |
| 亮一下又灭 | 初始化序列不完整 | 用卖家给的完整初始化序列 |

## A3 · 显示自增计数器

**任务**：在 OLED 上显示一个每秒自增的计数器，连续观察 1 分钟不出现花屏、跳字或卡死。

### 知识点

**刷新的正确做法**：

```c
/* 错误：每次都清全屏 → 屏闪，而且慢 */
OLED_Clear();
OLED_ShowNum(...);

/* 正确：只更新那个区域（定长显示 + 补零），不清屏 */
OLED_ShowNum(0, 2, count, 6, 16);   /* 固定 6 位宽，前面补零 */
```

**为什么定长显示**：如果数字位数会变（`1` → `10` → `100`），不清屏就会留下旧数字的残迹（比如 `9` 变成 `10` 时留下 `90`）。定长补零能避免。

### 操作步骤

```c
/* USER CODE BEGIN 2 */
OLED_Init();
OLED_Clear();
OLED_ShowString(0, 0, "Counter:", 16);

uint32_t t_1s   = 0;
uint32_t count  = 0;
/* USER CODE END 2 */

while (1)
{
    /* USER CODE BEGIN 3 */
    uint32_t now = HAL_GetTick();          /* 若 P05 已配 TIM2，可改用 tick_1ms */

    if (now - t_1s >= 1000)               /* 每秒一次 */
    {
        t_1s = now;
        count++;
        OLED_ShowNum(0, 2, count, 6, 16);  /* 固定 6 位宽，自动补零 */
    }
    /* USER CODE END 3 */
}
```

### 验证方法

- 计数器每秒 +1，连续跑 **1 分钟**（到 60）不花屏、不跳字、不卡死
- 数字前补零（如 `000012`），位数不变
- 观察时屏上没有闪烁感

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 数字后面有残影 | 没定长显示，旧位数没擦掉 | 用定长 + 补零 |
| 计数不准 | 用了 `HAL_Delay(1000)` 阻塞，或有其他耗时 | 用 tick 判断；检查循环里有无阻塞 |
| 跑一会儿花屏 | 显存写入越界或 I2C 出错 | 加 I2C 错误重试；检查坐标范围 |
| 整屏闪 | 每帧都 `OLED_Clear` | 去掉全屏清，只更新局部 |

## A4 · 串口同步打印

**任务**：把 OLED 的显示内容通过串口同步打印一份，两份内容保持一致（用于离线核对）。

### 知识点

**为什么要有这个**：OLED 是硬件显示，做实验记录/截图时不好保留数据。串口日志能导出、能贴进报告、能事后核对——**它是你的"证据"**。

### 操作步骤

```c
if (now - t_1s >= 1000)
{
    t_1s = now;
    count++;

    OLED_ShowNum(0, 2, count, 6, 16);
    printf("[OLED] Counter = %lu\r\n", (unsigned long)count);   /* 同步打印 */
}
```

**核对方法**：跑 30 秒，对比屏上的数字与串口最后一行是否一致；中途抽 3 次点对点核对。

| 核对时点 | OLED 显示 | 串口打印 | 一致？ |
|---|---|---|---|
| 第 10 秒 | | | ✅/❌ |
| 第 20 秒 | | | |
| 第 30 秒 | | | |

### 验证方法

- 串口打印的数值与屏上显示**始终一致**
- 打印带 `[OLED]` 前缀，便于在混杂日志里筛选
- 保留串口日志作为交付证据

## B1 · 多页菜单

**任务**：在 OLED 上做一个多页菜单：至少 3 个页面，用按键上下翻页、当前选中项高亮显示。

### 知识点

**菜单的三个组成**：

| 组成 | 说明 |
|---|---|
| 页面/条目列表 | 有哪几项 |
| 当前选中索引 | 现在选中第几项 |
| 翻页规则 | 到头后循环还是停住（本项目**循环**）|

**避免闪烁的关键**：只在**选中项变化时**重绘，不要每轮循环都重绘整屏。

### 操作步骤

```c
/* USER CODE BEGIN 0 */
#define MENU_CNT   3

static const char *menu_items[MENU_CNT] = {
    "1. LED Control",
    "2. Brightness",
    "3. About",
};
static uint8_t menu_sel = 0;

static void menu_draw(void)
{
    for (uint8_t i = 0; i < MENU_CNT; i++)
    {
        /* 选中项前面加 ">"，并可用反色高亮；这里用简单标记 */
        char line[20];
        snprintf(line, sizeof(line), "%c%s", (i == menu_sel) ? '>' : ' ', menu_items[i]);
        OLED_ShowString(0, i * 2, line, 16);
    }
}

static void menu_move(int8_t dir)
{
    if (dir > 0) menu_sel = (menu_sel + 1) % MENU_CNT;                 /* 下 */
    else         menu_sel = (menu_sel + MENU_CNT - 1) % MENU_CNT;     /* 上（循环）*/
    menu_draw();
}
/* USER CODE END 0 */
```

配合 P04 的按键事件取用：

```c
/* 用两个按键（或一个按键的短按/长按）翻页 */
key_evt_t e = key_get_event();
if (e == KEY_EVT_SHORT)  menu_move(+1);      /* 短按下一项 */
if (e == KEY_EVT_LONG)   menu_move(-1);      /* 长按上一项 */
```

### 验证方法

- 3 个条目都能显示，当前选中项有明确标记
- 按按键能上下切换，**到最后一页再按能回到第一页**
- 翻页响应 ≤200ms，屏上无明显闪烁
- 选中标记与实际索引一致

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 翻页闪屏 | 每次都 `OLED_Clear` + 全屏重绘 | 只重绘变化的行 |
| 到头卡住 | 用了 `menu_sel++` 没做环绕 | 用 `% MENU_CNT` 取模 |
| 上一个选中标记没擦掉 | 重绘时没覆盖旧标记位置 | 整行重绘（含前导空格） |
| 按键连跳好几项 | 没去抖 | 复用 P04 的状态机 |

## B2 · 示波器看 I2C 时序

**任务**：用示波器抓 SDA 与 SCL 波形，在图上标出起始条件、地址字节、ACK 位、停止条件各在哪一段。

### 知识点

**I2C 四个关键时序点**：

| 事件 | 特征 |
|---|---|
| **起始条件（Start）** | SCL 为**高**时，SDA **由高变低** |
| **地址字节** | 起始条件后的 8 个时钟：7 位地址 + 1 位读写位 |
| **ACK** | 第 9 个时钟周期，**从机把 SDA 拉低** |
| **停止条件（Stop）** | SCL 为**高**时，SDA **由低变高** |

```
        Start                            ACK          Stop
SDA ────┐   ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌───┐  ┌────
        └───┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘   └──┘
             A6  A5  A4  A3  A2  A1  A0  R/W   ↑
                                           从机拉低
SCL ──┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌──
      └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘ └─┘
```

### 操作步骤

1. **示波器需要两个通道**：CH1 接 **SCL**、CH2 接 **SDA**，两个夹子都接 GND
2. 设置：
   - 探头衰减 **×1**
   - 时基 **10μs/格** 左右（100kHz 时，一个时钟周期 10μs）
   - 电压 **1V/格**
   - 触发：**CH1 下降沿** 或 **CH2 下降沿**，电平 1.6V
3. 用**单次触发（Single）** 抓一次通信（可以让程序只做一次 OLED 刷新）
4. 在波形图上标注四个位置，截图
5. 写进 README：

| 时序点 | 在图上什么位置 | 特征 |
|---|---|---|
| 起始条件 | | SCL 高时 SDA 下降 |
| 地址字节 | | 起始后 8 个时钟 |
| ACK 位 | | 第 9 个时钟，SDA 被从机拉低 |
| 停止条件 | | SCL 高时 SDA 上升 |

> **没有示波器怎么办**：用**逻辑分析仪**（若能借到，25 元的 8 通道就够）；或用**软件 I2C + GPIO 翻转打点**，用示波器单通道分别看 SDA/SCL。也可以降低 I2C 速率到 10kHz 让波形更容易抓。

### 验证方法

- 抓到了清晰的双通道波形
- 四个时序点都标注出来，且标注位置正确
- 能口头讲清"ACK 是怎么看出来的"（第 9 个时钟 SDA 被拉低）

## B3 · 驱动封装成模块

**任务**：把 OLED 驱动封装成独立模块（`.c` / `.h` 分离，对外只暴露 `oled_init`、`oled_print`、`oled_clear` 等接口），主程序里不出现任何 I2C 底层调用。

### 知识点

**判断封装是否到位**：**主程序里搜不到 `HAL_I2C_`**。所有 I2C 细节都关在驱动里。这样做的价值：

| 好处 | 说明 |
|---|---|
| 换屏只改驱动 | 换驱动芯片/换 SPI 接口，应用层不动 |
| 换 MCU 只改驱动 | 从 F103 换到别的芯片，只重写驱动 |
| 应用层好读 | `oled_print("Hello")` 比一串 I2C 调用清楚得多 |

### 操作步骤

**`oled.h`**（对外接口）：

```c
#ifndef __OLED_H
#define __OLED_H

#include <stdint.h>

/* 初始化屏：内部完成 I2C 初始化后的首次配置 */
void oled_init(void);

/* 清屏 */
void oled_clear(void);

/* 在指定位置显示字符串（英文），x: 0~127, y: 页 0~7 */
void oled_print(uint8_t x, uint8_t page, const char *str);

/* 在指定位置显示定长数字（前面补零） */
void oled_print_num(uint8_t x, uint8_t page, uint32_t num, uint8_t digits);

#endif
```

**`oled.c`**（实现，包含所有 I2C 细节）：

```c
#include "oled.h"
#include "i2c.h"        /* CubeMX 生成的 I2C 句柄 */
#include "oled_font.h"  /* 字模表 */

#define OLED_ADDR   0x78    /* 8 位地址形式，按你扫描到的改 */

static void oled_write_cmd(uint8_t cmd)
{
    uint8_t buf[2] = { 0x00, cmd };          /* 0x00 = 命令 */
    HAL_I2C_Master_Transmit(&hi2c1, OLED_ADDR, buf, 2, 100);
}

static void oled_write_data(uint8_t *data, uint16_t len)
{
    /* 控制字节 0x40 = 数据，需要连同数据一起发 */
    static uint8_t buf[129];
    buf[0] = 0x40;
    for (uint16_t i = 0; i < len && i < 128; i++) buf[i + 1] = data[i];
    HAL_I2C_Master_Transmit(&hi2c1, OLED_ADDR, buf, len + 1, 200);
}

void oled_init(void)  { /* 初始化命令序列（照卖家例程） */ }
void oled_clear(void) { /* 全页写 0x00 */ }
void oled_print(uint8_t x, uint8_t page, const char *str) { /* 取字模 + 写显存 */ }
void oled_print_num(uint8_t x, uint8_t page, uint32_t num, uint8_t digits) { /* 补零 */ }
```

主程序变得很干净：

```c
/* USER CODE BEGIN Includes */
#include "oled.h"
/* USER CODE END Includes */

/* USER CODE BEGIN 2 */
oled_init();
oled_clear();
oled_print(0, 0, "STM32 Ready");
oled_print_num(0, 2, 12345, 6);
/* USER CODE END 2 */
```

### 验证方法

- **主程序（`main.c` 的业务部分）里搜不到 `HAL_I2C_`**——这就是封装到位的证据
- `oled.h` 的接口不超过 5~6 个函数（对外接口要少而清晰）
- 功能正常
- 评审时能指出"如果要换 SPI 的屏，只需改 `oled.c` 内部"

## B4 · 换屏测试

**任务**：做一个"换屏测试"：修改驱动模块里的初始化序列与分辨率参数，适配另一款不同驱动芯片的 OLED（或说明若换成 SPI 接口的屏需要改哪几处）。

### 知识点

**换屏要改什么**——取决于"换的是什么"：

| 换屏类型 | 要改的地方 |
|---|---|
| **同驱动芯片，不同尺寸**（如 128×64 → 128×32） | 分辨率宏、页数、初始化序列里的复用率设置 |
| **不同驱动芯片**（SSD1306 → SH1106） | 初始化命令序列（不同芯片命令不同）、列地址偏移（SH1106 有 2 列偏移）|
| **I2C → SPI 接口** | 重写底层收发函数（`oled_write_cmd/data` 改为 SPI 发送）、增加 DC/RES/CS 引脚控制 |

**关键设计**：把所有"可能变的东西"抽成宏或配置表放在驱动文件顶部，换屏只改这几行。

### 操作步骤

在 `oled.c` 顶部做配置区：

```c
/* ==================== 屏配置区（换屏只改这里）==================== */
#define OLED_WIDTH      128
#define OLED_HEIGHT     64
#define OLED_PAGES      (OLED_HEIGHT / 8)     /* = 8 */

/* 驱动芯片选择：1=SSD1306  2=SH1106 */
#define OLED_DRIVER     SSD1306

#if (OLED_DRIVER == SH1106)
  #define OLED_COL_OFFSET   2     /* SH1106 显存列地址有 2 列偏移 */
#else
  #define OLED_COL_OFFSET   0
#endif
/* ================================================================= */
```

然后写一份"换屏改动说明"放进 README：

```markdown
## 换屏测试：需要改动的位置

| 目标 | 要改的地方 | 工作量 |
|---|---|---|
| 128×64 → 128×32（SSD1306） | `OLED_HEIGHT` 改 32；初始化序列里的复用率命令 | 2 行 |
| SSD1306 → SH1106 | `OLED_DRIVER` 改 SH1106；`OLED_COL_OFFSET` 改 2；初始化序列替换 | 1 个配置 + 1 段序列 |
| I2C → SPI 接口 | 重写 `oled_write_cmd` / `oled_write_data` 两个函数（改用 SPI 发送）；新增 DC/RES/CS 引脚控制 | 2 个函数 |
| 换 MCU 平台 | 只改 I2C 句柄来源（`i2c.h`）与发送函数 | 1 处 |

**结论**：应用层（`main.c` 里的 `oled_print` 调用）**完全不需要改动** —— 这就是 B3 封装的价值。
```

**若手头没有第二块屏**：把上表写清楚（任务允许"或说明…需要改哪几处"），并说明改动的理由。有条件的话改 `OLED_HEIGHT` 为 32 试一次，观察显示效果变化。

### 验证方法

- 给出了明确的"改动位置表"，每项都说得清为什么改
- 能讲清"I2C 换 SPI 要动哪两个函数"
- （若实际换了屏）新屏能正常显示

## B5 · 菜单控制工作参数

**任务**：用按键菜单控制 OLED 上显示的一个工作参数（如 LED 闪烁频率），实现"改设置 → 屏上立即反映"。

### 知识点

**"设置项"要落到实际行为**：光在屏上改个数字没有意义，要让参数**真的驱动某个硬件行为**（这里是 LED 闪烁频率）。这样才是完整的"人机交互闭环"：

```
按键 → 改参数 → ① 屏上显示更新  ② 硬件行为跟着变
```

### 操作步骤

```c
/* 可调参数：LED 闪烁的半周期（ms） */
static uint16_t led_half_ms = 500;
static const uint16_t half_ms_table[] = { 100, 200, 500, 1000 };   /* 4 档 */
#define HALF_MS_CNT  (sizeof(half_ms_table)/sizeof(half_ms_table[0]))
static uint8_t  half_ms_idx = 2;      /* 默认 500ms */

static void param_draw(void)
{
    char line[20];
    snprintf(line, sizeof(line), "LED: %4ums", led_half_ms);
    oled_print(0, 4, line);                       /* 屏上显示 */
    printf("[PARAM] led_half_ms = %u\r\n", led_half_ms);  /* 串口同步 */
}

/* 按键调节 */
key_evt_t e = key_get_event();
if (e == KEY_EVT_SHORT)                   /* 短按：切换档位 */
{
    half_ms_idx = (half_ms_idx + 1) % HALF_MS_CNT;
    led_half_ms = half_ms_table[half_ms_idx];
    param_draw();
}

/* LED 闪烁用当前参数（非阻塞写法，避免屏刷新受影响） */
static uint32_t t_led = 0;
uint32_t now = HAL_GetTick();
if (now - t_led >= led_half_ms)
{
    t_led = now;
    HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
}
```

### 验证方法

- 按键切换档位后，**屏上数字立即变化**
- **LED 实际的闪烁速度也跟着变**（这是"工作参数"的意义）
- 在 4 档之间循环切换，每档都生效
- 屏刷新与 LED 闪烁互不干扰（都用了非阻塞）
