## 0 · 开工前的准备

### 0.1 选题的尺度（最重要的一步）

**选对了题目，项目就成功了一半。**

| ❌ 太大 | ✅ 合适 | ✅ 也可以 |
|---|---|---|
| "智能家居系统" | "温湿度记录仪" | "倒计时器" |
| "四轴飞行器" | "按键密码锁" | "简易电子琴" |
| "机器人" | "超声波测距仪" | "智能小灯（光敏自动亮灭）" |

**判断标准**：能不能在 4 周内（**工作日每天 2 h，4 周约 40 h**；周末不排任务）做出**能现场演示**的东西？

**推荐尺度**：**一个自己已经会做的功能 + 一两样新东西**。
- 纯用已学过的东西 → 学不到新东西，但**能保证做完**
- 全是新东西 → 大概率做不完
- **熟 + 新** 的组合最稳
- 40 h 是按"工作日 2 h"算的，不要按 4 周×7 天去排；时间不够时**先砍"最好有"的项**——它们一律标为可选，只保"至少要有的 ≤5 条"。

### 0.2 本项目允许的选题池（供参考）

| 类型 | 题目 | 用到的外设 | 增量点（相对前面已做过的项目，这是评审要的"自己的东西"）|
|---|---|---|---|
| 显示类 | 温湿度**记录仪** | I2C + 传感器 + OLED + **Flash** + 按键 | **存储与查询**：AHT20 读数定时存 Flash、按键翻看历史极值与最值时间（P07 B5 只做到"显示 + 告警"，这里不是重复显示）|
| 显示类 | 数字时钟 | 定时器 + OLED + 按键 | 时间基准（掉电不丢要靠备份域/外部 RTC）+ 校时交互 |
| 交互类 | 按键密码锁 | 按键 + OLED + Flash 存储 | **状态机 + Flash 存密码**（掉电保存、错误次数锁定）|
| 交互类 | 简易电子琴 | 按键 + 定时器 PWM + 蜂鸣器 | **PWM 音频表**：音符→频率映射、节拍控制 |
| 控制类 | 智能小灯 | ADC(光敏) + PWM + 阈值控制 | 采集→阈值→PWM 的闭环调光（不是只点亮）|
| 控制类 | 超声波测距仪 | 定时器输入捕获 + OLED | **输入捕获测距**：回波高电平时间 → 距离换算与校准 |
| 数据类 | 电压记录仪 | ADC + Flash + 串口导出 | 采样率控制 + 存储 + 自定义导出协议（可复用 P06 帧格式）|

> **怎么用这张表**：先挑一类，再确认"增量点"这一列你能讲清、能演示出来。**只把"按键 + OLED + 串口"原样拼一遍不算**（A5 的验收要求，见 A5 知识点里的说明）。

**⚠️ 关于传感器选型（选题池里最容易踩坑的一处）**：

- **优先用 P07 已学的 I2C 传感器**：AHT20（7 位地址 `0x38`）或 SHT30（`0x44`）。它们和 OLED 挂在同一条 `PB6/PB7` 总线上，`HAL_I2C_Master_Transmit` / `HAL_I2C_Mem_Read` 那一套代码可以直接复用。
- **DHT11 / DS18B20 是单总线器件**：不靠 I2C，而是靠"拉低—释放—数高低电平长度"的时序通信，需要**微秒级延时**（用 DWT 计数器或 TIM 自己实现），**全套教程没有教过**。
- 因此：选题池里的温湿度类题目，**请用 AHT20 / SHT30 替代 DHT11 / DS18B20**。若你坚持选 DHT11 / DS18B20，必须在 A2 的器件清单/方案里明确写：「**这是计划外自学内容**，预计额外 10~20 小时，需要自己实现 µs 延时（DWT 或 TIM），不推荐零基础同学选」。

### 0.3 时间安排建议（4 周）

| 周 | 做什么 | 交付节点 |
|---|---|---|
| 第 1 周 | **到货清点、搭最小系统、接线图定稿、跑通骨架**（点灯 + 串口 + 屏/传感器能通信；下单在 P09 第 4 周就已完成）| 接线图定稿 + 骨架能跑 |
| 第 2 周 | 核心功能跑通（最难的那部分先做） | 能演示一个核心功能 |
| 第 3 周 | 补齐其余功能、模块化整理；**周内功能冻结** | 全部功能能跑（**功能冻结日 = 2027-06-07**）|
| 第 4 周（06-07 ~ 06-11）| **只做文档、异常测试与演示彩排**，不再加新功能 | 四件套齐全，**06-11 交付** |

**⚠️ 下单不在 P10 做**：器件清单在 **P09 中期**提交、**P09 第 4 周**下单（流程见 P10 任务卡 A2 与 `BOM_采购清单.md` §7），P10 开始时应该已经到货。**P10 开始后才下单必然赶不上**——物流 3~7 天会直接吃掉 1/4 的工期。

**⚠️ 交付日是 06-11，不是 06-20**：本项目 4 周里**前 3 周做功能、最后 1 周（06-07~06-11）只做文档与测试**。别把"写文档/异常测试"留到第 4 周末，那已经过了交付日。

**⚠️ 时间实际是压缩的**：日历上 P10 是 4 周（05-24 ~ 06-20），但交付日提前到 **06-11**（避开期末复习），真正能写功能的时间只有 **05-24 ~ 06-06 这两周多**——所以第 1~3 周要并行推进，**功能冻结日 06-07 之后一律不加新功能**；**06-12 ~ 06-20 是评审与补交窗口，不排新任务**。排计划时按"两周半写代码 + 5 天收尾"来估，不要按满 4 周估。

## A1 · 自选题目写需求说明

**任务**：自选一个题目（如温湿度记录仪、倒计时器、简易电子琴、智能小灯、按键密码锁等），写一页需求说明：做什么、给谁用、至少要有什么功能。

### 知识点

**需求说明不是功能列表的堆砌**。它要回答三个问题：

| 问题 | 作用 |
|---|---|
| **做什么** | 一句话说清这个设备是干什么的 |
| **给谁用** | 用户是谁、什么场景（决定交互怎么设计） |
| **至少要有什么** | 最小可用功能集（划清底线，防止做不完） |

**"至少要有"是给自己划的安全线**：时间不够时，保住这些就算完成；有余力再加"最好有"。

### 操作步骤

照这个模板写**一页纸**：

```markdown
# 需求说明：<你的题目>

## 一句话说明
（例：一个能实时显示当前温度并刷新的小型显示仪）

## 给谁用、什么场景
（例：放在书桌上，用户随时看一眼当前温度；不需要联网，不需要历史记录）

## 至少要有（必须完成）
1. 能读取温度传感器数据
2. 能在 OLED 上显示温度（保留一位小数）
3. 每秒刷新一次，不闪屏
4. 上电即可工作，不需要连电脑

## 最好有（有余力再做）
1. 加一个按键，能在摄氏/华氏之间切换
2. 超过设定温度时 LED 报警

## 明确不做（划清边界，防止范围失控）
1. 不做联网上报
2. 不做历史数据存储
3. 不做手机 App
```

**"明确不做"这一节很关键**——它防止你中途不断加需求，最后什么都做不完。

### 验证方法

- 一页纸齐全（一句话说明 / 场景 / 至少要有 / 最好有 / 明确不做）
- "至少要有"不超过 5 条，且都**可验证**（不是"比较好用"这种模糊描述）
- 指导人确认过（任务要求"交给指导人确认后再动手"是从 A2 的清单开始，但需求建议先确认）

## A2 · 列出器件清单

**任务**：列出所需器件清单（元件名称 + 型号 + 数量 + 用途），交给指导人确认后再动手。

### 知识点

**为什么要写"用途"**：评审时会**随机抽查 3 个器件**，问"它在电路里起什么作用"。清单里写明用途，就是提前准备这个环节。

**型号要具体**：写"温度传感器"不够，要写清具体型号（如 `AHT20` 或 `SHT30`，都是 P07 学过的 I2C 传感器），因为你得确认它**接口类型**（I2C/单总线/模拟）和**供电电压**（3.3V/5V）。**DHT11 / DS18B20 是单总线器件**，需要 µs 级延时，属于计划外自学内容（见 0.2 的说明），不推荐零基础选。

### 操作步骤

照这个模板列清单：

| # | 元件名称 | 型号 | 数量 | 用途 | 接口/电压 | 是否已有 |
|---|---|---|---|---|---|---|
| 1 | 温湿度传感器 | AHT20 | 1 | 测温度/湿度 | I2C / 3.3V | 否 |
| 2 | OLED 显示屏 | 0.96" SSD1306 | 1 | 显示温度 | I2C / 3.3V | 是（P07 用过）|
| 3 | 上拉电阻 | 4.7kΩ | 2 | I2C 总线拉高（模块板上通常已自带，不必另买）| — | 是（模块自带）|
| 4 | 杜邦线 | 母对母 | 10 | 接线 | — | 是 |
| 5 | 5V 电源 | USB 供电 | 1 | 供电 | — | 是 |

> **传感器怎么选（重要）**：优先用 **P07 已学的 I2C 传感器**——AHT20（7 位地址 `0x38`）或 SHT30（`0x44`），同一套 `HAL_I2C_*` 代码直接复用。**DHT11 / DS18B20 是单总线器件**，需要自己实现微秒级延时（DWT 或 TIM），全套教程没教，属**计划外自学内容**：预计额外 10~20 小时，不推荐零基础同学选；若坚持用，器件清单里必须写明这一点，并预留出调试时间。

**检查清单**（下单前逐项过）：

- [ ] 每个器件的**供电电压**与开发板匹配吗（3.3V / 5V）？
- [ ] **接口类型**与你的引脚规划一致吗（I2C / SPI / 单总线 / 模拟）？
- [ ] 有没有**需要独立供电**的（电机、大功率 LED、舵机）？
- [ ] 上拉/下拉电阻、去耦电容这些**小件**备齐了吗？
- [ ] 手头已有的不用重复买？

### 验证方法

- 清单 **6 列**齐全（名称 / 型号 / 数量 / 用途 / 接口·电压 / 是否已有；序号列不算）
- **交给指导人确认过**（这是任务明确要求）
- 评审时被抽查 3 个器件，都能说清用途

## A3 · 画接线图或原理图

**任务**：画出接线图或原理图（手绘拍照、画图工具、嘉立创 EDA 均可），标出每个引脚接什么。

### 知识点

**接线图 vs 原理图**：

| | 接线图 | 原理图 |
|---|---|---|
| 关心什么 | **哪个引脚接到哪里** | 电气关系（含网络标号、元件符号）|
| 适合 | 面包板搭建、杜邦线连接 | 画 PCB、正式设计 |
| 本项目 | **接线图就够** | 想画也可以 |

**为什么必须画**：画的过程中你会**发现接口对不上的问题**（比如"这个传感器要 5V 但我只有 3.3V"、"这两个外设抢同一个引脚"）——在纸上发现比焊好之后发现便宜得多。

### 操作步骤

**手绘**（最快，拍照即可）：

```
        ┌──────────────────────────────────┐
        │  STM32F103C8T6（蓝板/最小系统）   │
        │                                  │
  3.3V ─┼──┬──────────────────────────────● OLED VCC（3.3V）
        │  └──────────────────────────────● 传感器 VCC（按模块规格：3.3V 或 5V）
        │                                  │
   GND ─┼──┬──────────────────────────────● OLED GND
        │  └──────────────────────────────● 传感器 GND      ← 全部共地
        │                                  │
   PB6 ─┼──┬──────────────────────────────● OLED SCL  ┐
  (SCL) │  └──────────────────────────────● 传感器 SCL ┘ 同一条 I2C1 总线
        │                                  │
   PB7 ─┼──┬──────────────────────────────● OLED SDA  ┐
  (SDA) │  └──────────────────────────────● 传感器 SDA ┘ 并联在 PB6/PB7 上
        └──────────────────────────────────┘
```

**接线的三条铁律**：

| # | 规则 | 说明 |
|---|---|---|
| 1 | I2C 只用 **PB6(SCL) / PB7(SDA)** | 这是 I2C1 的**默认引脚**，CubeMX 里选中 I2C1 就自动变绿，不用额外配置 |
| 2 | **GND 只连板子 GND 和模块 GND** | ❌ 绝不能把 GPIO（例如 PB7）接到模块的 GND——那不是"接地"，而是把这个引脚对地短路 |
| 3 | **所有模块共地** | OLED、传感器、板子三者的 GND 必须连在一起；不共地时 I2C 没有参考电平，通信会时好时坏 |

供电：OLED 用 **3.3V**；传感器**按模块规格**（AHT20 / SHT30 模块一般是 3.3V，个别 5V 模块接板上 5V 脚）。接电前看一眼模块丝印，接错电压是最容易烧模块的操作。

> **⚠️ 引脚复用提醒（组合选题必看）**：`PB6/PB7` 在 **P05** 里被 **TIM4**（`CH1` 舵机 / `CH2` 输入捕获）用过。如果你做的是**组合选题**（比如舵机 + OLED 同屏、输入捕获测距 + 屏显），先回 P05 的「定时器 / 通道资源分配表」对一遍，**必要时换脚**——例如把舵机换到 `TIM4_CH3/CH4`（`PB8/PB9`），并且**不要再把 I2C 重映射到 PB8/PB9**（否则又抢上了），或者干脆换一个定时器。只做 I2C 类选题则不受影响。

> **若确实要用 PB8/PB9**：在 CubeMX 的**引脚图上**把 **PB8 / PB9** 直接点选成 `I2C1_SCL` / `I2C1_SDA`（F1 的 I2C1 重映射是**引脚映射**，不是在 `GPIO Settings` 里勾一个名为 "Remap" 的复选框；以你所用 CubeMX 版本的实际界面为准）。重新生成代码后才有效；没做重映射的话**总线完全没信号**，你会以为屏坏了。**新手默认别用 PB8/PB9。**

**用工具画**（更清晰）：嘉立创 EDA、draw.io、甚至 PPT 都行。

**必须标出**：

- [ ] 每个外设接在**哪个引脚**（引脚号要具体）
- [ ] **供电**（3.3V / 5V / 独立电源）
- [ ] **共地**（所有器件 GND 必须连在一起）
- [ ] 上拉/下拉电阻的位置和阻值
- [ ] 引脚冲突检查（同一个引脚不能接两个功能）
- [ ] **没有把 GPIO 当 GND / VCC 用**（GPIO 只接信号脚，电源脚只接电源）

### 验证方法

- 图上每个引脚标得清清楚楚
- 有供电与共地标注
- **无引脚冲突**
- 评审时能照着图接一遍线

### 常见问题

| 现象 | 原因 |
|---|---|
| 图上看着没问题，实际接不通 | 漏了共地 |
| 某个外设不工作 | 供电电压不匹配（5V 器件接 3.3V）|
| 两个功能互相干扰 | 引脚冲突（一个引脚配了两个功能）|
| I2C 屏一直白屏、扫描不到设备 | 用了 PB8/PB9 但没在引脚图上把这两脚映射成 `I2C1_SCL` / `I2C1_SDA`；或把 GPIO 接到了模块 GND |

## A4 · 完成程序并做出演示成品

**任务**：完成程序编写与调试，做出一个能现场演示的成品（上电即可工作，不依赖电脑里的调试器）。

### 知识点

**"上电即可工作"是硬指标**：很多人的项目**接着调试器能跑，拔了就不行**。原因通常是：

| 原因 | 说明 |
|---|---|
| 程序没烧进 Flash | 只做了"在线调试"，没真正下载 |
| 依赖调试器的复位 | 没有正确的初始化顺序 |
| 依赖串口连接 | 某些外设初始化在等串口握手 |

**验收前必做**：拔掉烧录器、拔掉串口线，**只接电源**，上电看是否正常工作。

### 操作步骤

**1. 开发顺序：先做最难的核心功能**

不要从"点亮 LED"开始（那早就做过）。**先把最不确定的部分做通**：
- 不确定传感器能不能读通 → 先做传感器
- 不确定电机能不能转 → 先做电机

这样如果某个部分做不通，你有时间换方案。

**2. 每完成一个功能就 Git 提交**

```powershell
git add .
git commit -m "P10：温湿度读取功能完成并验证"
git push
```

保留可回退的版本——改坏了能立刻退回上一个好版本。

**3. 交付前必做"裸机测试"**

| 步骤 | 操作 |
|---|---|
| 1 | 拔掉 ST-Link 烧录器 |
| 2 | 拔掉串口线（如果有） |
| 3 | 只接电源（USB 或电池） |
| 4 | 上电，观察成品是否正常工作 |
| 5 | 连续运行 15 分钟，记录有无异常 |

### 验证方法

- **不接电脑、不依赖调试器，上电即可工作**
- 连续运行 **15 分钟**功能正常
- 板上有焊接/接线牢固（轻轻晃线不会断）
- 有演示视频（含完整操作流程）

### 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 拔了调试器就不工作 | 没烧进 Flash | Keil 里正常 `Download`，不是 `Debug` |
| 上电后有时不启动（接上调试器就正常）| ① **外设上电慢**：传感器 / 屏需要 100~200 ms 才就绪，初始化发得太早 | 初始化外设前延时 100~200 ms，并给读操作加 3 次重试 |
| 上电后有时不启动，且换电脑/换线也一样 | ② **MCU 本身没启动**：供电不足（线太细/接触不良）、程序没烧进 Flash、BOOT 跳线不对 | **别用延时掩盖**：量 3.3 V 是否稳、换短而粗的供电线、确认 Keil 里是 `Download` 而不是 `Debug`、检查 BOOT0=0 |
| 跑一会儿就不对了 | 栈溢出 / 内存泄漏（P09 学过） | 用栈水位与堆剩余检查 |
| 线一碰就断 | 杜邦线接触不良 | 换线，或焊上 |

## B2 · 模块化封装

**任务**：做到模块化：至少把 2 个功能封装成独立的 `.c` / `.h` 模块，模块对外接口清晰、应用层不碰底层寄存器。

### 知识点

**判断模块化是否到位**——问自己三个问题：

1. 这个模块能不能**不改代码就换引脚**？（能 = 封装到位）
2. `main.c` 里有没有直接操作寄存器的代码？（有 = 没封装好）
3. 想换一个传感器，要改几个文件？（只想改 1 个 = 好）

**标准模块结构**：

```
<模块名>.h   ← 对外接口（别人只 include 这个）
<模块名>.c   ← 实现细节（外面看不到）
```

### 操作步骤

**示例：把传感器封装成模块**

> 下面的示例用本项目推荐的 **AHT20（I2C，7 位地址 `0x38`）** 讲"封装思路"——底层细节（命令、延时、状态轮询、换算、错误码）全关在 `.c` 里，`.h` 只暴露"初始化 + 读一次温湿度"，应用层完全看不到 `HAL_I2C_*`、也看不到寄存器。

`aht20.h`：

```c
#ifndef __AHT20_H
#define __AHT20_H

#include <stdint.h>

/* 返回 0 成功；-1 = I2C 无应答/超时；-2 = 数据未就绪或校验失败 */
int aht20_init(void);
int aht20_read(int32_t *temp_x100, int32_t *humi_x100);   /* 单位 0.01℃ / 0.01%RH */

#endif
```

`aht20.c`：

```c
#include "aht20.h"
#include "i2c.h"                  /* hi2c1 —— P07 已生成的 I2C1 句柄 */

#define AHT20_ADDR8   (0x38 << 1) /* HAL 的 DevAddress 要 8 位形式 */

/* 所有底层细节关在这里：命令、80ms 等待、状态字轮询、换算、错误码 */
static int aht20_send_cmd(uint8_t cmd, uint8_t p1, uint8_t p2) { /* ... */ }
static int aht20_wait_ready(uint32_t timeout_ms)               { /* ... */ }

int aht20_init(void) { /* 0xBE 软复位 → 0xE1 校准；失败返回 -1 */ }

int aht20_read(int32_t *temp_x100, int32_t *humi_x100)
{
    /* 0xAC 触发测量 → 等 80ms → 读 6 字节 → 查状态字 bit7 → 换算成 0.01 单位 */
}
```

**应用层（main.c）变得干净**：

```c
#include "aht20.h"

int32_t t, h;
if (aht20_read(&t, &h) == 0)
{
    printf("T=%ld C  H=%ld %%\r\n", (long)(t / 100), (long)(h / 100));
}
else
{
    printf("sensor read failed\r\n");   /* 具体错误码在模块内部打印，应用层不用管细节 */
}
```

> **封装到位的标志**：想换传感器（AHT20 → SHT30）或换 I2C 引脚时，**只改这个模块的 `.c`**，`main.c` 一行不动——这就是 B2 验收里"要换一个传感器，改哪几个文件"的标准答案。

### 验证方法

- 至少 2 个模块独立成 `.c` / `.h`
- **应用层里搜不到寄存器操作**（如 `GPIOA->`）和底层 HAL 调用
- 每个模块的 `.h` 接口简洁（5~8 个函数以内）
- 能回答："要换一个传感器，改哪几个文件？"（答：只改那个模块的 `.c`，应用层不动）

| "这段代码干什么？" | 评审前**自己逐段过一遍代码**，特别是从例程拷来的部分 |
| "改个需求要动哪几个文件？" | 提前想好 1~2 个例子，理清模块边界 |
| "**你的数据是怎么测出来的？用的哪个档位 / 哪个测量点？**" | 对应 `REVIEW_TEMPLATE.md` 的"必问三题"第 2 题：每测一个值就记下**仪器档位 + 测量点 + 读数**（万用表档位、示波器时基与探头倍率），做法见 **P08 A3** 的万用表对照记录 |

### 操作步骤

**1. 自查代码**（评审前必做）

对着自己的代码问：

- [ ] 每个函数我都能说清作用吗？
- [ ] 有没有从例程拷来但我不理解的代码？（**有就现在搞懂**）
- [ ] 我用的每个外设，初始化参数为什么这么设？
- [ ] 那个"魔数"（如 `0x5A5AA5A5`、`REFRESH_MS`）代表什么？

**2. 准备"改需求"的答案**

提前想好例子：

```markdown
## 改需求示例
**问**：如果要把刷新频率从 1 秒改成 500ms，要改哪几个文件？
**答**：只改 1 处 —— `app.c` 里的刷新周期常量（`REFRESH_MS`）。
     因为我把周期抽成了宏，显示逻辑是参数化的，不用动。

**问**：如果要加一个"温度超过 30℃ 时 LED 报警"的功能呢？
**答**：改 2 个文件 —— `app.c` 加阈值判断与调用，`led.c` 加报警闪烁接口。
     不需要动传感器模块和显示模块。
```

**3. 诚实原则**

遇到不懂的：**直接说不懂，然后说你会怎么去搞懂**。

```c
"这段是例程里带的，我目前还不能完全解释清楚。
 我的理解是……如果需要我可以现在查手册确认。"
```

> 这比硬编一个错误答案好得多。**评审看的是态度与潜力，不是全知全能。**

### 验证方法

- 能讲清自己的代码（评审随机挑段都能说）
- 能回答"改需求动哪几个文件"
- 不懂时能诚实承认并说清补救路径
